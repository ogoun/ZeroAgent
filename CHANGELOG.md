# Журнал изменений

Формат: новые записи сверху.

## Не выпущено

### Исправлено
- `za-agent`: если после компакции запрос всё ещё не помещается в окно, run встаёт на паузу `context`, а не начинает ход за окном; аварийная компакция сокращает и хвост истории. Ввод, пришедший во время компакции, читается до следующего хода. Сводка модели вынесена в блок `<summary from="model">`, модель не может изобразить цель или поправку пользователя. Вводы пользователя в сводке ограничены четвертью окна.
- `za-agent`: удаление старых результатов больше не разбирает указатель на файл выгрузки в тексте результата (процитированный или поддельный указатель уводил ссылку на чужой файл, и текст терялся) — текст результата всегда сохраняется в файл. Имя этого файла — по содержимому (`{run}-{blake3[..16]}.txt`): разные результаты не делят файл, длинный `call_id` не ломает запись. Ошибка записи — событие `context.alert {kind: "prune_failed"}`; временный файл при сбое удаляется.
- `zero-agent`: повтор открытия журнала, занятого другим процессом, ждёт до 3 с вместо 1 с — на Windows закрытие журнала и снятие блокировки убитого процесса под нагрузкой дольше секунды.
- `zero-agent run`: флаги `--max-usd`, `--max-gpu-ms`, `--max-duration` (с) для нового run и `--resume`. Run, исчерпавший предел стоимости, времени GPU или активного времени, снова продолжается из CLI. Подсказка при `blocked_on_budget` называет флаг исчерпанного вида. `answer` по `unk-…` при расхождении называет действующее решение. `za-agent`: в исходниках нет байта NUL (метка `za-request-v1\0` экранирована, хэш запроса прежний); порог NFR-03 в тесте хода умножается на `ZA_TEST_TIME_SCALE`.
- `zero-agent run`: первая строка stderr — всегда `run <id>`, раньше предупреждений (`--agents-md` без файла) и логов шлюза и журнала. `run --resume` без флагов бюджета сохраняет бюджет run, а не заменяет его `[budgets.run]`: предел прежнего запуска больше не снимается молча; `--max-steps`/`--max-tokens` при resume меняют поля поверх текущего бюджета run. Путь проекта в `<env>` и подсказках — без префикса `\\?\` Windows. У `failed` в stderr — причина (`zero-agent: run завершился ошибкой: <причина>`).
- `za-agent`: `finish` вместе с отменой даёт `done`, только если `cancelling` ещё не записан; после записанного `cancelling` итог — `cancelled` (из `cancelling` переход только в `cancelled`). Ввод пользователя (`turn.input`, текст `correct`) экранируется как недоверенный: `<` и `>` и их аналоги заменяются (`escape_untrusted`), управляющий тег из ввода не становится командой.
- `za-agent`: resume не засчитывает простой между процессами в активное время после сбоя на границе шага; пауза, нажатая до resume, не теряется; испорченный снимок или история переводят run в `failed (snapshot)`, другая версия снимка статус не меняет.
- `za-agent`: при `finish = Length` с текстом и обрезанным вызовом модель получает один nudge про обрезанный вызов, а не два подряд.
- `zero-agent`: предел `usd` в `[budgets.run]`, равный NaN, бесконечности или отрицательному числу, — ошибка конфигурации (NaN раньше молча снимал предел); ошибка разбора называет поля бюджета по имени; опечатка раздела (`[budget.run]`) по-прежнему ошибка разбора, теперь под тестом.
- `za-agent`: конечный снимок run пишется после конечного статуса, а не до него: сбой между ними больше не оставляет завершённый run в `running` со снимком, с которого resume начал бы новый ход. Ответ модели, обрезанный пределом вывода (текст без вызовов, `finish = length`), — исход хода `truncated` с просьбой продолжить короче, а не пустой ход с ложным «нет текста». `finish` вместе с отменой в одном пакете завершает run по `finish`. Точка сбоя `CrashPoint::AfterFinalStatus`.
- `za-agent`: вызовы пакета после принятого `finish` не исполняются (`not executed: run finished by finish`); сбой журнала в слоте инструмента даёт модели `internal error: journal write failed`; тесты пакета инструментов не зависят от задержки журнала (рандеву вместо порога 30 мс, ожидания под пределом).
- `za-agent`: при `finish = Length` неразобранный вызов из текста получает один nudge про обрезку пределом вывода, а не просьбу повторить с валидным JSON; тесты обрыва хода сигналом не зависают при медленной записи журнала.
- `za-llm`: тексты ошибок проверки аргументов по схеме (`SchemaError.message`) на английском: они уходят модели в результате отвергнутого вызова. Подсказка ближайших имён у неизвестного инструмента — только близкие (расстояние ≤ max(длина, 3) / 3 или имя как подстрока), без близких — пусто; коды ошибок очереди — константы `za_llm::error::queue_code`.
- `docs/journal.md`: убран байт NUL и CRLF, git снова показывает дифф журнала как текст.
- `za-llm`: разные `key_ref`, дающие одну переменную окружения (`a.b`, `a-b`, `A_B` → `ZA_SECRET_A_B`), — ошибка конфигурации `KeyRefEnvCollision`, а не общий ключ двух эндпоинтов. `secret_env_name` доступен без функции `http` (`za_llm::config`).
- Тесты: длительности тестов `Gateway` умножаются на `ZA_TEST_TIME_SCALE` (1–6, в CI 4); тесты `r1a_models` не зависят от размера кэшей cargo/uv машины.
- `za-llm`: низкое место на томе журнала (RES-018) останавливает фоновые заявки (`Job`, `Arena`) и облачных групп, не только локальных; ресурсы узла (RAM, VRAM, CPU) по-прежнему проверяются только для эндпоинтов на этом хосте. `za-res`: `Admission::journal_verdict` публичный.
- `za-llm`: `daily_budget_usd` у группы, где у эндпоинта нет `price`, а бэкенд не сообщает стоимость (все, кроме OpenRouter), — ошибка конфигурации `BudgetWithoutPrice`: раньше такой бюджет молча не действовал. Пример в README дополнен `price`.
- `za-llm`: сохранение и восстановление слотов llama.cpp (`/slots/{id}?action=save|restore`) отправляют ключ эндпоинта (`Authorization: Bearer`), как зонд и запрос: у сервера с `--api-key` сохранение KV-кэша больше не отказывает молча. 401/403 на `/slots` выключают сохранение для эндпоинта (`slot_save = false`) с одним предупреждением.
- `za-llm`: ошибка TLS при установке соединения (сертификат, рукопожатие, `https://` на порт без TLS) — класс `Auth` с текстом `TLS: …`, а не `Transport`: не повторяется, предохранитель выключает эндпоинт до сброса. Ошибка TLS на установленном соединении остаётся повторяемой (`Transport`, при чтении тела — `StreamCut`). Зависимость `rustls` (тот же крейт, что у `reqwest`).
- `za-llm`: функция `http` включает `tokio/macros` — без dev-зависимостей тестов крейт не собирался. Коннектор Chat Completions: `ReasoningMode::Off` у OpenAI и OpenRouter не отправляет полей рассуждения; `strict: true` только для схем, совместимых со strict-режимом OpenAI (белый список ключей Structured Outputs, глубина до 10); разные вызовы под одним `index` с разными `id` не сливаются, а `id`, пришедший после первого фрагмента, вызов не делит; запасной `id` вызова уникален; пустые аргументы — `{}`; `parallel_tool_calls` из возможностей провайдера.
- `za-core`: при `ReplayMismatch` демонстрационный run переводится в `paused` с причиной `replay_mismatch`, а не остаётся в `running`.
- `za-store`: повреждённый файл журнала (`SQLITE_CORRUPT`, `SQLITE_NOTADB`) — `StoreError::Corrupt`, а не `Sqlite`; `EINVAL` от `fsync` каталога на Unix терпится с `warn`; предупреждение о занятом чекпоинте WAL — один раз за серию и при первом превышении 64 МиБ, остальное в `debug`.
- `za-core`: расхождение имени или аргументов эффекта с журналом при повторе (в том числе дрейф `prefix_hash` у `model` демонстрации) — ошибка `EffectError::ReplayMismatch { key, field }` вместо `warn`; `demo-run --resume` завершается кодом 1. `EffectError::Unknown` и `ReplayMismatch` отравляют `RunCtx`, как ошибка журнала. `serde_json` с функцией `float_roundtrip`: дробные аргументы читаются из журнала точно и не дают ложного расхождения.
- `za-store`: контроль роста WAL (ARC-035) — `journal_size_limit` 64 МиБ и `wal_checkpoint(TRUNCATE)` писателем при WAL больше 8 МиБ (проверка каждые 16 пачек), без ожидания читателей.
- `za-store`: `put_blob` восстанавливает пропавший или неполный файл blob при существующей строке; на Unix после `rename` синхронизируется каталог `blobs/`, при его создании — каталог проекта.
- `zero-agent`: `--resume`, `replay` и тестовые хелперы повторяют открытие журнала на `Locked` (10 × 100 мс).
- `deny.toml`: убрана неиспользуемая лицензия `Zlib`.

### Изменено
- `za-protocol`: причины перехода в `failed` — константы `fail_reason` (`store`, `history`, `prefix` и др.), как `pause_reason`.
- `za-llm`: разрешение предохранителя `Gateway` берёт в момент выдачи места очереди, а не до постановки: ждущие места заявки не занимают пробу полуоткрытого предохранителя, проба достаётся заявке, первой получившей место; заявка, получившая место, пока проба занята (например, при `max_parallel > 1`), по-прежнему сразу кончается `CircuitOpen`; отказ при выдаче отпускает место. До постановки `CircuitOpen` — только пока не истекла пауза открытого предохранителя.
- Тесты `za-llm`: ожидания событий — щедрый предел (30 с × `ZA_TEST_TIME_SCALE`), таймауты транспорта и пороги длительности — с множителем; каталоги профилей тестов `Gateway` — `gateway/<pid>/` на прогон, каталоги прошлых прогонов старше 30 мин удаляются.
- `za-store`: `set_status` и `set_status_with_reason` возвращают `StatusChange { from, generation }` вместо `generation`; `run_status_payload` — payload события `run.status`.
- `za-protocol`: `Budget` отвергает незнакомые поля (`deny_unknown_fields`): опечатка в имени предела — ошибка разбора, а не снятое ограничение.
- CI: `actions/checkout@v7` (Node 24) вместо `@v4`.
- `za-store`: журнал доводится до версии схемы 2 (таблица `usage`); после этого бинарники R0 и R1-A его не открывают (`SchemaTooNew`), откат — только с копией `journal.db`.
- `zero-agent doctor`: `LLAMA_URL` печатается без учётных данных и параметров запроса, адрес с ними не зондируется; без `[models]` сервер `LLAMA_URL` зондируется один раз (как модель `local`). `ask` вне терминала выводит только итог последней попытки, без обрывков до повтора. `resources` показывает `probing` без срока. `za-llm`: причина «ключ не настроен» называет переменную `ZA_SECRET_<ИМЯ>`.
- `zero-agent doctor`: в отчёте `gpu` (один вызов `nvidia-smi`; нет NVIDIA — `warn`) и `models` — состояние каждого эндпоинта из `config.toml` после первого зонда (`inactive`, `unreachable` — `warn`, ошибка конфигурации — `fail`). JSON: `"gpu": {...}`, `"models": [["<id>", {...}], ...]`.
- `za-llm`: текст `ConfigParseError` начинается с «конфигурация» (файл общий для `[models]` и `[resources]`); белый список имён полей дополнен разделами и полями `[resources]`.
- `za-llm`: `Usage.input` у всех провайдеров — весь вход, включая кэш: коннектор Anthropic складывает `input_tokens`, `cache_read_input_tokens` и `cache_creation_input_tokens`. Источник подсчёта токенов у совместимого сервера — `Usage` (как у vLLM; до первого ответа — символы / 4). `ThinkingSupport` дополнен полями `budget`, `effort_xhigh`, `effort_max`, `sampling`: Anthropic шлёт `enabled` с бюджетом только модели, которая его принимает, а `Effort::Max` — наибольшим уровнем модели (`max`, иначе `xhigh`, иначе `high`); Responses и Chat Completions OpenAI (`openai_chat`) по профилю не шлют `temperature`/`top_p` рассуждающим моделям; Responses не шлёт `reasoning` и `include` моделям без рассуждений, `Effort::Max` — `max`/`xhigh`/`high` по профилю.
- `za-llm`: функции `default = ["gateway"]`, `gateway`, `http`; `probe` — псевдоним `http`. `serde`, `thiserror`, `tracing`, `tokio` стали обязательными зависимостями. `ToolSchema` сериализуем.
- `za-store`: `StoreError` помечен `#[non_exhaustive]`, новые варианты `Corrupt` (повреждение журнала), `SchemaTooNew { found, supported }`, `Serde` вместо общего `Sqlite`.

### Добавлено
- `zero-agent inspect --project DIR --run ID [--turn N] [--raw | --json]`: запрос хода к модели, восстановленный по журналу байт в байт (сверка `request_hash`), — блоки `tools`, `core`, `adapter`, `overlay`, `agents_md`, `first_message`, `dialog`, `control` с байтами, оценкой токенов и хэшем, оценка запроса, расход провайдера и предсказание следующего хода; `--raw` — точное тело запроса провайдеру без ключей. `zero-agent stats --project DIR --run ID [--json]`: метрики run — ходы, шаги, токены и доля кэша, время до первого токена (p50, p95), скорость вывода, ошибки модели по классам, ремонт вызовов, компакции, стоимость. API: `za_agent::inspect`, `run_metrics`, `Inspection`, `BlockCost`, `RunMetrics`, `InspectError`; `FrozenPrefix.sizes` (`BlockSizes`); `ModelPort::render_request` (`Gateway`, `ScriptedModel`).
- `za-agent`: компакция истории. При заполнении окна до `compact_at` (и при подозрении на тихую обрезку) модель пишет сводку тем же префиксом без инструментов и мышления; новая история — `<env>`, recovery памяти, блок `<summary>` с целью и сообщениями пользователя дословно, хвост последнего запроса или хода и напоминание `Current task: …`. Переполнение окна (`ContextOverflow`, запрос выше окна) — аварийная компакция по усечённому входу и один повтор хода; повторный отказ или повторная обрезка — пауза `context`. Бесполезная компакция подавляется (`context.alert {kind: "compaction_insufficient"}`). События `context.compacted` (tainted), `context.alert {kind: "n_ctx_changed"}` при resume на другое окно; точка сбоя `CrashPoint::AfterCompact`. API: `compact`, `summary_block`, `split_tail`, `cut_points`, `Conversation::from_messages`, `COMPACT_RUBRIC`, `ControlAction::Compact`; снимок += `last_next_step`.
- `za-agent`: выгрузка большого вывода инструмента (R1-B2): вывод длиннее доли окна `spill_share` (после экранирования) остаётся в контексте головой и хвостом со строкой `… omitted N lines; search .zero-agent/work/spill/<id>.txt`, полный текст — в файле проекта; каталог `.zero-agent/work/` получает `.gitignore`. Удаление старых результатов: при заполнении окна до `prune_at` результаты старше последних 4 ходов и длиннее 1024 байт заменяются ссылкой на файл, событие `context.pruned`, эпоха истории в снимке run (`epoch`). `Conversation::rewrite_results`, `ToolEnv.spill`.
- `za-agent`: счётчик контекста (R1-B2): бюджеты окна по таблице 2.3 (`ContextBudget`), лимит вывода хода с бюджетом мышления (`output_plan`: ход на small-тире больше не обрезается мышлением без ответа), оценка запроса по расходу прошлого хода и новым сообщениям (`ContextMeter`, эффект `context` на границе шага), событие `context.alert` при неизвестном окне (`n_ctx_unknown`, run берёт 8192) и при подозрении на тихую обрезку сервером (`truncation_suspected`). Снимок run версии 2: счётчик, задача, `<env>` и вводы пользователя; снимок версии 1 читается, в том числе посреди шага (сбой, пауза на одобрении или `ask_user`): шаг доигрывается с параметрами хода R1-B1. Подозрение на обрезку сравнивает расход с оценкой без рассуждений прошлых ходов: шаблоны llama.cpp их выбрасывают, длинное рассуждение больше не даёт ложного срабатывания. `model.request` содержит `options` хода и `turn_attempt`. Новые события `context.pruned`, `context.compacted`, `loop.detected` и причины паузы `tool_errors`, `model_loop` в протоколе.
- `za-llm`: `ModelPort::count_tokens` — точный счёт токенов; `Gateway` у llama.cpp спрашивает `POST /tokenize` (предел 5 с, 404 — без счёта), `ScriptedModel::with_token_counter`.
- `zero-agent`: раздел `[context]` конфигурации (`tier`, `compact_at`, `prune_at`, `spill_share`) с проверкой диапазонов; замораживается на run. Порядок тира: `--tier` > `[context].tier` > размер окна.
- `zero-agent run`: run агента через цикл `za-agent` — новый (`--model`, `--mode`, `--work-mode`, `--tier`, `--max-wait`, `--max-steps`, `--max-tokens`, `--agents-md`) и продолжение `--resume` (после паузы, бюджета и аварийного завершения; `--model`, `--input`, новый бюджет). Ответ — в stdout по мере генерации, первая строка stderr — `run <id>`; бюджет — `[budgets.run]` и флаги поверх него; Ctrl+C — пауза, второй — выход. Коды выхода: 0 — `done`/`partial`, 1 — ошибка или `failed`, 3 — нужно решение (`zero-agent: ответьте: …`), 4 — пауза или `blocked_on_budget`, 5 — `blocked`, 6 — `cancelled`. `zero-agent answer`: ответ на вопрос модели (`--text`), одобрение (`--approve`, `--deny --note`), решение неизвестного исхода (`--done`, `--not-done`). Приёмка R1-B1 — `tests/r1b_loop.rs`.
- `za-agent`: продолжение run `resume_run` после сбоя процесса и по команде: реплей шага по квитанциям (повторный запрос к модели тот же, `NonIdempotent`-вызов с квитанцией не повторяется, без квитанции — решение пользователя `needs_decision`), дописывание отложенного статуса чистой паузы, доведение `pausing` до `paused` и `cancelling` до `cancelled`; изменения `ResumeChange` — эндпоинт (только на границе шага, иначе `ChangeMidStep`), бюджет, режим и ввод; первое сообщение после resume — `<control action="resume">` с блоком `<state>` (`state_block`).
