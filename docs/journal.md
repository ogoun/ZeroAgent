Сверены 2026-11-09 с вендорскими шаблонами и парсерами vLLM (`main`):

Обрыв — отклонение, только если имя принято.
  - **Gemma 4**: `<|tool_call>call:NAME{k:<|"|>s<|"|>,n:42}<tool_call|>` или `…<turn|>`, также `<|tool_call>:NAME{…}`. Источники: `google/gemma-4-31B-it/chat_template.jinja` (макрос `format_argument`), vLLM `vllm/parser/gemma4.py`, `vllm/tool_parsers/gemma4_utils.py`. Свой разбор объектов, списков, строк `<|"|>…<|"|>` (закрывающий тег внутри строки вызов не ломает), значения без кавычек: `true`/`false`/`null`/числа — JSON, прочее — строка; вложенность до 64. Ошибки — по правилу Hermes.

Источники: `mistral-common` `tokens/tokenizers/instruct.py` (`InstructTokenizerV2/V11/V13`), vLLM `vllm/parser/mistral.py`. Текст после JSON остаётся текстом; синтаксическая ошибка с принятым именем — отклонение до конца строки или следующего маркера.

Источники: `meta-llama/llama-models` `models/llama3_2/text_prompt_format.md`, vLLM `pythonic_tool_parser.py`, `llama4_pythonic_tool_parser.py`. Литералы Python: строки (одинарные, двойные, тройные, экранирование), числа с `_`, `True`/`False`/`None`, списки, кортежи, словари; позиционные аргументы — ошибка.

Обрыв концом текста с принятым именем (у llama3_json — и имя оборванного объекта) — отклонение всего текста; синтаксическая ошибка — текст (раунд 1).

Оборванный объект считается вызовом, только если после имени конец или ключ `parameters`/`arguments`.

## 2026-11-09. R1-A, задача 7: нормализация вызовов, форматы P0

Запись описывает итоговое состояние после раундов исправлений 1–3 (ревью task-7-review.md, решения контроллера).

- **`za_llm::normalize`** (ядро, без функций): `normalize(msg, tools, formats) -> NormalizeOutcome` — чистая функция по порядку MDL-005. Нативные `Part::ToolCall` первыми; затем всегда (D39) скан `Text`, потом `Reasoning` форматами по порядку. Пустой `formats` — `all_formats()` (ruling: скан по D39 не выключается): Hermes, Qwen XML, Harmony, затем пять форматов P1 задачи 8, пока без разбора. Разметка вызовов вырезается из `text`/`reasoning`; пробелы на стыке схлопываются в `"\n\n"`, `"\n"`, `" "` или ничего. Текст без находок не меняется. Части `Text` (и `Reasoning`) склеиваются через `"\n"`, если на стыке нет пробела.
- **Дубли (D39)**: извлечённый вызов отбрасывается (`dropped_duplicates`), если имя и `canonical_json` аргументов совпали с нативным — до нормализации или после неё (Qwen XML `"5"` и нативный `5` — дубль). Один нативный поглощает любое число повторов. Вызов из рассуждения, совпавший с принятым из текста, тоже дубль (остаётся вызов из текста); повторы внутри одного источника сохраняются.
- **Предел**: не больше `MAX_EXTRACTED_CALLS` = 64 извлечённых вызовов на сообщение (текст и рассуждение вместе); остальное — одно отклонение `CallRejection::TooManyCalls { limit, skipped }` (новый вариант). Так ограничены и `rejected`, и строки `debug`.
- **Аргументы**: `RawArgs::Text`, строка вместо объекта и нативный `Null` с `raw_arguments` — разбор JSON (`ArgsParsedFromString`; пустая строка — `{}`, обёртка `` ```json `` снимается); `Pairs` — объект строк. Не разобралось — `Unparseable { raw }`.
- **Имя (D28, порог уточнён контроллером, I4)**: полный Дамерау — Левенштейн (Лоуренс — Вагнер) по символам Unicode. Исправление — только единственный кандидат, имя не короче 5 символов и расстояние ≤ min(2, длина / 4): `get` → `set` не исправляется. Иначе `UnknownTool` с тремя ближайшими (расстояние, затем имя). Имя длиннее 256 символов не исправляется. Кандидаты с разницей длин больше порога отсеиваются без подсчёта расстояния; ответ `accept_name` кэшируется по имени в пределах одного `normalize`.
- **Схема (D5)** `validate_and_coerce`: своё подмножество (`type` и массив типов, `properties`, `required`, `additionalProperties`, `items`, `enum`, `const` с числами по значению, `minimum`/`maximum`, `minLength`/`maxLength` в символах, `minItems`/`maxItems`, `anyOf`/`oneOf` — сначала ветки без приведения, затем первая с приведением, локальный `$ref` любым JSON Pointer, глубина ≤ 64); прочие ключевые слова — `debug`. Приведение только при несовпадении типа; `enum`/`const` без `type` — приведение строки к типу значения-кандидата; строка, начинающаяся с `[`, но не JSON, при `type: array` — ошибка, а не `[строка]`. Ошибки — JSON Pointer пути; при ошибке аргументы не меняются.
- **id** вызова без id: `call_` + 12 hex `blake3(name + canonical_json(args))`; совпавший id (тот же вызов дважды) разводится суффиксом `#n` в хэше — детерминированно (CORE-007, ruling).
- **`extracted_mutation_blocked`** (D27): не `Native` и класс не `Pure`/`ReadOnly`.
- **Форматы P0** (разбор без regex). Сверены 2026-11-09 с шаблонами: Hermes-3 `tokenizer_config.json` (NousResearch, «within <tool_call></tool_call> XML tags»), Qwen3-Coder `chat_template.jinja` (`<tool_call>`, `<function=NAME>`, `<parameter=K>`, значение, `</parameter>`, `</function>`, `</tool_call>` — каждый тег с новой строки), OpenAI «Harmony response format» (developers.openai.com/cookbook, получатель в разделе роли или канала, стоп-токены `<|call|>`, `<|end|>`, `<|return|>`).
  - Общее: разбор линейный — каждый маркер ищется от текущей позиции не больше раза на вхождение (`Finder`); 1,2 МБ повторов любого маркера, в том числе с 33 инструментами и длинными или ошибочными именами, — меньше секунды в debug (до исправления: 22 с в release на 1,2 МБ `to=functions.x `). Маркер без признака вызова — обычный текст без отклонения; `Unparseable` — только для начала, похожего на настоящий вызов, но обрезанного или битого.
  - Код Markdown (`normalize/code.rs`): блоки с забором `` ``` ``/`~~~` в начале строки (незакрытый — до конца) и инлайн-код (серия обратных кавычек до такой же серии в той же строке) находятся один раз по исходному тексту и заменяются заглушками `U+E000 n U+E001`. Форматы маркеров в коде не видят, вырезание вызовов области не сдвигает; после разбора код возвращается в текст и в аргументы вызовов. Заборы и обратные кавычки внутри тел вызовов (`<tool_call>…</tool_call>`, `<function=…>…</function>`, вызов Harmony `to=functions.…<|message|>…<|call|>` или `…<|end|>`; закрытие раньше следующего открытия) Markdown не считаются; сообщения обычных каналов Harmony (`final`, `analysis`) — не тела вызовов, код в них скрыт: нечётный забор в значении `write_file` не открывает пример после вызова.
  - Hermes: признак — `{` после `<tool_call>`; JSON читается потоковым десериализатором, `</tool_call>` ищется после конца JSON (закрывающий тег в строковом аргументе не ломает вызов); несколько объектов подряд; целый JSON без `</tool_call>` принимается, текст после него остаётся. JSON оборвался концом текста — отклонение до конца; синтаксическая ошибка — отклонение до `</tool_call>`, если он стоит раньше следующего `<tool_call>`, иначе тег — обычный текст (`<tool_call>{...}` в прозе).
  - Qwen XML: признак — `<function=ИМЯ>` с телом, начинающимся с `<parameter=`/`</function>` или оборванным. Полный вызов (с `</function>`) — вызов при любом имени: неизвестное даёт `UnknownTool` с ближайшими (D28). Обрезанный без `</function>` — отклонение, только если имя принято `accept_name`, иначе текст. Обёртка необязательна, у значения снимается по одному краевому переводу строки; пропущенный `</parameter>` терпится. Ограничение (как у vLLM): значение с `</parameter>` или `<function=` режется.
  - Harmony: вырез от `<|start|>`/`<|channel|>`/`to=`, тело до `<|call|>`/`<|end|>`/`<|return|>`/`<|start|>`/конца; `to=functions.` без маркеров Harmony — текст и не захватывает следующий настоящий вызов; заголовок без `<|message|>` — отклонение, только если имя принято, а остаток заголовка ≤ 64 байт без перевода строки.
  - Битая разметка формата — `RawCall` с пустым именем и `RawArgs::Text(разметка)` → `Unparseable` (соглашение для задачи 8). Тест обрыва ответа на каждом символе: без паники, принятые вызовы проходят схему.
  - Известное ограничение: Harmony от сервера с `skip_special_tokens` (маркеры вырезаны) не распознаётся — решение после живой проверки gpt-oss.

## 2026-11-09. R1-A, задача 5: коннектор Anthropic Messages

Запись описывает итоговое состояние после исправлений по ревью: устаревшие формулировки первой версии исправлены на месте, ревью M6.

- **`AnthropicWire`, `AnthropicDecoder`** (`wire/anthropic.rs`, `Connector::Anthropic`).
  - Запрос: `POST {base}/messages` (D37). Заголовки: `x-api-key` (`sensitive`), `anthropic-version: 2026-10-21`. Если в `messages` есть сообщение с `clear_at`, добавляется `anthropic-beta: mid-conversation-system-clear-at-2026-08-21`.
  - Насос SSE и признак конца потока вынесены в `wire/mod.rs` (`pump<D: StreamDecoder>`), Chat Completions пользуется тем же насосом. `bad_request` и `u64_at` стали общими.
  - `open` отправляет тело готовым текстом (`body_text` → `Box<RawValue>`). У `serde_json` для этого включена функция `raw_value`, новых крейтов нет. `HttpTransport::post_sse` теперь принимает любое `Serialize`.
- **Тело запроса.**
  - `system` — строкой на верхнем уровне.
  - `max_tokens` берётся из запроса, затем из `ctx.max_output_tokens`, иначе 8192 (D36).
  - `stream: true`; `stop` уходит как `stop_sequences`.
  - `temperature`, `top_p`, `top_k` не отправляются (D15); `seed` и `presence_penalty` — только `debug`.
  - Подряд идущие сообщения одной роли сливаются. Поэтому результаты инструментов одного хода уходят одним сообщением `user`: блоки `tool_result` первыми, `is_error` только при ошибке. Пустой текст не отправляется.
  - Инструменты идут в порядке `render_tools` в форме `{name, description, input_schema}`.
  - `cache_key` даёт `cache_control: {type: "ephemeral"}` на последнем инструменте и на `system`; тогда `system` — массив из одного блока `text`. Сам ключ провайдеру не уходит.
- **Мышление (D15, D36, решения контроллера).**
  - `Default` — полей мышления нет.
  - `Off` у адаптивных моделей и до зонда: поля `thinking` нет, `output_config.effort = "low"`. Причина: `{type:"disabled"}` у Opus 5.5 и Sonnet 5.5 даёт 400; решение контроллера подтверждено.
  - `Off` при профиле с `adaptive = false`: полей нет.
  - `Effort(e)` и `Budget(n)` у адаптивных моделей и до зонда (решение контроллера, отступление от брифа): `thinking: {type: "adaptive"}` и `output_config.effort`; `Budget` переводится через `Effort::nearest`.

  - Известное ограничение (ревью M2): у Opus 4.8/4.7/4.6 и Sonnet 4.6 без поля `thinking` мышление и так выключено, и `effort: low` там только снижает глубину ответа. - **`tool_choice` (решения контроллера).**
  - `auto` и `none` уходят как есть.
  - Принудительный выбор (`any`, `tool`) отправляется только при трёх условиях: профиль без adaptive, `caps.tool_choice_required`, мышление в запросе не включено.
  - В остальных случаях — `auto` и инструкция «Ответь вызовом инструмента `X`.» или «…одного из доступных инструментов.». Сюда входят Opus 5.5, Sonnet 5.5, Fable 5.1, любые адаптивные модели, профиль до зонда и запрос с включённым мышлением.

  - Откат профиля по D15 (`tool_choice_required = false` после 400) — задачи 9 и 15.
  - `caps.parallel_tools = false` даёт `disable_parallel_tool_use: true`.
  - До отправки `BadRequest`: принудительный выбор без инструментов, неизвестное имя инструмента, повтор имени.
- **`strict`** отправляется только при `caps.strict_schema` и схеме из белого списка strict-режима Anthropic (Structured outputs, «JSON Schema limitations», проверено 2026-11-09).
  - Не допускаются `minimum`, `maximum`, `multipleOf`, `minLength`, `maxLength`.
  - `minItems` — только 0 или 1; `format` — из списка; `enum` — из простых значений; `allOf` — без `$ref`.
  - У каждого объекта `additionalProperties: false` и полный `required`.
  - `$ref` только локальный и не внутри `$defs`: рекурсия не поддерживается.
  - На запрос не больше 20 strict-инструментов и 16 объединений.
  - Белый список отличается от OpenAI, поэтому у Anthropic он свой.
- **Декодер.**

В стриме `thinking_tokens` приходит только в последнем `message_delta`.

- **Возврат рассуждения.**
  - Формат: `ReplayBlob { wire: AnthropicMessages, model, data: {signature, blocks} }`. `blocks` — блоки ответа в исходном порядке: `thinking` с подписью и `redacted_thinking` целиком, `text` целиком, `tool_use` ссылкой по `id`. `signature` — подпись первого блока `thinking`.
  - Блоб восстанавливает сообщение ассистента в исходном порядке. Блоки мышления идут без изменений. Текст — как был, если не менялся; иначе весь текст встаёт на место первого блока. Вызовы берутся из `Part::ToolCall`.
  - Блоб отправляется при любой модели, если протокол Anthropic. Решение контроллера по ревью M5 отменяет фильтр плана «только та же модель». Документация велит передавать блоки и при смене модели: нечитаемые API отбрасывает сам и бесплатно.
  - Порядок блоков важен: у Opus 5.5 и Sonnet 5.5 между вызовами идут блоки `thinking` с заметками, а preserved thinking сверяет историю.
  - Входы `tool_use` возвращаются байт-в-байт, то есть исходным текстом `raw_arguments`, если он совпадает с разобранными аргументами. По FAQ «Preserved thinking» это не обязательно («key order doesn't matter», ревью M1), но оставлено решением контроллера.

`za-store`: blobs по BLAKE3 (`put_blob` идемпотентен; до 1 МиБ в строке `blobs`, больше — файл `blobs/<hash>` рядом с `journal.db`, запись через временный файл, `fsync` и переименование; при чтении хеш и размер сверяются). Payload события длиннее `BLOB_THRESHOLD` = 64 КиБ канонического JSON сохраняется blob в той же транзакции, в строке события `null` и `blob_ref`; `read_after` и `read_run` подставляют payload обратно (ARC-032). Runs: `create_run` (статус `queued`, `generation` 0, `root_id` от родителя, у корня свой `id`) и `set_status` (сверка `expected_generation`, затем таблица переходов, `generation + 1`) пишут `run.created` и `run.status {from, to, generation}` в той же транзакции. Снимки: `save_snapshot` (тот же `seq` заменяется), `latest_snapshot` по наибольшему `seq`. Новые ошибки: `UnknownRun`, `InvalidTransition`, `StaleGeneration`. Миграция схемы не понадобилась. Тест `disk_full` переведён на payload 512 КиБ: 1 МиБ теперь уходит в файл и БД не переполняет.

## 2026-11-08. R0, задача 4: устойчивость к `kill -9`

Тестовый бинарник `za-store/src/bin/crash_writer.rs` пишет события из четырёх потоков (убийство попадает и в середину group commit) и печатает `seq` каждого подтверждённого с немедленным flush. `tests/crash.rs` убивает его через `Child::kill` (TerminateProcess на Windows, SIGKILL на Linux) через 50…753 мс после первого подтверждения, открывает журнал заново и проверяет, что все напечатанные `seq` на месте: 20 раундов с `Durability::Normal` и 5 раундов с `append_durable`. На Windows прошло без потерь; `journal.lock` после убийства свободен. За окно 50 мс подтверждается около 430 событий в режиме Normal и около 3 в режиме durable. Тест ловит потерю: при подмене печатаемого `seq` падает в первом раунде. Время теста около 21 с.

## 2026-11-08. R0, задача 3: журнал на SQLite

Крейт `za-store`: `journal.db` в каталоге проекта, блокировка `journal.lock` (`File::try_lock`, второй `open` даёт `StoreError::Locked`), миграции по `PRAGMA user_version` (схема 0001: `runs`, `events`, `effects`, `interrupts`, `snapshots`, `blobs`, таблицы STRICT, `seq` с AUTOINCREMENT). Один поток-писатель: group commit до 256 команд в `BEGIN IMMEDIATE`, у каждой команды своя точка сохранения, ответ после COMMIT; SQLITE_FULL даёт `StoreError::Full`, писатель продолжает работу. Четыре читателя `query_only=ON` в своих потоках. `rusqlite 0.41.1` bundled, SQLite 3.54.1.

**Замер `synchronous`** (Windows, диск H:, 200 последовательных `append` и 2000 параллельных): FULL — 31…33 мс на последовательный `append`, 2000 параллельных за 0,47…0,48 с; NORMAL — 0,17 мс и 0,41 с. Group commit выравнивает пропускную способность, но задержка одиночной записи при FULL на два порядка выше.

**Решение (контроллер, раунд 1):** по умолчанию `Durability::Normal` (`synchronous=NORMAL`). WAL с NORMAL переживает `kill -9` (NFR-08), а FULL с 31…33 мс на запись ломает NFR-02 (≤ 50 мс на ход). Для записей, которые обязаны пережить отключение питания (намерения `NonIdempotent`-эффектов, задача 6), есть `append_durable`: пачка с такой командой целиком фиксируется с FULL, затем значение восстанавливается. `StoreOptions::durability = Full` включает FULL для всего. Повторный замер: `append` 0,17 мс, `append_durable` 33,4…33,8 мс, `append` сразу после серии durable 1,0…1,1 мс (вероятно, авточекпоинт WAL), 2000 параллельных `append` за 66…69 мс.
