# R1-M «Память»: план реализации

> **Для агентов-исполнителей:** ОБЯЗАТЕЛЬНЫЙ ПОД-СКИЛЛ: superpowers:subagent-driven-development (рекомендуется) или superpowers:executing-plans, задача за задачей. Шаги отмечаются чекбоксами (`- [ ]`).

**Goal:** агент R1-C2 подключается к серверу ZeroAIMemory `0.0.11-m6` (блок 8 дорожной карты). Клиент `za-memory` находит сервер и его возможности, ведёт сессию run, даёт замороженный дайджест на шаге 0, пакет восстановления после компакции и подсказки к вводу и ошибкам. Ключи моделей и поиска берутся только из Vault памяти: нет Vault — модели с ключом ждут, локальные без ключа работают. Модель получает инструменты памяти. Запись идёт через один шлюз с таксономией, маской, правилами доверия и ключом идемпотентности, при недоступной памяти — в outbox. Нейтральный снимок сессии отправляется после компакции, при остановке и при конце run. Контрактные тесты с записью гоняются только на тестовом сервере. Результат — сценарий S10 («продолжи» через неделю) и S4 с памятью; при недоступной памяти агент работает в L0.

**Architecture:**
- **`za-memory`** — содержимое заготовки R0 (D133):
  - `transport` — HTTP-клиент без прокси, заголовки, сроки, разбор problem+json и ошибок MCP;
  - `discovery` — `/api/v1/health`, уровень и флаги, проверка токена, решения и Vault;
  - `session`, `recall`, `fit` — сессия run, `/recall` и укладка ответа в бюджет;
  - `port` — `ZamMemory: za_core::MemoryPort`;
  - `vault`, `keys` — поиск записей по `key_ref`, раскрытие только нужных значений, ожидание Vault;
  - `gateway`, `taxonomy`, `outbox` — единственный писатель;
  - `tools` — инструменты модели (чтение через MCP, запись через шлюз);
  - `snapshot`, `files` — снимок сессии и `files/changed`.
- **`za-core`** получает порт памяти `memory` (перенос из `za-agent`, D138): `MemoryPort`, `Recall`, `MemoryLevel` (L0, L1, L2), `SessionNote`.
- **`za-agent`** — новые эффекты памяти в драйвере и компакции, состояние памяти run (снимок v5), подсказки append-сообщением, напоминание «итоги записаны».
- **`za-store`** — таблица `memory_outbox` (миграция 4).
- **`za-llm`** — причина «нет ключа» даёт источник ключей (`SecretSource::missing_reason`).
- **`za-jail`** — токен памяти не уходит в окружение дочерних процессов.
- **Бинарник** — раздел `[memory]`, привязка к решению (только доверенный проект), ключи из Vault с ожиданием, команды `memory status|outbox|init`, строки `doctor`, приёмка.

**Tech Stack:**
- Rust 1.99.1, edition 2024; tokio, serde, serde_json, blake3, thiserror, tracing, jiff; уже подключённые `reqwest =0.12.28` (`json`, `rustls-tls`, webpki-roots), `rusqlite =0.41.1`, `url =2.5.8`, `axum` (тесты).
- **Новых крейтов нет.** `za-memory` подключает только крейты из `[workspace.dependencies]`.
- Признак `test-hooks` (R1-C2 D128) у `za-memory` и `zero-agent`: подмены для тестов и `EnvStore` в бинарнике существуют только с ним (D143).

## Global Constraints

Все ограничения R1-B1, R1-B2, R1-C1 и R1-C2 (разделы Global Constraints их планов) действуют без изменений. Дополнительно:

- **Решения владельца 2026-11-16 обязательны** (D132):
  1. Vault недоступен (сервер выключен или Vault заблокирован) — агент ждёт его возвращения. Модели и поиск, которым нужен ключ, не запускаются. Запасного чтения `ZA_SECRET_*` нет. Локальные модели без ключей работают. `EnvStore` остаётся только для тестов и CI (D143). Запись ZAM `i:01M7GSTKNCEAB96HCY6RH05GBM`.
  2. Записи окружения из Vault (`host`, `environment`: адреса, назначение, ограничения, без паролей) показываются всем моделям, включая облачные (D144). `i:01M7GTX72QEF4TS64YSQ5EKK52`.
  3. Идеи — по режиму памяти: разбор идей агентом включён — агент разбирает, выключен — ждёт «начать» человека. Режим определяется по флагу, а не по ответу 409 (D148). `i:01M7GW48TNE3S8XDF4WC9SVX7E`.
  4. Тесты с записью — только на тестовом сервере `http://192.168.0.210:7700`, пользователь `zeroagent-test`. Адрес и токен — только через окружение теста (`ZAM_URL`, `ZAM_TOKEN`) и `NO_PROXY=192.168.0.210`. На рабочем `192.168.0.240` — никогда, только снимки ответов на чтение. Живые тесты — под `#[ignore]`, в CI их нет (D151). Заметка ZAM `правила/тестовый-стенд-памяти` (`n:01M7GVP37FESVVTFJXF1D3MXNT`).
  5. Новые предложения к ZAM подаются идеями в решение ZAM, а не файлом (D156).
- **Решения контроллера обязательны:**
  - ключи ищутся в Vault решения проекта, затем в личном (Knowledge); имя записи равно `key_ref` из `config.toml`; раскрываются только нужные команде ключи, кэш живёт в процессе; раскрытие — событие журнала и запись аудита без значения (D143);
  - на малых окнах агент сам урезает правила памяти: `output_limit` через REST, приоритет «Задачи» над «Правилами» (D141);
  - рантайм работает через REST; MCP — только для инструментов чтения модели. Причина: MCP теряет код ошибки и не передаёт `output_limit`, `parent_id`, `record` (D137, D147).
- **Рабочий сервер памяти — общая память владельца.** Ни один тест, скрипт или ручная проверка не пишет в `192.168.0.240`: ни заметки, ни записи журнала, ни кэш, ни снимки, ни Vault. Помощник живых тестов отказывает до первого запроса, если хост `ZAM_URL` не `192.168.0.210` (D151). Снимки ответов с рабочего сервера хранят только форму JSON без значений: репозиторий публичный, а в ответах — память владельца (D151).
- **Секреты и токены** не читаются вручную и не печатаются: `vault get` и `?reveal=1` исполнитель руками не вызывает; токен тестового сервера приходит из окружения теста. Значения Vault и токен памяти не попадают в журнал, квитанции, outbox, снимок сессии, аудит, `Debug`, логи и тексты ошибок (Review Focus 1).
- **Фиктивные секреты и токены** в тестах собираются из частей (`["zam", "_", "t3st"].concat()`), цельной строкой формата не пишутся (GitHub push protection).
- Зависимости — правило R1-C2: версия `=x.y.z` из `Cargo.lock`; новых крейтов в R1-M нет. `cargo deny check` и `cargo xtask policy` зелёные.
- Направления крейтов (D133, `cargo xtask policy`):
  - `za-memory` — от `za-protocol`, `za-core`, `za-store`, `za-secrets`; не от `za-agent`, `za-llm`, `za-tools`, `za-jail`, `za-web`, `za-skills`, `za-extract`. От `za-memory` зависят только `zero-agent` и `xtask` (бюджет промптов, как `xtask → za-web`);
  - `za-agent` по-прежнему не зависит от `za-memory` (тест `xtask/src/policy.rs:648`) и от `reqwest`: порт памяти — в `za-core` (D138);
  - вызов `reqwest::Client::builder` в `za-memory` — только в `crates/za-memory/src/transport.rs` (правило D129 R1-C2 расширяется третьим держателем HTTP-клиента).
- Временные файлы — только в `.tmp/` проекта ZeroAgent (тесты) и в `<project>/.zero-agent/work/` (продукт). `/tmp`, `%TEMP%`, `AppData\Local\Temp` и scratchpad запрещены.
- Тексты для модели (описания инструментов, подсказки, отказы, пометки, напоминание, скилл `memory-protocol`) — на английском, только ASCII-пунктуация, входят в хэш промптов (D94, D155). Текст из памяти (русский Markdown ZAM) — данные: проходит `escape_untrusted` и обёртку `<memory …>` (MEM-006, SEC-054).
- Новые коды событий, причин, действий аудита и происхождений — константы `za_protocol`; строки в коде не дублируются.
- **Уроки R1-C1 и R1-C2:** сигнал в тестах — по каналу поддельного сервера или событию журнала, а не по таймеру; ожидание — под `within` × `ZA_TEST_TIME_SCALE`; `std::env::set_var` не используется (окружение — параметром конструктора или `Command::env`); тесты CI не ходят в сеть, только поддельные серверы на `127.0.0.1`; литералы структур с новыми полями дополняются `..Default::default()`.

## Review Focus

1. **Утечка секрета или токена.** Значение ключа из Vault и токен `ZA_MEMORY_TOKEN` ищутся по сырым байтам `ZA_HOME`, журнала, квитанций, `memory_outbox`, тела снимка сессии, аудита, stdout и stderr: их нет. `format!("{:?}")` клиента, ошибок и кэша ключей не содержит значений. Дочерний процесс `bash` не видит `ZA_MEMORY_TOKEN` и `ZAM_TOKEN`. Ошибка Vault или 401 не цитирует тело запроса. Тесты — задачи 1, 4, 6, 8, 12.
2. **Запись на рабочий сервер.** Ни один тест не может отправить запрос на `192.168.0.240`: охранник живых тестов, адреса поддельных серверов только `127.0.0.1`. Снимки формы не содержат значений из памяти владельца (заголовки, тексты, id, пути). Тесты — задача 10.
3. **Реплей и повторы.** Ключи эффектов памяти не зависят от уровня памяти (правило D50). Новые эффекты ставятся последними в шаге и не сдвигают номера старых. Повтор записи после сбоя посреди вызова, resume и досылка outbox не задваивают запись: `Idempotency-Key` равен ключу эффекта. Квитанция `{text}` без `state` из R1-B читается. Тесты — задачи 2, 5, 6, 12.
4. **Бюджет памяти на малом окне.** Окно 8k, дайджест с резервом Rules 1312 токенов и задачей `in_progress`: первое сообщение содержит строку задачи и `next_step` и укладывается в 200 токенов (MEM-030). Обрезанные разделы названы одной строкой. Тесты — задачи 3, 12.
5. **Враждебный репозиторий и враждебная память:**
   - `.zeroaimemory/solution.toml` указывает на чужое решение пользователя;
   - `.zero-agent/config.toml` проекта задаёт адрес памяти;
   - недоверенный проект пытается писать в Knowledge;
   - запись памяти содержит `</memory>` и «ignore previous instructions»;
   - модель просит `scope.all_solutions`, `space: "rules"`, `certainty: "axiom"`;
   - модель просит раскрыть Vault.

   Ожидание: привязка к решению только у доверенного проекта; адрес памяти проект не задаёт; недоверенный проект пишет — отказ; текст памяти экранирован; запросы вне решения и Knowledge, запись в Rules и `axiom` — отказ; инструмента Vault у модели нет. Тесты — задачи 5, 7, 11, 12.
6. **Ожидание Vault.** Vault заблокирован или сервер выключен:
   - run с облачной моделью ждёт, к модели нет ни одного запроса, `ZA_SECRET_*` не читается;
   - run с локальной моделью без `key_ref` идёт сразу;
   - после разблокировки ключ раскрывается один раз, эндпоинт зондируется, run идёт;
   - Ctrl+C во время ожидания завершает команду без run в журнале.

   Тесты — задачи 4, 12.
7. **Протокол ZAM:** `/health` в корне — HTML; `/mcp` без `Accept` — 406; ошибка MCP — HTTP 200 с `isError`; `type` `about:blank` у 400, 401, 403, 404; `?name=` у списка Vault молча игнорируется; предел хука 7500 байт у тела с `source` или `code_map`. Ожидание: клиент не попадает ни в одну из ловушек. Тесты — задачи 1, 3, 4, 7, 10.

## Вопросы владельцу (не блокируют план)

Каждый вопрос — отдельно и по-простому. До ответа действует решение в скобках.

1. **Где хранить пароль агента от памяти?** Агенту нужен свой ключ доступа к серверу памяти. Ключи моделей лежат в самой памяти, а этот ключ туда не положить: без него агент в память не войдёт. Сейчас план берёт его из переменной окружения Windows. Подходит так, или хранить его в файле в папке агента? (План: переменная `ZA_MEMORY_TOKEN`, D134.)
2. **Разбирать ли идеи, пока режим не виден?** Память скоро научится просить агента разбирать ваши идеи. Узнать, включено ли это у вас, агент пока не может: память ему этого не говорит, мы попросили ZeroAIMemory это добавить. До тех пор агент идеи не разбирает и ждёт вашего «начать». Так оставить? (План: ждать, D148.)
3. **Нужна ли проверка со старой версией памяти?** По ТЗ агент работает и с прошлой версией памяти. Живьём её проверить негде: тестовый сервер всегда новый. Поставить на тестовый стенд вторую, старую память или проверять старую версию только имитацией? (План: только имитацией, D151.)
4. **Чужой непроверенный проект и память.** В проекте, которому вы не дали доверие, агент может читать вашу общую память, но не пишет в неё ничего. Так подходит? (План: только чтение, D135.)
