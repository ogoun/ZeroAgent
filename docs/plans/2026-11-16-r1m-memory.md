# R1-M «Память»: план реализации

> **Для агентов-исполнителей:** ОБЯЗАТЕЛЬНЫЙ ПОД-СКИЛЛ: superpowers:subagent-driven-development (рекомендуется) или superpowers:executing-plans, задача за задачей. Шаги отмечаются чекбоксами (`- [ ]`).

**Goal:** агент R1-C2 подключается к серверу ZeroAIMemory `0.0.11-m6` и новее (тестовый стенд — `0.0.12-m6.5`, `4459dda`; оба — L2; блок 8 дорожной карты). Клиент `za-memory` находит сервер и его возможности, ведёт сессию run, даёт замороженный дайджест на шаге 0, пакет восстановления после компакции и подсказки к вводу и ошибкам. Ключи моделей и поиска берутся только из Vault памяти: нет Vault — модели с ключом ждут, локальные без ключа работают. Модель получает инструменты памяти. Запись идёт через один шлюз с таксономией, маской, правилами доверия, проверкой области и ключом идемпотентности, а каждая запись с ключом сначала встаёт в outbox. Нейтральный снимок сессии отправляется после компакции, при остановке и при конце run. Токен памяти и клиент `zam` недоступны модели: защищённые места, встроенный запрет команды, чистое окружение детей, шаблон маски. Контрактные тесты с записью гоняются только на тестовом сервере. Результат — сценарий S10 («продолжи» через неделю) и S4 с памятью; при недоступной памяти агент работает в L0.

**Architecture:**
- **`za-memory`** — содержимое заготовки R0 (D133):
  - `transport`, `clock` — HTTP-клиент без прокси и редиректов, заголовки, сроки, разбор problem+json и ошибок MCP; часы и ожидание для тестов без таймеров;
  - `discovery` — `/api/v1/health`, уровень и флаги, проверка токена, решения и Vault;
  - `session`, `recall`, `fit` — сессия run, `/recall` без серверной обрезки и укладка ответа в бюджет на клиенте;
  - `port` — `ZamMemory: za_core::MemoryPort`;
  - `vault`, `keys` — поиск записей по `key_ref`, раскрытие только нужных значений, ожидание Vault;
  - `taxonomy`, `gate`, `scope`, `gateway`, `outbox` — единственный писатель: одна функция решения, проверка области, транзакционная очередь;
  - `tools`, `ideas` — инструменты модели (чтение через MCP, запись через шлюз), режим идей;
  - `snapshot`, `files` — снимок сессии и `files/changed`.
- **`za-core`** получает порт памяти `memory` (перенос из `za-agent`, D138), защищённые места `Roots.sealed` (D157), `ToolCx.facts`, `ToolOutput.memory`, `Tool::max_tier`, `Tool::clean` (D162).
- **`za-agent`** — новые эффекты памяти в драйвере и компакции, доигрывание шагов старых журналов без них (D161), состояние памяти run (снимок v5), подсказки append-сообщением, напоминание «итоги записаны», встроенный запрет клиента `zam` в `bash` (D158).
- **`za-store`** — таблица `memory_outbox` (миграция 4).
- **`za-llm`** — причина «нет ключа» даёт источник ключей (`SecretSource::missing_reason`).
- **`za-jail`** — переменные `ZAM_*` и `ZA_MEMORY_*` не уходят в окружение дочерних процессов (D159).
- **`za-secrets`** — шаблон токена `zam_`, маска, пересобираемая после каждого раскрытия (`MaskCell`, D160).
- **Бинарник** — раздел `[memory]`, привязка к решению (только доверенный проект), ключи из Vault с ожиданием, команды `memory status|outbox|init`, строки `doctor`, догоняющий снимок, приёмка.

**Tech Stack:**
- Rust 1.99.1, edition 2024; tokio, serde, serde_json, blake3, thiserror, tracing, jiff; уже подключённые `reqwest =0.12.28` (`json`, `rustls-tls`, webpki-roots), `rusqlite =0.41.1`, `url =2.5.8`, `axum` (тесты).
- **Новых крейтов нет.** `za-memory` подключает только крейты из `[workspace.dependencies]`.
- Признак `test-hooks` (R1-C2 D128) у `za-memory` и `zero-agent`: подмены для тестов, ручные часы и `EnvStore` в бинарнике существуют только с ним (D143, D165).

## Global Constraints

Все ограничения R1-B1, R1-B2, R1-C1 и R1-C2 (разделы Global Constraints их планов) действуют без изменений. Дополнительно:

- **Решения владельца 2026-11-16 обязательны** (D132):
  1. Vault недоступен (сервер выключен или Vault заблокирован) — агент ждёт его возвращения. Модели и поиск, которым нужен ключ, не запускаются. Запасного чтения `ZA_SECRET_*` нет. Локальные модели без ключей работают. `EnvStore` остаётся только для тестов и CI (D143). Запись ZAM `i:01M7GSTKNCEAB96HCY6RH05GBM`.
  2. Записи окружения из Vault (`host`, `environment`: адреса, назначение, ограничения, без паролей) показываются всем моделям, включая облачные, во всех run, где память читается, в том числе в недоверенном проекте (D144; ответ владельца 2026-11-16 в `preflight-rulings.md`). `i:01M7GTX72QEF4TS64YSQ5EKK52`.
  3. Идеи — по режиму памяти: разбор идей агентом включён — агент разбирает, выключен — ждёт «начать» человека. Режим токену прямо не виден; агент узнаёт его по признакам сервера (D148, D169). `i:01M7GW48TNE3S8XDF4WC9SVX7E`.
  4. Тесты с записью — только на тестовом сервере `http://192.168.0.210:7700`, пользователь `zeroagent-test`. Адрес и токен — только через окружение теста (`ZAM_URL`, `ZAM_TOKEN`) и `NO_PROXY=192.168.0.210`. На рабочем `192.168.0.240` — никогда; с него снимается только `GET /api/v1/health` без токена (D151). Живые тесты — под `#[ignore]`, в CI их нет. Заметка ZAM `правила/тестовый-стенд-памяти` (`n:01M7GVP37FESVVTFJXF1D3MXNT`).
  5. Новые предложения к ZAM подаются идеями в решение ZAM, а не файлом (D156).
- **Решения контроллера обязательны:**
  - ключи ищутся в Vault решения проекта, затем в личном (Knowledge); имя записи равно `key_ref` из `config.toml`; раскрываются только нужные команде ключи, кэш живёт в процессе; раскрытие — событие журнала и запись аудита без значения (D143);
  - **укладка памяти в бюджет — только клиентская** (preflight-rulings, заменяет прежнее «`output_limit` через REST»): `/recall` идёт без `output_limit`, потому что под пределом сервер снимает «Последнее известное состояние» и «Окружение» раньше правил; клиент кладёт ответ в бюджет сам, «Задачи» и «Последнее состояние» важнее «Окружения», оно важнее «Правил» (D141);
  - рантайм работает через REST; MCP — только для инструментов чтения модели. Причина: MCP теряет код ошибки и не передаёт `parent_id`, `record` (D137, D147).
- **Решения preflight по безопасности обязательны** (`preflight-rulings.md`, раздел «Безопасность»):
  - `~/.zeroaimemory/` и `ZA_HOME` — защищённые места: нативные инструменты их не читают и не пишут даже по гранту (D157);
  - вызов клиента `zam` (`zam`, `zam.exe`, полный путь) в `bash` — встроенный запрет, проект и глобальная конфигурация его не снимают (D158);
  - переменные `ZAM_*` и `ZA_MEMORY_*` удаляются из окружения дочерних процессов (D159);
  - HTTP-клиент памяти: редиректы выключены, системного прокси нет, адрес — только из глобальной конфигурации (D133, D134);
  - маска знает шаблон токена `zam_`; раскрытые значения Vault попадают в маску до первого использования ключа (D160);
  - область MEM-013 проверяется на всех параметрах, задающих пространство; чужое пространство — отказ без запроса (D164);
  - шлюз записи — единственный путь записи модели; `cache_put`, frontmatter заметок, правка доверенных записей из tainted-контекста, `origin: human` и `by: human` закрыты одной функцией решения (D163).
- **Рабочий сервер памяти — общая память владельца.** Ни один тест, скрипт или ручная проверка не пишет в `192.168.0.240` и не шлёт туда токен: ни заметки, ни записи журнала, ни кэш, ни снимки, ни сессии, ни Vault. Помощник живых тестов и `cargo xtask zam-shapes` отказывают до первого запроса, если хост `ZAM_URL` не `192.168.0.210` (для `zam-shapes` исключение — `GET /api/v1/health` без токена, D151).
- **Секреты и токены** не читаются вручную и не печатаются: `vault get` и `?reveal=1` исполнитель руками не вызывает; токен тестового сервера приходит из окружения теста. Значения Vault и токен памяти не попадают в журнал, квитанции, outbox, снимок сессии, аудит, `Debug`, логи и тексты ошибок (Review Focus 1).
- **Фиктивные секреты и токены** в тестах собираются из частей (`["zam", "_", "t3st"].concat()`), цельной строкой формата не пишутся (GitHub push protection).
- Зависимости — правило R1-C2: версия `=x.y.z` из `Cargo.lock`; новых крейтов в R1-M нет. `cargo deny check` и `cargo xtask policy` зелёные.
- Направления крейтов (D133, `cargo xtask policy`):
  - `za-memory` — от `za-protocol`, `za-core`, `za-store`, `za-secrets`; не от `za-agent`, `za-llm`, `za-tools`, `za-jail`, `za-web`, `za-skills`, `za-extract`. От `za-memory` зависят только `zero-agent` и `xtask` (бюджет промптов, снимки формы; как `xtask → za-web`); правило и юнит-тест — в задаче 2;
  - `za-agent` по-прежнему не зависит от `za-memory` (тест `xtask/src/policy.rs:648`) и от `reqwest`: порт памяти — в `za-core` (D138);
  - вызов `reqwest::Client::builder` в `za-memory` — только в `crates/za-memory/src/transport.rs` (правило D129 R1-C2, задача 6 R1-C2, расширяется третьим держателем HTTP-клиента).
- Временные файлы — только в `.tmp/` проекта ZeroAgent (тесты) и в `<project>/.zero-agent/work/` (продукт). `/tmp`, `%TEMP%`, `AppData\Local\Temp` и scratchpad запрещены.
- Тексты для модели (описания инструментов, пометки результатов, подсказки, отказы, напоминание, скилл `memory-protocol`) — на английском, только ASCII-пунктуация, входят в хэш промптов (D94, D155). Текст из памяти (русский Markdown ZAM) — данные: проходит `clean_invisible(…, Clean::Untrusted)` и `escape_untrusted` (MEM-006, SEC-051, SEC-054).
- Новые коды событий, причин, отказов, действий аудита и происхождений — константы `za_protocol`; строки в коде не дублируются.
- **Уроки R1-C1 и R1-C2:** сигнал в тестах — по каналу поддельного сервера или событию журнала, а не по таймеру; ожидание — под `within` × `ZA_TEST_TIME_SCALE`; интервалы клиента (повторная проба, повторы записи, ожидание Vault) — через `Clock`/`Sleeper` (D165), в тестах — ручные часы без сокетов под `start_paused`; `std::env::set_var` не используется (окружение — параметром конструктора или `Command::env`); тесты CI не ходят в сеть, только поддельные серверы на `127.0.0.1`; литералы структур с новыми полями дополняются `..Default::default()` или полем явно (списки мест — в Files задач).

## Review Focus

1. **Утечка секрета или токена.** Значение ключа из Vault и токен `ZA_MEMORY_TOKEN` ищутся по сырым байтам `ZA_HOME`, журнала, квитанций, `memory_outbox`, тела снимка сессии, аудита, stdout и stderr: их нет. `format!("{:?}")` клиента, ошибок и кэша ключей не содержит значений. Дочерний процесс `bash` не видит `ZAM_*` и `ZA_MEMORY_*`; `zam …` в `bash` — отказ; `read`, `search`, `glob` в `~/.zeroaimemory/` и `ZA_HOME` — отказ даже по гранту. Строка `zam_` + 40 символов в выводе маскируется. Редирект сервера памяти не исполняется. Ошибка Vault или 401 не цитирует тело запроса. Тесты — задачи 1, 2, 5, 7, 9, 13.
2. **Запись на рабочий сервер.** Ни один тест не может отправить запрос на `192.168.0.240`: охранник живых тестов разбирает URL (`url::Url::host()`), адреса поддельных серверов только `127.0.0.1`; `zam-shapes` к рабочему серверу шлёт только `GET /api/v1/health` без токена и без `X-Zam-Session`. Снимки формы не содержат значений (заголовки, тексты, id, пути). Тесты — задача 11.
3. **Реплей и повторы.** Ключи эффектов памяти не зависят от уровня памяти (D50). Аргументы прежних эффектов `memory.snapshot`, `memory.before`, `memory.after` не меняются. Шаг, начатый кодом R1-C2 (снимок v4), доигрывается без новых эффектов памяти; golden-журналы R1-C2 продолжаются без `ReplayMismatch` (D161). Повтор записи после сбоя посреди вызова, resume и досылка outbox не задваивают запись: `Idempotency-Key` равен ключу эффекта, тело детерминировано. Квитанция `{text}` без `state` из R1-B читается. Тесты — задачи 3, 6, 7, 13.
4. **Бюджет памяти на малом окне.** Окно 8k, дайджест с резервом Rules 1312 токенов и задачей `in_progress`: первое сообщение (дайджест и подсказка вместе) содержит строку задачи и `next_step` и укладывается в 200 токенов (MEM-030). Обрезанные разделы названы одной строкой. Подсказки эпохи не превышают потолка (D168). Описания памяти — в своём столбце бюджета, префикс small ≤ 1800 (D166). Тесты — задачи 4, 8, 13.
5. **Враждебный репозиторий и враждебная память:**
   - `.zeroaimemory/solution.toml` указывает на чужое решение пользователя;
   - `.zero-agent/config.toml` проекта задаёт адрес памяти;
   - `CLAUDE.md` проекта содержит `ZeroAIMemoryUrl=http://evil`, модель зовёт `zam` через `bash`;
   - недоверенный проект пытается писать в Knowledge;
   - запись памяти содержит `</memory>`, U+202E и «ignore previous instructions»;
   - модель просит `scope.all_solutions`, `scope.spaces` с чужим пространством, `include_human`, `memory_tree` чужого пространства, `memory_read` пути `<чужое>:/…`, `space: "rules"`, `certainty: "axiom"`, `certainty:` во frontmatter заметки, `cache_put` с `promote`, `idea origin: human`, `answer by: human`, правку `theorem` из tainted-контекста;
   - модель просит раскрыть Vault.

   Ожидание: привязка к решению только у доверенного проекта; адрес памяти проект не задаёт; `zam` в `bash` — отказ; недоверенный проект пишет — отказ; текст памяти очищен и экранирован; запросы вне решения и Knowledge, запись в Rules, `axiom`, `by: human`, `origin: human`, `promote` и правка доверенной записи из tainted-контекста — отказ; frontmatter статуса снимается; инструмента Vault у модели нет. Тесты — задачи 1, 6, 8, 12, 13.
6. **Ожидание Vault.** Vault заблокирован или сервер выключен:
   - run с облачной моделью ждёт, к модели нет ни одного запроса, `ZA_SECRET_*` не читается;
   - run с локальной моделью без `key_ref` идёт сразу;
