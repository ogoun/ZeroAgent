# R1-B2 «Контекст и отказы»: план реализации

> **Для агентов-исполнителей:** ОБЯЗАТЕЛЬНЫЙ ПОД-СКИЛЛ: superpowers:subagent-driven-development (рекомендуется) или superpowers:executing-plans, задача за задачей. Шаги отмечаются чекбоксами (`- [ ]`).

**Goal:** цикл R1-B1 держит контекст модели в пределах окна: считает токены, выгружает большие выводы, удаляет старые результаты, сжимает историю пилой и показывает, из чего состоит запрос. Детекторы таблицы 3.4 ловят повторы, циклы, застой, вырождение стрима и падение кэша. Лимиты промптов проверяются токенизаторами в CI.

**Architecture:**
- Всё — в `za-agent` поверх драйвера R1-B1. Ни одного нового примитива `za-core`.
- `ModelPort` получает два метода с реализацией по умолчанию: `count_tokens` (точный счёт у llama.cpp через `/tokenize`) и `render_request` (точное тело запроса для инспектора). `Gateway` реализует оба.
- Решения о контексте принимаются на границе шага по данным эффекта `context`, поэтому реплей после сбоя повторяет те же компакции (R1-B1 D9).
- Состояние счётчика, детекторов, эпохи и вводов пользователя входит в снимок run (версия 2, D66).
- `xtask prompt-budget` считает промпты токенизаторами cl100k и o200k (`tiktoken-rs`, только в `xtask`).

**Tech Stack:**
- Rust 1.99.1, edition 2024; tokio, serde, serde_json, blake3, thiserror, tracing.
- Новая зависимость: `tiktoken-rs 0.12.1` (MIT, 2026-09-24), только в `xtask`.

**Spec:**
- `docs/specs/2026-11-06-zero-agent-tz/`: часть 02 (раздел 2: CTX-001…018, таблица 2.3; раздел 3.4; раздел 4: PRM-007, распределение лимита Full), часть 01 (раздел 8: OPS-002…004; ARC-021), часть 04 (MEM-030, MEM-050, L0), часть 05 (SEC-004), приложение A (замеры).
- План-предшественник: `docs/plans/2026-11-09-r1b1-loop.md` — его интерфейсы этот план считает существующими. Решения R1-B1 — строки Ruling и Carry в `.superpowers/sdd/2026-11-09-r1b1-loop/progress.md` и `docs/journal.md`; при расхождении с текстом плана R1-B1 верен код ветки.
- Предварительная проверка: `.superpowers/sdd/2026-11-09-r1b2-context/preflight-scan.md`; как учтена каждая находка — строки Ruling в `progress.md` того же каталога.
- Разбиение: `docs/plans/2026-11-09-r1-overview.md`.

## Global Constraints

Все ограничения R1-B1 (раздел Global Constraints плана `2026-11-09-r1b1-loop.md`) действуют здесь без изменений. Дополнительно:

- `tiktoken-rs` подключается только к `xtask`; рабочие крейты токенизатор не тянут. Проверка — `cargo xtask policy` (задача 5).
- Выгрузка вывода пишет только в `<project>/.zero-agent/work/spill/` (SEC-004; временные файлы — ARC-021); каталог `.zero-agent/work/` получает `.gitignore` со строкой `*`.
- Сводка компакции — производный недоверенный ввод (CTX-011): событие с `tainted = true`, весь текст сводки (часть модели, цель, сообщения пользователя) проходит `escape_untrusted`.
- Порог `za-core` не трогается: план не меняет `crates/za-core/src`.
- Тесты — по образцу R1-B1: сигналы подаются по событию шины или журнала (`nth_of`), а не по таймеру; каждое ожидание — под тайм-аутом × `ZA_TEST_TIME_SCALE` (`within`); точка сбоя — `LoopDeps.crash` с `CrashPoint` (`crash_at`), а не брошенный future (Ruling 5.11 R1-B1: брошенный future не отменяет уже отправленную запись); верхних границ по времени, которые на деле меряют задержку писателя журнала, нет; дроби сравниваются с допуском или в целых.

## Review Focus

1. **Компакция посреди длинного run и затем `kill -9`.** После resume история той же эпохи, запросы совпадают с записанными, сводка не делается второй раз. Тесты в задачах 3 (`CrashPoint::AfterCompact`) и 9 (трасса).
2. **Огромный вывод с кириллицей и длинными строками** (лог сборки 20 МиБ, одна строка 5 МиБ). Обрезка не режет символ UTF-8 пополам, в контексте остаётся голова, хвост и строка `omitted N lines; search <path>` (для разреза внутри строки — `omitted N bytes`), полный текст лежит в spill, лимит соблюдён после экранирования. Тест в задаче 2.
3. **Переполнение контекста сервером** (`ContextOverflow` или тихая обрезка при малом `n_ctx`). Аварийная компакция и один повтор, без бесконечного цикла: не больше одной компакции по порогу на границе, подавление бесполезных компакций, повторная обрезка — пауза `context`, повторный отказ — пауза `context`. Тесты в задачах 1 и 3.
4. **Модель зациклилась**: одинаковые вызовы, ABAB, повтор текста в стриме, бесконечное рассуждение (в том числе замолчавший стрим). Run не тратит бюджет бесконечно: реакция по таблице 3.4, затем `blocked` или пауза. Тесты в задачах 6 и 7.
5. **Инструкция в выводе инструмента или в сводке** (`</summary>`, `<control from="user">`). После компакции она не становится частью системного текста или командой. Тест в задаче 3.
