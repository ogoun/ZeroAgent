# R1-A «Модели»: план реализации

> **Для агентов-исполнителей:** ОБЯЗАТЕЛЬНЫЙ ПОД-СКИЛЛ: superpowers:subagent-driven-development (рекомендуется) или superpowers:executing-plans, задача за задачей. Шаги отмечаются чекбоксами (`- [ ]`).

**Goal:** единый интерфейс к llama.cpp, vLLM, OpenRouter, Anthropic, OpenAI и любому OpenAI-совместимому серверу. Все обращения к моделям идут через общую очередь, где у локальных и облачных моделей отдельные пулы и лимиты. Монитор следит за CPU, RAM, GPU, VRAM и дисками и при нехватке ресурса ставит следующих просителей на паузу.

**Architecture:**
- `za-llm` без функций даёт только чистые части: канонический формат сообщений, возможности провайдера, таксономию ошибок, нормализацию вызовов и трейт `ModelPort`. Его подключает `za-core`.
- Функция `http` добавляет коннекторы, разбор SSE и зонды. Функция `gateway` добавляет очередь, повторы, предохранитель, слоты llama.cpp и `Gateway` — единственную реализацию `ModelPort` для рабочего кода.
- Новый крейт `za-res` собирает снимки ресурсов узла и решает допуск. От других `za-*` он зависит только через `za-protocol`.
- Бинарник `zero-agent` читает раздел `[models]` и `[resources]` конфигурации и показывает модели, ресурсы и очередь.

**Tech Stack:**
- Rust 1.99.1, edition 2024.
- tokio: `sync`, `time`, `rt`, `process`, `macros`.
- reqwest 0.12.28 с `rustls-tls`; чтение тела через `Response::chunk()`, без функции `stream`.
- serde, serde_json (`float_roundtrip`), blake3, jiff, thiserror, tracing.
- Новые зависимости: `sysinfo 0.40.x` (`system`, `disk`) и `toml` (только в бинарнике).
- axum 0.8.9 — только в тестах, как поддельный HTTP-сервер.

**Spec:**
- `docs/specs/2026-11-06-zero-agent-tz/`: часть 02 (раздел 3: MDL-001…023, таблица 3.4), часть 03 (раздел 7: RES-001…024), часть 01 (разделы 3, 4.3, 5, 6.1, 7–10), часть 05 (SEC-040, SEC-044, SEC-100), часть 07 (UI-046), часть 00 (D-24).
- Заметки заказчика N-12, N-13, N-17…N-20: `docs/research/2026-11-06-landscape/00-customer-notes.md`.
- Разбиение R1: `docs/plans/2026-11-09-r1-overview.md`. Карта этапов: `docs/plans/2026-11-06-roadmap.md` (блоки 2 и 16).

## Global Constraints

Перенесено из R0:

- Платформы Windows x64 и Linux x64, тесты зелёные на обеих (`ubuntu-latest`, `windows-latest` в CI).
- Зависимости минимальны: только crates.io с закреплёнными версиями. Запрещены `git =`, внешние `path =`, submodule, код других агентов и агентные фреймворки (ARC-012, N-13). Причина каждой новой зависимости пишется комментарием в `[workspace.dependencies]` и в `docs/journal.md`. `cargo deny check` и `cargo xtask policy` зелёные.
- Журнал только дополняется, at-least-once на шаг (CORE-001). R1-A журнал не пишет: события `model.*` пишет цикл в R1-B.
- Временные файлы только внутри проекта: тесты используют `env!("CARGO_TARGET_TMPDIR")`, рабочие файлы — `.tmp/`. Системные `%TEMP%` и `/tmp` запрещены (ARC-021). Фикстуры ответов провайдеров лежат в репозитории.
- Логи через `tracing`, ошибки библиотек через `thiserror`, без `unwrap` вне тестов.
- Телеметрии наружу нет (ARC-043). Облако не вызывается, пока пользователь сам не настроил ключ (MDL-021).
- Коммиты на русском в стиле `feat(llm): …`.
- `docs/journal.md` и `CHANGELOG.md` обновляются в каждой задаче, меняющей поведение (OPS-021).

Новое в R1-A:

- `unsafe_code = "forbid"` действует во всех крейтах, в том числе в `za-res`; переопределять его в R1-A запрещено.
- Ключи и токены не попадают в журнал, логи, `Debug`, сообщения ошибок и кэш профилей (SEC-040, SEC-044). Тип `Secret` не реализует `Display` и `Serialize`, а его `Debug` печатает `***`.
- Модель вызывается только через `Gateway` (RES-001). Коннекторы — `pub(crate)`; наружу из `za-llm` торчат только `ModelPort`, `Gateway`, `ScriptedModel` для тестов и зонды.
- Автоматического перехода на другую модель нет, тем более в облако (MDL-016, D-24). `Gateway` никогда не меняет эндпоинт запроса.
- Тесты коннекторов не используют облачные ключи. Работают на поддельном axum-сервере с записанными фикстурами, в том числе SSE. Живые тесты помечены `#[ignore]` и читают `LLAMA_TEST_URL`, `VLLM_TEST_URL`, `OPENROUTER_TEST_KEY`, `ANTHROPIC_TEST_KEY`, `OPENAI_TEST_KEY`, а модель — из `ZA_TEST_<PROVIDER>_MODEL`.
- Порог `za-core` в `xtask/core-size-limit.txt` (5000 строк) не повышается: модельный слой живёт вне ядра (ARC-011).
- Направление зависимостей: `za-res` из всех `za-*` зависит только от `za-protocol`. `za-core` подключает `za-llm` с `default-features = false`. Обе проверки — в `cargo xtask policy`.

## Review Focus

1. **Обрыв стрима посреди вызова инструмента** (локальный сервер перезапустился, сеть моргнула). Частичный вызов не попадает в итоговое сообщение. Потребитель получает `StreamEvent::Restart` и чистый повтор, а после 5 повторов — типизированную ошибку. Тесты в задачах 10 и 15.
2. **Кириллица, разрезанная между чанками, CRLF и многострочное `data:`** в SSE. Текст собирается побайтово точно, без `�`. Тест в задаче 3.
3. **Утечка ключа** через `Debug` конфигурации, текст ошибки (провайдер эхом вернул заголовок) или кэш профиля. Ключ нигде не виден. Тесты в задачах 3 и 9.
4. **На машине нет NVIDIA**: GPU другого вендора, `nvidia-smi` нет в `PATH` или он отвечает `[N/A]`, как под WDDM на Windows. GPU помечается недоступным, допуск по VRAM не блокирует навсегда, остальные метрики идут. Тесты в задачах 11 и 12.
5. **Потерянный слот очереди**: вызывающий бросил стрим, задача упала с паникой или run отменён во время ожидания. Слот освобождается, заявка исчезает из снимка очереди. Тесты в задаче 13.

## Решения плана

Где ТЗ молчит или неоднозначно, решение принято здесь. Задачи на него ссылаются.

| № | Решение | Обоснование |
|---|---|---|
| D1 | Новый крейт `za-res`: монитор, допуск, резервирование диска. Очередь, повторы, слоты и `Gateway` — в `za-llm` за функцией `gateway`. | Ресурсы нужны не только моделям: R1-C (сборка, клонирование, RES-017) и R2 (браузер, воркеры) тоже их потребляют. Очередь RES-001 привязана к эндпоинтам моделей. `za-core` видит только трейт (ARC-010, таблица крейтов части 01). |
| D2 | Стрим — `tokio::sync::mpsc::Receiver<Result<StreamEvent, ModelError>>` внутри `ModelStream`. Сетевая задача пишет в канал. Drop `ModelStream` отменяет задачу и закрывает соединение. Без `futures` и без функции `stream` у reqwest: используется `Response::chunk()`. | Меньше зависимостей (N-13). Отмена через drop закрывает HTTP-соединение, и llama.cpp прекращает генерацию (NFR-04 ≤ 2 с). |
| D3 | MDL-020 «egress-прокси с подстановкой ключа» — часть отложенного SEC-100 (P3). В R1 ключ подставляет daemon в момент отправки из `SecretSource`. В `ChatRequest`, событиях и логах ключа нет. | SEC-100 отложен решением заказчика (N-15). Принцип части 01 «секреты остаются в daemon» соблюдён. Точка расширения — `SecretSource` и `HttpTransport`. |
| D4 | `SecretSource` в R1-A — переменные окружения `ZA_SECRET_<ИМЯ>`, где имя приводится к верхнему регистру и `-` заменяется на `_`. В конфигурации только `key_ref = "anthropic"`; литерал ключа там не принимается. Хранилище ОС и шифрованный файл (SEC-040) — R1-C, замена реализации без смены конфигурации. | Блок 7 (SEC-040) — в плане R1-C. Форма конфигурации не меняется при переходе. |
| D5 | Проверка аргументов по JSON Schema и приведение типов — своя подмножественная реализация, без крейта `jsonschema`. Поддерживаются: `type` (в том числе массив типов), `properties`, `required`, `additionalProperties`, `items`, `enum`, `const`, `minimum`/`maximum`, `minLength`/`maxLength`, `minItems`/`maxItems`, `anyOf`/`oneOf`, локальные `$ref` на `#/$defs/…` и `#/definitions/…`. Прочие ключевые слова игнорируются с `debug`. | Отклонение от стека части 01: `jsonschema` тянет regex-движки, разбор URL и HTTP-резолвер. Схемы инструментов простые, а приведение типов (шаг 6 MDL-005) всё равно требует своего обхода схемы. |
| D6 | GPU читается через `nvidia-smi --query-gpu=index,name,uuid,utilization.gpu,memory.total,memory.used,memory.free,temperature.gpu --format=csv,noheader,nounits`: отдельный процесс на каждый замер, таймаут 5 с, `kill_on_drop`. На Windows процесс запускается с `CREATE_NO_WINDOW` (`0x0800_0000`, безопасный `CommandExt::creation_flags`). Нет `nvidia-smi` или GPU другого вендора — `GpuStatus::Unavailable`, повторная попытка через 60 с. | Загрузка NVML через `libloading` требует `unsafe` (`Library::new` — unsafe fn), что запрещено `unsafe_code = forbid`. `nvml-wrapper` безопасен, но тянет `libloading` и proc-macro цепочку `wrapcenum-derive → darling → syn`. Вызов раз в 2 с даёт пренебрежимую нагрузку. AMD и Intel — P2, позже. |
| D7 | CPU, RAM и тома — через `sysinfo 0.40` (`default-features = false`, `features = ["system", "disk"]`, лицензия MIT). Ввод-вывод тома — `Disk::usage()`. Если платформа даёт нули или не поддерживает метрику, поле равно `None`. | Без `unsafe` в нашем коде на обеих ОС. Своя реализация через WinAPI потребовала бы `unsafe`. |
| D8 | Параллелизм локального эндпоинта = `min(слоты сервера, max_parallel из конфигурации)`. Для llama.cpp слоты — `total_slots` из `/props`. Для vLLM и совместимых серверов — `max_parallel`, по умолчанию 4. VRAM работает как порог допуска, а не как делитель. | llama.cpp и vLLM выделяют KV-кэш при старте сервера на все слоты (`n_ctx` делится между `-np`; у vLLM — `gpu_memory_utilization`). Активный слот VRAM не добавляет, растут только чужие процессы. RES-002 «не выше числа слотов» выполняется. |
| D9 | Приоритеты (RES-003): `Interactive` 0, `Top` 1, `Orchestrator` 2, `Worker` 3, `Job` 4, `Arena` 5. Ранг заявки = `max(базовый − floor(ожидание / 30 с), min(базовый, 1))`; при равенстве — FIFO. Фоновые классы `Job` и `Arena` занимают в локальной группе не больше `max(1, n − 1)` слотов из `n`. | Старение против голодания без возможности обогнать пользователя (RES-013). Последний слот остаётся под интерактивную работу. |
| D10 | Пороги допуска по умолчанию: запас RAM — `max(2 ГиБ, 10 % RAM)`; аварийный пол RAM для `Interactive` — 512 МиБ; запас VRAM — 1024 МиБ, пол — 256 МиБ; запас места на томе — 5 ГиБ; низкое место на томе журнала — 2 ГиБ; CPU занят — ≥ 95 % дольше 10 с, касается только фоновых. Гистерезис: возобновление при свободном ≥ порог × 1,1, но не меньше порог + 256 МиБ. | ТЗ значений не задаёт. Величины безопасные для RTX 3090 и 64 ГБ RAM, все настраиваются в `[resources]`. |
| D11 | Периоды опроса: CPU и RAM — 1 с; GPU — 2 с; тома — 5 с; размеры категорий данных — 300 с, обход не больше 200 000 записей, при превышении `truncated = true`. | «Опрос раз в секунды, без LLM» (RES-010). Обход каталогов дорогой, поэтому редкий. |
| D12 | Очередь не завершает заявку по времени ожидания, если `max_wait` не задан. С `max_wait` заявка получает `QueueError::WaitTimeout`, и цикл R1-B переводит run в `paused` с причиной `queue`. | RES-007: долгое ожидание не превращает run в `failed`. |
| D13 | Профили моделей лежат в JSON-файлах `ZA_HOME/models/profiles/<bundle_key>.json`. Запись атомарная: временный файл рядом и `rename`. Перенос в таблицу `model_profiles` глобальной `agent.db` — в R1-D, вместе с глобальной БД. | Глобальной БД ещё нет, а MDL-003 требует хранить профиль на связку уже сейчас. |
| D14 | Бюджет облачной группы — дневной лимит в долларах, считается в памяти по UTC-суткам. Учёт по run и дереву с сохранением — CORE-113 в R1-B. | RES-004 требует бюджет в облачном пуле, а таблицы `usage` и бюджетов появятся в R1-B. |
| D15 | Anthropic: заголовок `anthropic-version: 2026-10-21`; `temperature`, `top_p`, `top_k` не отправляются (в этой версии API они дают 400). Способ мышления берётся из Models API: `capabilities.thinking.types.adaptive.supported` → `{"type":"adaptive"}` и `output_config.effort`; иначе `enabled` с `budget_tokens`. Если провайдер отверг принудительный `tool_choice` (400 с упоминанием `tool_choice`), профиль получает `tool_choice_required = false`, и запрос не повторяется с тем же значением. | Данные справочника Claude API на 2026-10. MDL-003: «реальные возможности важнее документации». |
| D16 | Стоимость в `Usage`: сумма от провайдера (`usage.cost` у OpenRouter, `cost_source = Provider`), иначе расчёт по ценам из конфигурации эндпоинта (`Computed`), иначе `None` (`Unknown`). Встроенной таблицы цен нет. | MDL-020 «реальная стоимость из ответа провайдера». Цены меняются, зашивать их нельзя. |
| D17 | Источники контекста MDL-004 для Ollama (`/api/ps`) и LM Studio (`/api/v1/models`) не реализуются: бэкенды P1 и P2. Произвольный совместимый сервер опрашивается через `/v1/models`, поля `max_model_len`, `context_length`, `context_window`. | Обязательные бэкенды по таблице 3.1 части 02. |
| D18 | Проба переполнения (MDL-004, шаг 3) делается только для локальных и совместимых эндпоинтов на этом хосте и только если рантайм не сообщил контекст. Один запрос с промптом 2 000 000 символов и `max_tokens = 1`: сервер отвергает его при проверке длины, и число берётся из текста ошибки функцией `parse_context_limit`. Если запрос принят — стрим сразу бросается, берётся консервативное значение. Консервативное значение — 8192, нижняя строка таблицы 2.3 части 02. Облако пробой переполнения не трогается никогда. | Отказ при токенизации быстрый; поиск делением пополам стоил бы минуты обработки промпта на GPU. В облаке проба стоила бы денег. |
| D19 | Повторы MDL-018: до 5. Задержка 1 с × 2^(n−1), потолок 30 с, джиттер ±20 %. `Retry-After` уважается до 120 с; если он дольше — повторов нет, `RateLimited` уходит вызывающему, run встаёт на паузу. | «До 5 повторов с экспоненциальной задержкой». Потолок не даёт стриму висеть минутами. |
| D20 | Повтор после того, как часть ответа уже ушла потребителю, порождает `StreamEvent::Restart { attempt, reason }`. Потребитель отбрасывает накопленное. Итоговое сообщение `Finished` собирается только из последней попытки. | Иначе в историю попал бы обрывок вызова инструмента (Review Focus 1). |
| D21 | Защита от повтора после ошибки разбора: `Gateway` хранит отпечаток запроса (`request_fingerprint`), который закончился `ErrorClass::Malformed`, по ключу run. Тот же отпечаток снова — `ErrorClass::RepeatedAfterParseError` без отправки. | MDL-018: «идентичный запрос после ошибки парсера не повторяется без изменения». |
| D22 | Предохранитель на эндпоинт (MDL-016): открывается после 5 неудачных запросов подряд (повторы уже исчерпаны) классов `Transport`, `Timeout`, `Overloaded`, `Server`, `StreamCut`. Пауза 30 с, затем одна пробная заявка. Повторный отказ удваивает паузу, потолок 300 с. `Auth` переводит эндпоинт в `Disabled` до `Gateway::reset` — это выбор пользователя «повторить». | Таксономия и пороги в ТЗ не заданы. Ошибки ключа не лечатся ожиданием. |
| D23 | Конфигурация R1-A: разделы `[models]` и `[resources]` файла `ZA_HOME/config.toml`, крейт `toml`. Раздел `resources` добавлен к списку разделов части 01, раздел 7. Полная схема слоёв ARC-040 — R1-D. | Нужна сейчас для эндпоинтов и порогов. Слои — блок 14 (R1-D). |
| D24 | `models.default` обязан ссылаться на локальный пул; иначе ошибка конфигурации `ConfigError::CloudDefault`. Порядок выбора: явный выбор run → выбор задания → роль → `default` (MDL-021). | «Локальная модель остаётся значением по умолчанию». |
| D25 | Пул эндпоинта: `anthropic`, `openai_responses`, `openai_chat` и `openrouter` всегда облачные. `llama_cpp`, `vllm` и `openai_compatible` — локальные, если хост loopback или частный адрес (RFC 1918, `fc00::/7`); иначе облачные. Конфигурация может переопределить. Допуск по ресурсам узла применяется только к эндпоинтам на этом хосте (loopback). | vLLM бывает «локальный и серверный» (таблица 3.1): сервер в локальной сети не тратит VRAM этого узла. |
| D26 | Таймауты: соединение — 2 с локально и 10 с в облаке; до первого байта — 300 с локально (длинные промпты; у llama.cpp `return_progress: true` держит поток живым) и 120 с в облаке; между чанками — 90 с. Локальные запросы идут без прокси (`no_proxy`), облачные учитывают `HTTPS_PROXY` из окружения. | Обработка промпта 64k на 27B занимает десятки секунд; корпоративный прокси нужен облаку. |
| D27 | MDL-006: нормализация помечает источник вызова (`CallSource::Content` или `Reasoning`), а `extracted_mutation_blocked` даёт решение для класса эффекта. Сам отказ в исполнении и nudge делает цикл R1-B: класс эффекта инструмента знает реестр инструментов. | Модельный слой не знает классов инструментов. |
| D28 | Проверка имени (MDL-005): единственный кандидат с расстоянием Дамерау — Левенштейна ≤ 2 исправляет имя с отметкой `Repair::NameCorrected`. Иначе — `CallRejection::UnknownTool` с ближайшими (до 3, по возрастанию расстояния). Для форматов без явных маркеров (`pythonic`, `llama3_json`) вызов извлекается из текста, только если имя известно или исправимо. | Таблица 3.4 «ошибка со списком ближайших».
