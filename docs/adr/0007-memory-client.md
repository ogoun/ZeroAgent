# ADR 0007. Клиент памяти ZeroAIMemory: `za-memory`, каналы, Vault, токен и клиент `zam`

- Статус: принято (R1-M, 2026-11-17). Источник: решения плана D133–D168, `docs/plans/2026-11-16-r1m-memory.md`; ruling контроллера — `.superpowers/sdd/2026-11-16-r1m-memory/progress.md` и `preflight-rulings.md` (раздел «Безопасность»); решения владельца 2026-11-16 (Vault, окружение, идеи, тестовый стенд).
- Требования: часть 04 ТЗ (память), MEM-014, SEC-002 (граница shell — best effort), SEC-040, SEC-041 (секреты), раздел 9 (угрозы «враждебный репозиторий», «эксфильтрация»).

Разделы о Vault и ключах (задача 5), шлюзе записи (задача 6), outbox (задача 7), инструментах модели (задача 8) и снимке сессии (задача 9) дописывают эти задачи.

## Крейт `za-memory`, каналы и транспорт

**Контекст.** Агент R1-M подключается к серверу ZeroAIMemory `0.0.11-m6` и новее (тестовый стенд — `0.0.12-m6.5`). Серверу нужен токен агента, а токен — единственный секрет вне Vault (D134). Сервер отвечает по двум каналам: REST `/api/v1/…` с ошибками problem+json и MCP `/mcp` (streamable HTTP без сессий протокола), у которого ошибки инструментов — HTTP 200 с `isError` и текстом, а код `type` теряется. По умолчанию `reqwest` берёт прокси из окружения и повторяет 307 и 308 с телом и всеми заголовками на другой хост.

**Решение.**

1. **Крейт** `za-memory` (D133): от `za-protocol`, `za-core`, `za-store`, `za-secrets` (все виды); от него — только `zero-agent` и `xtask`. `za-agent` его не видит: порт памяти — в `za-core` (D138, задача 3). Правило и юнит-тест — `cargo xtask policy` (`MEMORY_ALLOWED_ZA_DEPS`, `MEMORY_USERS`, `r1m_memory_directions`).
2. **Третий держатель HTTP-клиента** после `za-llm` и `za-web`: `reqwest` с теми же функциями (`json`, `rustls-tls`, webpki-roots; без сжатия, cookie, SOCKS, HTTP/2 — страж функций workspace D129 покрывает и его граф). `reqwest::Client` строится только в `crates/za-memory/src/transport.rs` (`HTTP_CLIENT_ALLOWED`); в остальных файлах крейта `reqwest` не упоминается вовсе (`HTTP_HOLDERS`, пустой список путей: метод HTTP — реэкспорт `transport::Method`), атрибут `path` и `include!` в `src/` запрещены (`check_holder_includes`, общий с `za-web`). Тесты крейта подключают `test-support/fake_zam.rs` через `#[path]` законно: страж сканирует только `src/` и `build.rs`.
3. **Свойства клиента** (D133, D137): `no_proxy()` всегда — токен не уходит прокси; `redirect(Policy::none())` — любой 3xx — ошибка `Protocol` «memory server redirected; not followed», переход не исполняется, второй сервер запроса не получает; соединение 2 с, срок каждого запроса — аргументом (`/health` 3 с, MCP 5 с, Vault 5 с, снимок 10 с, статус 5 с), он покрывает и чтение тела; `User-Agent: zero-agent/<версия>`. `Authorization: Bearer` ставится на каждый запрос с `set_sensitive(true)`, не в `default_headers`; `ZamClient: Debug` и `Token: Debug` — вручную (`zam_…`). Если сервер повторил токен в тексте ошибки, клиент заменяет его на `[token]` (защита в глубину).
4. **Адрес** — только `[memory] url` глобальной конфигурации: `http` или `https`, хост, без учётных данных, строки запроса и фрагмента, путь допустим (`server.base_path`). Проектный `[memory]` — только `enabled = false`, `url` и `machine` — предупреждение (D134). `doctor` предупреждает, если `http` ведёт на хост вне loopback и частных сетей: токен шёл бы открытым текстом (D152).
5. **Заголовки атрибуции:** `X-Zam-Machine` — всегда (`[memory] machine` или имя хоста), `X-Zam-Session`, `X-Zam-Solution`, `X-Zam-Area` — из контекста запроса; до 128 печатных символов, не-ASCII — байтами UTF-8 (`HeaderValue::from_bytes`), управляющий символ — ошибка до сети. `GET /api/v1/health` идёт анонимно: без токена и без `X-Zam-*` (D136).
6. **Каналы** (D137): REST — всё, что делает рантайм (обнаружение, сессии, `/recall`, снимок, Vault, запись, outbox). MCP `tools/call` — только чтение модели (`memory_search`, `memory_read`, `memory_tree`): без `initialize` и без `Mcp-Session-Id`, с `Accept: application/json, text/event-stream` (без него 406). Ответ — JSON или поток SSE (берётся первое сообщение с `result` или `error`).
7. **Неявная сессия MCP.** Запрос MCP без `X-Zam-Session` сервер привязывает к последней незавершённой сессии пользователя за 12 часов (с `X-Zam-Machine` — той же машины), и учёт выданного и отметки «выдавалось» легли бы в чужую сессию хуков. Поэтому клиент шлёт `X-Zam-Session` всегда, когда есть сессия run, и аргумент `session_id`, равный заголовку, у `memory_search`, `memory_read`, `memory_recall` (`SESSION_ARG_TOOLS` сервера); у `memory_tree` аргумента нет — учёт по заголовку. `X-Zam-Machine` сужает подбор неявной сессии, если сессии run нет.
8. **Ошибки** (D137): REST — `ZamError { kind, status, problem_type, title, detail, code, retry_after }`, вид — по коду; `type` различает только 400 `session-required` и 503 `busy`/`vault-locked` (у `about:blank` других признаков нет), 3xx и неожиданные коды (405, 406, 415) — `Protocol`. MCP — таблица четырёх форм текста `fail_text`/`problem_text` (`Ошибка <код> <title>[: <detail>][ (код <c>)]`, `Ошибка аргументов:`, `Внутренняя ошибка MCP:`, прочее — `Protocol` с исходным текстом до 500 символов), строка `~N tok` снимается; ошибка JSON-RPC (неизвестный инструмент) — `Protocol`. Разбор текста — обход до CR-25. Тексты ошибок — без тела запроса и без заголовков; HTML прокси не цитируется.
9. **Обнаружение** (D136): уровень — по флагам `features`, номер версии ни с чем не сравнивается: L0 — нет ответа или не ZAM (не JSON, нет `version`; корневой `/health` — HTML WebUI), L1 — нет `features`, L2 — есть `m6`; неизвестные флаги и поля сохраняются и пропускаются. Статус для `doctor` и `memory status`: токен — `GET /api/v1/spaces`, решение — `GET /api/v1/solutions/{guid}`, личный Vault — поле `locked`, выключенные типы подсказок — `hooks` ответа `POST /api/v1/recall {event: "session_start", record: false, budget_tokens: 1}` без сессии (ни отметок показа, ни учёта).
10. **Часы** (D165): все интервалы клиента — через `Clock` (`TokioClock`); в тестах — `ManualClock` под признаком `test-hooks`, время двигает тест.

**Отложено.** `initialize` один раз на процесс, если сервер ответит на `tools/call` без него ошибкой протокола (D137): живой сервер `0.0.11-m6` (rmcp без сессий, `NeverSessionManager`) его не требует, форма отказа неизвестна; проверка — живой тест задачи 11, реализация — по её итогу. Повторная проба после перехода в L0 (не чаще раза в 30 с, D136) и уведомление о смене уровня (`watch`) — в порту памяти (задача 4).

**Остаточные риски.** Имя хоста в `[memory] url` (кроме `localhost`) `doctor` не разрешает: адрес вида `http://memory.lan` получает предупреждение об открытом тексте, даже если хост в локальной сети. Сервер памяти, которому вы дали адрес, агент считает доверенным: тексты его ошибок (`detail`) попадают в журнал процесса и вывод `doctor`.

## Токен и клиент `zam`

**Контекст.** У агента свой токен памяти — переменная окружения `ZA_MEMORY_TOKEN` (D134); других источников нет. Но на машине пользователя есть и полный токен его клиента `zam`: файл `~/.zeroaimemory/config.toml` (`USERPROFILE` на Windows, `HOME` иначе). Клиент `zam` ищет адрес и токен независимо от агента: флаг → `ZAM_URL`/`ZAM_TOKEN` → `ZeroAIMemoryUrl`/`ZeroAIMemoryToken` в `CLAUDE.local.md`, `CLAUDE.md`, `AGENTS.md` вверх от текущего каталога → `~/.zeroaimemory/config.toml`. Враждебный репозиторий со строкой `ZeroAIMemoryUrl=http://evil` в `CLAUDE.md` и вызов `zam …` через `bash` отправили бы чужому серверу полный токен пользователя. Модель с инструментами чтения могла бы прочитать и сам файл токена, и `ZA_HOME/config.toml`.

**Решение.** Риск закрывается пятью мерами вместе (preflight 8.11; мера 5 — проход исправлений fix-1, Important 2 ревью задачи 1); каждая — встроенная, ни проект, ни глобальная конфигурация, ни гранты, ни режим `bypass`, ни записанное одобрение её не снимают.

1. **Защищённые места (D157).** `ZA_HOME` и `~/.zeroaimemory/` — места, где нативный инструмент не делает ничего: `read`, `search`, `glob`, список, `edit`, `multi_edit` и `cwd` команды — `denied: protected path`. Это первый шаг решения политики (`decide`), до правил и режима.
   - Корни run (`za_core::paths::Roots`) получают домашний каталог и список `sealed`: `Roots::with_home(home)` канонизирует `home`, как `ZA_HOME`, и кладёт в `sealed` `<home>/.zeroaimemory`, а если это ссылка или junction — ещё и её каноническую цель. `za-core` окружение не читает: домашний каталог передаёт бинарник (`zero_agent::home::user_home`, как у клиента `zam`). Без домашнего каталога (`LoopDeps::new`, тесты) `sealed` пуст, `ZA_HOME` защищён всё равно.
   - `paths::sealed_place` сверяет канонический путь, на Windows без учёта регистра, поэтому защита действует через ссылку, junction, короткое имя 8.3 и другой регистр. `paths::resolve` ставит `protected` при любом доступе, политика (`call_of`) повторяет проверку.
   - Слова команды `bash` — все слова `argv`, цели перенаправлений и значения опций каждого сегмента, включая тела подстановок и строку вложенной интерпретации — разбираются лексически: начало `~`, `$HOME`, `${HOME}`, `%USERPROFILE%`, `$env:USERPROFILE`, `${env:USERPROFILE}`, `$env:HOME`, `${env:HOME}` (`za_shell::HOME_PREFIXES`) раскрывается по домашнему каталогу корней, абсолютный путь берётся как есть. Слово внутри защищённого места — тот же отказ.
   - **Начало домашнего каталога задаёт границу проекта** (Minor 2 ревью задачи 1): слово с ним — путь команды (`za_shell::path_words`, как `~`). Пакет вызовов разрешает его по домашнему каталогу корней канонически (`policy::command_path`, и при решении, и при повторной проверке в слоте): в вопросе и в `boundary.outside` — настоящий путь, защищённое место узнаётся и через другой регистр и короткое имя 8.3. Граница такого слова — всегда «вне проекта», грант её не покрывает: раскрытие по корням — best effort, оболочка раскрывает начало по своей переменной. Команда с ним спрашивает (`outside_project`) в любом режиме, включая `bypass`, как с `~` (слово `pinned`; Minor 2 повторного ревью fix-1): например, `source $HOME/.cargo/env`, `export PATH=$HOME/bin:$PATH`. Одобрение такой команды, открытое до R1-M, после `--approve` и resume отвечает модели `path changed since planning; call again`: путь слова теперь `<home>/…` вне проекта, а не `<проект>/~/…` (Minor 1).
   - **Обход не заходит в защищённые места** (Important 1 ревью задачи 1). Пакет передаёт корни run инструменту (`ToolCx::roots`); обход `search` и `glob` пропускает каталоги, для которых `sealed_place`, даже если корень обхода выше них (проект — домашний каталог, грант на домашний каталог, шаблон `glob` с префиксом выше), а корень обхода в защищённом месте не обходится и не читается (`no matches`, `no files matched`; политика такой вызов отвергает раньше). Обход файлов проекта для чекпоинта — тот же: `GitCheckpointer::new(…, run_roots)` получает корни run, и корни чекпоинта — свой проект и `ZA_HOME` хранилища с домашним каталогом и защищёнными местами run (`Roots::with_sealed_of`); бинарник передаёт корни run, `checkpoints` строит те же (`home::with_user_home`). Восстановление защищённые места не пишет, не удаляет и не копирует в чекпоинт «до»: запись дерева старого чекпоинта (до R1-M или без домашнего каталога) в защищённом месте `restore_set` отбрасывает, поэтому её нет ни в наборе изменений, ни в копии «до»; копия файлов (`files::copy`, `files::paths`) сверяет те же корни (Minor 3 повторного ревью fix-1). `edit` и `multi_edit` сверяют защищённые места корней run и без политики (защита в глубину).
   - **По умолчанию закрыто** (Minor 5 повторного ревью fix-1): корни run обязательны — `ToolCx::roots: Arc<Roots>`, `search_in`/`glob_in` берут `&Roots`, `GitCheckpointer` — `Arc<Roots>`. Законного пути вызова без корней run нет (`None` давали только тесты; продакшн-литерал `ToolCx` один — пакет вызовов), поэтому код, который забыл корни run, не компилируется, а не возвращает обход в защищённые места молча. Тесты дают `Roots::boundary` или корни с домашним каталогом.
   - **Записанное одобрение шаг 1 не снимает** (Minor 3 ревью задачи 1): одобренный, но не начатый вызов (намерения нет) под встроенным запретом — защищённое место или `zam` — получает отказ, как без одобрения (`policy::builtin_deny`). Так одобрение, открытое до R1-M или в run без домашнего каталога, после `--approve` не исполняет `zam` и не читает `ZA_HOME`. Отказ — решение без следа: реплей того же журнала даёт тот же текст. Начатый вызов реплеится по квитанции; намерение `bash` без квитанции — неизвестный исход, решение человека, без повтора (`NonIdempotent`); у начатого чтения пути, который теперь защищён, классы путей в `tool.started` (`protected: false`) расходятся с текущими — вызов идёт на новое решение, и шаг 1 даёт отказ.
   - **`request_grant` на защищённое место** — `denied: protected path` без вопроса человеку: грант там ничего не дал бы (Minor 10 ревью задачи 1).
   - `<project>/.zeroaimemory/` (привязка к решению, D135) защищён только от нативной записи, как `.zero-agent/`: читать его можно, менять — только командой `memory init`.
   - Проект внутри защищённого места — отказ старта run (`RunError::SealedProject`): иначе любой вызов был бы отказом. Домашний каталог, который не канонизируется (сетевой путь, висячая ссылка), — тоже отказ старта, со своим текстом и путём домашнего каталога (`RunError::UserHome`, Minor 5 ревью задачи 1): защищённое место не построить, fail-closed.
   - Корни только для границы проекта (разрешение пути инструментом, набор доверия, инструкции, скиллы) — `Roots::boundary`: без `ZA_HOME` и защищённых мест, `protected` — только у служебных путей проекта, а не у каждого пути, как у прежних `Roots::canonical(d, d)` (Minor 6 ревью задачи 1).
   - Рантайм не затронут: свои файлы `ZA_HOME` (журнал, конфигурацию, чекпоинты, скиллы `ZA_HOME/skills` через `activate_skill`, D118) он читает своими путями, вне политики.
2. **Встроенный запрет `zam` (D158).** Вызов `bash`, у которого имя команды любого сегмента — `zam` по `za_shell::argv0` (без пути, `.exe`, `.cmd`, регистра, сквозь обёртки `env`, `sudo`, `timeout`, оператор `&`), — `denied: memory client` (`deny_reason::MEMORY_CLIENT`). Сегменты внутреннего кода (`sh -c`, `bash -c`, `pwsh -Command`, `cmd /c`, `eval`, `iex`) и тела подстановок `za_shell::segments` отдаёт отдельными сегментами, поэтому второго разборщика нет. В снимок политики и её хэш правило не входит: golden `policy_r1c1.hash` прежний. Текст отказа — образец `runtime/policy.denied_memory_client` в хэше промптов (`PROMPT_VERSION = "r1m.1"`, D155). Человек вызывает `zam` из своего терминала; агенту память доступна только через собственный клиент `za-memory` с токеном `ZA_MEMORY_TOKEN` и адресом из глобальной конфигурации.
3. **Чистое окружение детей (D159).** `za_jail::child_env` в режиме `Inherit` снимает по префиксу без учёта регистра на любой платформе `ZA_MEMORY_` и `ZAM_` (как `ZA_SECRET`): уходят `ZA_MEMORY_TOKEN`, `ZAM_TOKEN`, `ZAM_URL`, `ZAM_SESSION*`, `ZAM_MACHINE` и будущие переменные клиента; `ZAMBA_X` остаётся (префикс — с подчёркиванием). Тесты бинарника снимают те же префиксы у дочернего `zero-agent` одним помощником `tests/support/process.rs::strip_private_env` у всех запускателей (`Env::run_env`, `r0_acceptance`, `r1a_models`, `hooks_absent`): токен разработчика не уходит поддельному серверу.
4. **Шаблон маски (D160, часть шаблона).** В `RULES` маски (`za-secrets/src/scan.rs`) — токен ZeroAIMemory: префикс `zam_`, ровно 40 символов base62, правая граница слова, вид `zam_token`. Так маскируется и токен агента, и токен клиента `zam`, прочитанный в обход мер 1–2. Проверка случайности тела — `mixed_random`: два класса символов из трёх (цифры, строчные, прописные) и не меньше 10 разных символов. **Отступление от буквы D160** («проверка `random_looking`»): `random_looking` требует цифру, а 40 символов base62 из ОС-источника случайности не содержат цифры у ~0,09 % токенов (`(52/62)^40`) — такой токен не маскировался бы. `mixed_random` пропускает настоящий токен с вероятностью порядка 1e-15 и так же отвергает вырожденные тела (одна буква, один регистр, одни цифры). Известные значения процесса (значение `ZA_MEMORY_TOKEN`, раскрытые значения Vault) добавляет задача 5 (`MaskCell`): до неё токен читает только `doctor`, и в его выводе токена нет.
5. **Файл инструкций проекта — через маску процесса** (Important 2 ревью задачи 1). Клиент `zam` прежнего формата (блок v1) писал токен строкой `ZeroAIMemoryToken=<токен>` в `CLAUDE.md`, а текст `AGENTS.md`/`CLAUDE.md` доверенного проекта уходил в замороженный префикс — в системный промпт, в том числе облачной модели, и в префикс в хранилище. Теперь драйвер (`start_run`, шаг 0) после очистки невидимых символов пропускает текст через `LoopDeps.masker` — те же шаблоны (`zam_` и прочие) и известные значения, что у результатов инструментов, — до `fit_agents_md` и `freeze_for`. Агент читает как инструкции только `AGENTS.md`, без него — `CLAUDE.md` (`zero_agent::trust::INSTRUCTION_FILES`); `CLAUDE.local.md` он не читает. Если маска что-то заменила, в журнале — событие `input.masked {source: agents_md, masked: N}` (`za_protocol::EventKind::InputMasked`, число мест — `SecretMasker::mask_counted`), в stderr run — строка `zero-agent: в файле инструкций проекта замаскировано секретов: N …`; значений нет нигде.

**Остаточные риски** (SEC-002: граница shell — best effort; ОС-изоляции нет, N-15):

- **Косвенные пути в `bash` не ловятся:** путь из переменной (`$p/config.toml`), из подстановки (`$(echo ~)/…`), относительный после `cd` (`cd ~; cat .zeroaimemory/config.toml`), собранный программой (`python -c "open(…)"`), а также жёсткая ссылка внутри проекта на файл токена (чтение жёсткой ссылки разрешено, D98, записанный риск 7.12). Начало домашнего каталога раскрывается по корням, оболочка — по своей переменной (`HOME=/x; cat $HOME/…`): граница такого слова всё равно «вне проекта», в `auto` — вопрос.
- **Обход командой `bash` внутри проекта** (Minor 4 повторного ревью fix-1). Проект — домашний каталог пользователя или предок `ZA_HOME`: тогда `grep -r … .`, `find . -exec cat {} \;`, шаблон оболочки `cat .zeroaimemor?/config.toml` — пути внутри проекта, вопроса в `auto` нет. Нативные `search`, `glob` и чекпоинт защищённые места обходят, а лексическая сверка слов команды (`command_words`) обход оболочки и её шаблон не узнаёт; маска закрывает только тело `zam_` и известные значения (не `base64`). Мера — предупреждение: `run` (при старте и resume) и `doctor` (в каталоге запуска) печатают на каждое существующее защищённое место внутри проекта строку stderr «zero-agent: в проекте лежит защищённое место <путь>: команды bash внутри проекта его не узнают; лучше открыть проект в подкаталоге» (`home::sealed_in_project`), значений в ней нет.
- **Имя `zam` не ловится:** из переменной или подстановки (`$c search`), в непрозрачном внутреннем коде (`-EncodedCommand`, код из переменной), у переименованной копии бинарника, при сборке и запуске клиента из исходников (`cargo run -p zam-cli`).
- **Домашний каталог не задан** (`USERPROFILE`/`HOME` пусты) — `~/.zeroaimemory/` не защищён по пути (`warn` в журнале процесса); клиент `zam` тогда тоже не находит свой файл.
- **Маска знает только шаблон и известные значения:** токен в base64 или URL-кодировке не узнаётся (записанный риск D90).
- **Шаблон `zam_` — ровно 40 символов тела** (`min = max = 40`, Minor 8 ревью задачи 1): токен, разорванный переводом строки (`zam_Xq7L…` + `\n` + хвост), не маскируется ни одной частью — у каждой части тело короче 40; известное значение (`ZA_MEMORY_TOKEN`) маска знает и в разорванном виде (КМП по тексту без переводов строки). Обратная ошибка — лишняя маска: после совпадения продолжение `wrapped_tail` (`scan.rs`) может забрать следующую строку из букв и цифр как перенос тела. Ошибка в безопасную сторону, код не менялся.
- **Исполненный вызов** реплеится без шага 1: квитанция есть — результат берётся из неё (детерминизм D92), даже если вызов прочитал защищённое место до R1-M.
