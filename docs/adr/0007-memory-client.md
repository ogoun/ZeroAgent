# ADR 0007. Клиент памяти ZeroAIMemory: `za-memory`, каналы, Vault, токен и клиент `zam`

- Статус: принято (R1-M, 2026-11-17). Источник: решения плана D133–D168, `docs/plans/2026-11-16-r1m-memory.md`; ruling контроллера — `.superpowers/sdd/2026-11-16-r1m-memory/progress.md` и `preflight-rulings.md` (раздел «Безопасность»); решения владельца 2026-11-16 (Vault, окружение, идеи, тестовый стенд).
- Требования: часть 04 ТЗ (память), MEM-014, SEC-002 (граница shell — best effort), SEC-040, SEC-041 (секреты), раздел 9 (угрозы «враждебный репозиторий», «эксфильтрация»).

Разделы о крейте и транспорте (задача 2), Vault и ключах (задача 5), шлюзе записи (задача 6), outbox (задача 7), инструментах модели (задача 8) и снимке сессии (задача 9) дописывают эти задачи.

## Токен и клиент `zam`

**Контекст.** У агента свой токен памяти — переменная окружения `ZA_MEMORY_TOKEN` (D134); других источников нет. Но на машине пользователя есть и полный токен его клиента `zam`: файл `~/.zeroaimemory/config.toml` (`USERPROFILE` на Windows, `HOME` иначе). Клиент `zam` ищет адрес и токен независимо от агента: флаг → `ZAM_URL`/`ZAM_TOKEN` → `ZeroAIMemoryUrl`/`ZeroAIMemoryToken` в `CLAUDE.local.md`, `CLAUDE.md`, `AGENTS.md` вверх от текущего каталога → `~/.zeroaimemory/config.toml`. Враждебный репозиторий со строкой `ZeroAIMemoryUrl=http://evil` в `CLAUDE.md` и вызов `zam …` через `bash` отправили бы чужому серверу полный токен пользователя. Модель с инструментами чтения могла бы прочитать и сам файл токена, и `ZA_HOME/config.toml`.

**Решение.** Риск закрывается четырьмя мерами вместе (preflight 8.11); каждая — встроенная, ни проект, ни глобальная конфигурация, ни гранты, ни режим `bypass` её не снимают.

1. **Защищённые места (D157).** `ZA_HOME` и `~/.zeroaimemory/` — места, где нативный инструмент не делает ничего: `read`, `search`, `glob`, список, `edit`, `multi_edit` и `cwd` команды — `denied: protected path`. Это первый шаг решения политики (`decide`), до правил и режима.
   - Корни run (`za_core::paths::Roots`) получают домашний каталог и список `sealed`: `Roots::with_home(home)` канонизирует `home`, как `ZA_HOME`, и кладёт в `sealed` `<home>/.zeroaimemory`, а если это ссылка или junction — ещё и её каноническую цель. `za-core` окружение не читает: домашний каталог передаёт бинарник (`zero_agent::home::user_home`, как у клиента `zam`). Без домашнего каталога (`LoopDeps::new`, тесты) `sealed` пуст, `ZA_HOME` защищён всё равно.
   - `paths::sealed_place` сверяет канонический путь, на Windows без учёта регистра, поэтому защита действует через ссылку, junction, короткое имя 8.3 и другой регистр. `paths::resolve` ставит `protected` при любом доступе, политика (`call_of`) повторяет проверку.
   - Слова команды `bash` — все слова `argv`, цели перенаправлений и значения опций каждого сегмента, включая тела подстановок и строку вложенной интерпретации — разбираются лексически: начало `~`, `$HOME`, `${HOME}`, `%USERPROFILE%`, `$env:USERPROFILE`, `${env:USERPROFILE}`, `$env:HOME`, `${env:HOME}` раскрывается по домашнему каталогу корней, абсолютный путь берётся как есть. Слово внутри защищённого места — тот же отказ.
   - `<project>/.zeroaimemory/` (привязка к решению, D135) защищён только от нативной записи, как `.zero-agent/`: читать его можно, менять — только командой `memory init`.
   - Проект внутри защищённого места — отказ старта run (`RunError::SealedProject`): иначе любой вызов был бы отказом.
   - Рантайм не затронут: свои файлы `ZA_HOME` (журнал, конфигурацию, чекпоинты, скиллы `ZA_HOME/skills` через `activate_skill`, D118) он читает своими путями, вне политики.
2. **Встроенный запрет `zam` (D158).** Вызов `bash`, у которого имя команды любого сегмента — `zam` по `za_shell::argv0` (без пути, `.exe`, `.cmd`, регистра, сквозь обёртки `env`, `sudo`, `timeout`, оператор `&`), — `denied: memory client` (`deny_reason::MEMORY_CLIENT`). Сегменты внутреннего кода (`sh -c`, `bash -c`, `pwsh -Command`, `cmd /c`, `eval`, `iex`) и тела подстановок `za_shell::segments` отдаёт отдельными сегментами, поэтому второго разборщика нет. В снимок политики и её хэш правило не входит: golden `policy_r1c1.hash` прежний. Текст отказа — образец `runtime/policy.denied_memory_client` в хэше промптов (`PROMPT_VERSION = "r1m.1"`, D155). Человек вызывает `zam` из своего терминала; агенту память доступна только через собственный клиент `za-memory` с токеном `ZA_MEMORY_TOKEN` и адресом из глобальной конфигурации.
3. **Чистое окружение детей (D159).** `za_jail::child_env` в режиме `Inherit` снимает по префиксу без учёта регистра на любой платформе `ZA_MEMORY_` и `ZAM_` (как `ZA_SECRET`): уходят `ZA_MEMORY_TOKEN`, `ZAM_TOKEN`, `ZAM_URL`, `ZAM_SESSION*`, `ZAM_MACHINE` и будущие переменные клиента; `ZAMBA_X` остаётся (префикс — с подчёркиванием). Тесты бинарника снимают те же префиксы у дочернего `zero-agent` (`tests/support/process.rs`): токен разработчика не уходит поддельному серверу.
4. **Шаблон маски (D160, часть шаблона).** В `RULES` маски (`za-secrets/src/scan.rs`) — токен ZeroAIMemory: префикс `zam_`, ровно 40 символов base62, правая граница слова, вид `zam_token`. Так маскируется и токен агента, и токен клиента `zam`, прочитанный в обход мер 1–2. Проверка случайности тела — `mixed_random`: два класса символов из трёх (цифры, строчные, прописные) и не меньше 10 разных символов. **Отступление от буквы D160** («проверка `random_looking`»): `random_looking` требует цифру, а 40 символов base62 из ОС-источника случайности не содержат цифры у ~0,09 % токенов (`(52/62)^40`) — такой токен не маскировался бы. `mixed_random` пропускает настоящий токен с вероятностью порядка 1e-15 и так же отвергает вырожденные тела (одна буква, один регистр, одни цифры). Известные значения процесса (значение `ZA_MEMORY_TOKEN`, раскрытые значения Vault) добавляют задачи 2 и 5.

**Остаточные риски** (SEC-002: граница shell — best effort; ОС-изоляции нет, N-15):

- **Косвенные пути в `bash` не ловятся:** путь из переменной (`$p/config.toml`), из подстановки (`$(echo ~)/…`), относительный после `cd` (`cd ~; cat .zeroaimemory/config.toml`), собранный программой (`python -c "open(…)"`), а также жёсткая ссылка внутри проекта на файл токена (чтение жёсткой ссылки разрешено, D98, записанный риск 7.12).
- **Имя `zam` не ловится:** из переменной или подстановки (`$c search`), в непрозрачном внутреннем коде (`-EncodedCommand`, код из переменной), у переименованной копии бинарника, при сборке и запуске клиента из исходников (`cargo run -p zam-cli`).
- **Обход каталога с корнем выше защищённого места.** `search` и `glob` с корнем — предком `~/.zeroaimemory/` или `ZA_HOME` (проект — сам домашний каталог) заходят в него при обходе: политика видит только корень обхода, а инструменты обхода не знают защищённых мест (`ToolCx` их не несёт). Обход пропускает только `.git` и `.zero-agent`. Токен в найденных строках закрывает маска (мера 4), значение `ZA_HOME/config.toml` — нет. Кандидат на доработку: передать `sealed` инструментам обхода (`ToolCx`) и пропускать защищённые места в `filter_entry`.
- **Домашний каталог не задан** (`USERPROFILE`/`HOME` пусты) — `~/.zeroaimemory/` не защищён по пути (`warn` в журнале процесса); клиент `zam` тогда тоже не находит свой файл.
- **Маска знает только шаблон и известные значения:** токен в base64 или URL-кодировке не узнаётся (записанный риск D90).
