## Rule of Two без вопросов и отклонения от SEC-052, SEC-053

**Контекст.** SEC-052 (Rule of Two) требует, чтобы в одном run не сходились три свойства — недоверенное содержимое, приватные данные и внешняя связь, а третье добавлялось только через человека. SEC-053 требует подтверждения действий в tainted-контексте. R1-C1 (D82) уже снял причину `tainted`: чтение из сети не влияет на запуск команд.

**Решение заказчика 2026-11-11 — «Не спрашивать».** Сочетание приватных данных, недоверенного ввода и внешней связи прерывания не вызывает: вызов идёт по режиму. Экспозиция вычисляется и записывается: `LoopState.exposure` в снимке v4, событие `exposure.changed`, запись аудита `rule_of_two` на каждый вызов с внешней связью, исполняемый при всех трёх свойствах, строка CLI один раз на run. Вызов с внешней связью — это `risk = Network`, инструмент `web_*` и `bash`, классифицированный как сетевой или неопределённый (неразобранный сегмент, метка `unparsed`). Вызовы без внешней связи — `finish`, `ask_user`, `request_grant`, чтение и правка в проекте, `bash`, который разбор считает локальным, — записи не получают и при трёх свойствах (Ruling сомнения 1 прохода fix-5). Для `bash` это не гарантия: «локальная» команда вроде `python x.py` может сама передать данные наружу, а записи у неё нет. Run, где наружу выходит только `bash` без нативного сетевого вызова, трёх свойств не набирает: `bash` в свойства не входит (принятый риск ниже; Ruling I1 повторного ревью fix-5 и fix-6). Свойства вызова — это снимок начала пакета плюс вклад самого вызова. Сколько свойств добавил сам вызов, неважно: переход может быть и сразу на два. Формулировка плана «третье свойство при двух уже установленных» зависела от порядка вызовов: «чтение по гранту, затем сеть» записи не давало. Её заменил Ruling I1 ревью задачи 5. Причины `rule_of_two` в порядке причин одобрения нет. Буква SEC-052 «третье только через человека» и требование SEC-053 этим решением отменены (ссылки: `preflight-rulings.md`, `task-13-notes.md` п. 8 R1-C1, D82, D101, D106).

**Как считается.** Свойства независимы: `untrusted` — любое происхождение метки, кроме `outside_project`; `private` — исполненный нативный вызов с путём вне проекта (в том числе по гранту); `external` — исполненный нативный сетевой вызов. Все три берутся со снимка на начало пакета: аргументы вызовов одного пакета модель выбрала до их результатов, обмен данными внутри пакета невозможен, реплей детерминирован. `bash` и правки внутри проекта в свойства не входят.

**Принятые риски.** Эксфильтрация (командой `bash` или сочетанием нативных вызовов) не предотвращается; граница — режимы, гранты, доверие к проекту и правила по домену. Записывается она только у вызова с внешней связью. Граница shell — best effort (SEC-002): разбор команды узнаёт сетевые утилиты, но не программу, которая сама открывает соединение (`python x.py`, собранный бинарник, скрипт сборки). Такая команда считается локальной: записи `rule_of_two` у неё нет, а run, где наружу выходит только она, без нативного сетевого вызова, трёх свойств не набирает. Аудит позволяет найти такие run после факта. Пересмотр — вместе с ОС-изоляцией и прокси шлюза для `bash` (R2).

**Где в коде** (R1-C2, задача 5):

- тип `za_agent::Exposure` и `Exposure::untrusted_from` — `crates/za-agent/src/exposure.rs`; `decide`, `PolicyCx` (`crates/za-agent/src/policy.rs`) и `REASON_ORDER` (`tools.rs`) экспозиции не получают и не менялись;
- тип `Exposure`, `Exposure::all`, отметка `rule_of_two_marked` и `RuleOfTwoNotice` — модуль `crates/za-agent/src/exposure.rs` (ревью задачи 5, m8);
- флаги вызова — в квитанции эффекта (`private`, `external`; `untrusted` — по происхождениям квитанции): реплей квитанции даёт те же флаги без инструмента и без диска (D92). Флаги ставит только вызов, дошедший до инструмента: отказ разбора, гейта, политики или пользователя и вызов со сменой класса пути их не ставят. Ошибка самого инструмента флаги ставит (например, `web_fetch` с ответом `blocked: local or private address`): запрос, хотя бы DNS, мог уйти (m3 ревью задачи 5);
- снимок начала пакета — `ToolEnv.exposure` (`LoopState::exposure_now`); итог пакета — `ToolsOutcome.exposure`, `ToolsOutcome.rule_of_two` (вызовы пакета с записью аудита `rule_of_two`; признак — в квитанции, `Receipt.rule_of_two`), `ToolsOutcome.exposure_calls` (вызовы, поставившие флаг, которого в снимке не было);
- запись аудита `audit_action::RULE_OF_TWO` (`{call_id, tool, exposure, effect_key}`, объект — run) пишет слот вызова при живом исполнении, как запись гранта (SEC-090), — до вызова, вместе с `tool.started` (Ruling m2 ревью задачи 5). Свойства до вызова: `private` и `external` — по путям решения и спецификации, `untrusted` — по происхождениям без метки самого результата (`ToolJob::exposure_before`). Поэтому отмена посреди вызова запись не теряет, а реплей квитанции после паузы её не повторяет. Повтор замыкания после сбоя процесса (намерение без квитанции) защищён ключом эффекта: `ProjectStore::append_audit_once` пишет одну запись на `effect_key`. Отметка `"rule_of_two": true` ставится в `tool.started`. Если третье свойство дала только метка результата, запись пишется после вызова, а отметка ставится в `tool.finished`. Условие внешней связи — `ToolJob::external_link` (`crates/za-agent/src/tools.rs`); свойства экспозиции оно не меняет: `bash` в них по-прежнему не входит;
- сбой записи аудита обрабатывается как аудит гранта (D72, D91), без молчаливой потери (Ruling m1). До вызова: вызов не исполняется, квитанция — отказ `internal error: journal write failed`, run встаёт на паузу `store`. После вызова: результат не выдаётся (недоверенного содержимого в контексте нет, свойств два), флаги `private` и `external` остаются;
- событие `exposure.changed {untrusted, private, external, calls, rule_of_two}` пишет драйвер после пакета, если флаги run изменились. После пакета, остановленного на прерывании, его нет: шаг доигрывается при resume и пишет событие один раз. Затем `st.exposure` — объединение со снимком; снимает флаги только новый run. Вызовы при трёх свойствах в следующих пакетах флагов не меняют: их видно по аудиту и отметке в `tool.started`;
- строка CLI «в этом запуске сошлись недоверенное содержимое, ваши файлы вне проекта и обращение в сеть (SEC-052); вызов выполнен, запись в аудите» — `crates/zero-agent/src/run.rs`. Она печатается один раз на run, по первой отметке `rule_of_two` (`RuleOfTwoNotice`), и модели не уходит. Resume run, у которого запись `rule_of_two` уже есть, строку не повторяет. Если событие потеряно при отставании шины, строку даёт проверка аудита в конце процесса (m4);
- снимок v4 (D130): `Snapshot.exposure`, `Snapshot.skills` (оба `#[serde(default)]`, `skills` пуст до задачи 13); снимки v1–v3 читаются, фикстура v3 — `crates/za-agent/tests/golden/r1c1_v3.json`;
- тесты: `crates/za-agent/tests/policy.rs` (`rule_of_two_never_asks`, `tainted_never_asks_still_holds`, `untrusted_ignores_outside_project_origin`), `crates/za-agent/tests/tools_native.rs` (`exposure_*`, `third_property_*`, `only_external_link_calls_recorded_under_three_properties`, `grant_read_then_two_fetches_two_records_one_line`, `rule_of_two_survives_cancel_mid_call`, `rule_of_two_audit_failure_blocks_call`, `rule_of_two_not_duplicated_on_retry_after_crash`), `crates/za-agent/tests/resume.rs` (`snapshot_v3_reads_with_default_exposure`, `snapshot_v3_untrusted_label_resumes_untrusted`; `broken_snapshot_fails_other_version_does_not` — `{"v": 5}` не читается), `crates/za-store/tests/conformance.rs` (`audit_once_per_effect_key`), модульные `exposure::tests`, `tools::tests::reason_order_has_no_rule_of_two`, `tools::tests::external_link_cases`, `run::tests::rule_of_two_line_once_per_run`.

## Сетевой шлюз

**Контекст.** SEC-047 требует один компонент сетевого чтения: только чтение, без учётных данных и cookie пользователя, запрет локальных адресов, лимит размера и частоты, журнал. Обход фильтра «нашли — закрыли» (литералы `0x7f.1`, `2130706433`, NAT64, 6to4, DNS rebinding, редирект на `127.0.0.1`, `localhost.`) закрывается архитектурой, а не списком исключений (D107, D108, D124).

**Решение.** Крейт `za-web` (задача 6), объект `WebGateway` — один на процесс, его держат оба веб-инструмента.

- **Разрешающий список (D108).** `check_ip` пропускает только глобально маршрутизируемые адреса: IPv4 вне всех строк реестра IANA IPv4 Special-Purpose (целиком, в том числе строки с «Globally Reachable = True», например `192.88.99.0/24`, `192.31.196.0/24`) и вне `224.0.0.0/4`; IPv6 — только `2000::/3` вне всех строк реестра IANA IPv6 Special-Purpose (целиком весь `2001::/23`, `2620:4f:8000::/48`, `3fff::/20`, `5f00::/16`). Всё прочее — отказ `local or private address`: новый блок реестра правки кода не требует. Вложенный IPv4 проверяется правилом IPv4 только там, где его положение однозначно и трансляция стандартна: `::ffff:0:0/96`, `64:ff9b::/96`, `2002::/16`. Локальный NAT64 `64:ff9b:1::/48` (RFC 8215) отвергается целиком, в любой форме, в том числе `/96`: длину префикса и саму трансляцию выбирает оператор сети, и вердикт по вложенному адресу был бы догадкой (Ruling I1 ревью задачи 6). IPv4-compatible `::/96` (устарел по RFC 4291, 2.5.5.1, глобально не маршрутизируется) тоже отвергается целиком (M6 ревью задачи 6, строже буквы D108). Таблицы — константы `crates/za-web/src/addr.rs`, снимок реестров от 2025-10-09 (сверено 2026-11-16); тест сверяет их со своей копией реестров и проверяет первый и последний адрес каждой строки.
- **Где проверяется.** В резолвере клиента (`FilteredResolver`, трейт `reqwest::dns::Resolve`) поверх системного: соединение идёт только по адресам, которые фильтр пропустил, поэтому проверка и подключение не разделены во времени. Хоть один запрещённый адрес в ответе — отказ всего имени (признак rebinding). IP-литерал резолвер не видит — его проверяет `parse_url` сразу. Хост нормализует только `za_core::net::normalize_host` (D124), после неё — лексический запрет `localhost` и `*.localhost`; запрос уходит на нормализованный хост.
- **Предел портов.** Только порты `[web] ports` (по умолчанию `80, 443, 8080, 8443`), иначе `blocked: port <n> is not allowed` до соединения: GET к SMTP, Redis и подобным сервисам на публичном адресе (межпротокольная атака) невозможен.
- **Клиент.** `no_proxy()` (переменные `HTTP_PROXY` и прокси системы разрешали бы имена мимо фильтра), без cookie, без `Accept-Encoding` (ответ с `Content-Encoding` не `identity` — ошибка без распаковки), `User-Agent: zero-agent/<версия>`, `connect_timeout`, TLS — rustls с webpki-roots.
- **Редиректы** исполняет сам шлюз (`Policy::none` у клиента): каждый переход — своя запись журнала, проверка URL и порта, `robots.txt` и место в лимитере. До пяти переходов на тот же нормализованный хост (`http` → `https` можно, обратно — нет); иначе вызов возвращает `redirected to <url>; …`, и следующий вызов модели снова проходит политику и правила по домену.
- **Лимиты и дедлайн.** Тело до `max_bytes` (5 МиБ), скользящее окно `requests_per_minute` (60) на процесс и не чаще запроса в 500 мс к хосту; запросы к одному хосту идут по одному (замок хоста: `robots.txt` запрашивается один раз). Дедлайн вызова соблюдается на каждом шаге: шлюз сам возвращает `Timeout` вместе с журналом обращений, включая прерванный запрос (`reason = "timeout"`).
- **`robots.txt`** — свой разбор RFC 9309: группа `zero-agent`, иначе `*`; самое длинное совпадение, при равенстве `Allow`; 4xx — всё разрешено, 5xx и сбой — всё запрещено; кэш на источник 24 часа. Редирект `robots.txt` на тот же хост исполняется (до пяти, `http` → `https` тоже), на другой хост — не исполняется и считается 4xx (RFC 9309, 2.3.1.2 «недоступен»), соединения с чужим хостом нет; цель, которую отверг фильтр (порт, userinfo), — запись `blocked` и тоже «недоступен»; 3xx без `Location` — как 5xx.
- **Пределы разбора `robots.txt`** (M4 ревью задачи 6). Текст — до 500 КиБ (RFC 9309, 2.5; столько же читают Google, Bing и Яндекс), дальше не разбирается, обрезка по последней целой строке. Правил группы агента — до 2000 (`ROBOTS_MAX_RULES`), дальше не действуют. Сопоставление жадное по буквальным частям между `*` с линейным поиском подстроки: O(путь + шаблон) на правило вместо прежней динамики O(шаблон × путь). Шлюз разбирает текст один раз на источник и держит в кэше разобранные правила. Худший случай у пределов текста и длины URL (замер в release): разбор около 1 мс один раз на источник, сопоставление до 3,6 мс на запрос; прежде — около 0,5 с на каждый запрос.
- **Журнал.** На каждый HTTP-запрос вызова, отказ фильтра, отказ `robots.txt` и прерванный дедлайном запрос — запись `za_core::NetRequest` (D112). Userinfo и фрагмент в журнал и модели не попадают: ни из URL вызова, ни из `Location` (`final_url`, текст `redirected to <url>`; M2 ревью задачи 6). Строка отладочного лога (`ZA_LOG=debug`) несёт только хост и исход: строку запроса с секретом маскирует только запись журнала (M5).

**Второй держатель HTTP-клиента.** `za-web` — второй после `za-llm` крейт с `reqwest` (те же функции `json`, `rustls-tls`). `za-llm` приходит в `za-web` только транзитивно через `za-core` без функций: клиент шлюза — свой. `cargo xtask policy` проверяет: `za-web` зависит только от `za-protocol` и `za-core`, от `za-web` — только `zero-agent` и `xtask`; прямая зависимость от `reqwest` любого вида (обычная, dev, build) — только у `za-llm` и `za-web` (Ruling I2 ревью задачи 6: иначе второй клиент строится и без `Client::builder` в исходнике, например `Client::default()`); внутри них `reqwest::Client::builder`, `ClientBuilder`, `Client::new`, `Client::default`, упоминание типа `reqwest::Client`, `reqwest::get` и `reqwest::blocking` — только в `crates/za-web/src/gateway.rs` и `crates/za-llm`; у `reqwest` в сборке workspace вместе с тестами нет функций `gzip`, `brotli`, `deflate`, `zstd`, `cookies`, `socks`, `http2`, `http3`, корней ОС и системного TLS (D129).

**Тестовые подмены** (`with_test_resolve`, `with_inner_resolver`) существуют только с признаком сборки `test-hooks` (D128), не под `debug_assertions`: отладочная и release-сборка обхода фильтра не содержат. Тесты с ними — `crates/za-web/tests/gateway.rs` (`required-features`), в CI — отдельный шаг `cargo test -p za-web --features test-hooks`.

**Принятые риски.**

- **Hairpin NAT.** Публичный адрес, который ведёт обратно в сеть пользователя (внешний IP своего роутера с hairpin NAT, публичный адрес собственного сервера), фильтр не отличает от прочих публичных адресов. Предел портов снимает межпротокольные атаки, но HTTP-сервис на разрешённом порту такого адреса достижим.
- **Порты 8080 и 8443** открыты и на публичных адресах внутренних служб, выставленных наружу.
- **NAT64 с общеизвестным префиксом** `64:ff9b::/96` пропускает публичный IPv4 по вердикту вложенного адреса: трансляцию делает сеть пользователя. Локальный NAT64 `64:ff9b:1::/48` риском не является — он отвергается целиком.
- **Пределы `robots.txt`.** Правила дальше 500 КиБ текста или 2000-го правила группы не действуют: для такого сайта шлюз разрешает больше, чем хотел владелец.
- **Прокси для `bash`** нет: команды оболочки ходят в сеть мимо шлюза (D104, R2).

## Извлекатель

**Контекст.** Разборщики HTML и PDF получают враждебные данные, и в процессе агента у них три вида отказа, которые изнутри не перехватываются:

- **Переполнение стека.** `htmd` 0.5.6 обходит DOM рекурсивно. Около 2 МиБ вложенных `<span>` (≈ 350 000 уровней) переполняют стек потока, это проверено тестом `deep_nesting_kills_only_child`. Переполнение стека в Rust не паника: `catch_unwind` его не ловит, процесс завершается целиком.
- **Квадратичное время.** Проверка «элемент в области видимости» у `html5ever` при вложенных `<div>` растёт с глубиной: в release 64 КиБ разбираются за 0,43 с, 256 КиБ — за 9 с, 2 МиБ — минуты. Слияние соседних одинаковых строчных элементов у `htmd` (`Vec::remove` в цикле): 1 МиБ `<b>x</b>` — 1,5 с. Замер — журнал, 2026-11-16, задача 7.
- **Паники и вечные циклы** у разборщика PDF на битых данных (D113).

Поток зависшего разбора нельзя убить извне, а предварительный счёт глубины — новая эвристика с гонкой «нашли — закрыли».

**Решение (D113, D127).** Все разборщики враждебного содержимого собраны в крейте `za-extract`. Его функции вызываются только в подпроцессе `zero-agent extract <html|pdf>` через `za_jail::Runner`: `EnvMode::Clear`, `tmp_dir` — `work_dir("tmp")/<run>`, тайм-аут и предел вывода. Падение, переполнение стека и зависание убивают только подпроцесс, инструмент получает ошибку (`is_error`), процесс агента продолжает работу.

- **HTML** (задачи 7, 10): UTF-8 до 2 МиБ на stdin, в stdout — JSON `Markdown {title, text}` той же формы, что `za_core::extract::Markdown`; тайм-аут 10 с, вывод до 4 МиБ; сбой — `html: extractor failed: <причина>`.
- **PDF** (задача 10): `extract pdf <path> <first> <count> <max_chars>`, тайм-аут 30 с, вывод до 16 МиБ.
- **Направления** (`cargo xtask policy`): `za-extract` не зависит от крейтов workspace ни в каком виде, от него зависит только `zero-agent`. Прямая зависимость от `htmd`, `html5ever`, `markup5ever_rcdom` есть только у `za-extract`. `za-web` HTML не разбирает: он определяет тип и кодировку и передаёт HTML извлекателю (трейт `Extractor`, задача 8).
- **Тип и кодировка** (`za_web::convert`, D109) определяются строго:
  - тип — по `Content-Type`; без заголовка — по сигнатуре в начале тела после BOM и пробелов (`%PDF-`, `<!doctype html`, `<html` целым именем тега), иначе `text/plain`;
  - кодировка — BOM, затем `charset` заголовка, затем `<meta>` (только у HTML, в первых 1024 байтах, без закомментированных), иначе UTF-8; декодирование с заменой;
  - `Content-Encoding`, отличный от `identity`, — ошибка без распаковки. Правило имени кодирования у шлюза и `convert` общее.
- **Преобразование** (`za_extract::html_to_markdown`, D109):
  - вход длиннее 2 МиБ обрезается по границе символа до разбора;
  - в текст не попадают `head`, `title`, `script`, `style`, `noscript`, `template`, `svg`, `canvas`, `iframe`, `object`, `embed`, `form`;
  - заголовок — текст первого `<title>` пространства имён HTML в порядке документа, пробелы схлопнуты, без экранирования Markdown; `<title>` внутри SVG заголовком не считается;
  - картинки с адресом `data:` отбрасывает обработчик элемента `img`, а не замена по тексту;
  - серии пустых строк сжимаются в одну;
  - собственный обход дерева (поиск `<title>`) — без рекурсии.

**Цена.** Запуск процесса — около 20–50 мс на страницу, для `web_fetch` несущественно.

**Принятые риски.**

- **Память подпроцесса не ограничена**: бомба декомпрессии в PDF или огромное дерево DOM может занять RAM машины. Предел — Job Object с `JOB_OBJECT_LIMIT_PROCESS_MEMORY` и `RLIMIT_AS` через `za-jail`, R2.
- **Квадратичная разметка** (глубокие `<div>`, длинные серии одинаковых строчных элементов) доводит разбор до тайм-аута 10 с. Такая страница агенту недоступна: он получает ошибку извлекателя, а не текст.
- **Двоичные данные под `text/html` или текстовым типом** декодируются с заменой: тип берётся из заголовка без угадывания (D109). Ответ «нет читаемого текста» даёт `web_fetch` (D110, задача 8).
