## Rule of Two без вопросов и отклонения от SEC-052, SEC-053

**Контекст.** SEC-052 (Rule of Two) требует, чтобы в одном run не сходились три свойства — недоверенное содержимое, приватные данные и внешняя связь, а третье добавлялось только через человека. SEC-053 требует подтверждения действий в tainted-контексте. R1-C1 (D82) уже снял причину `tainted`: чтение из сети не влияет на запуск команд.

**Решение заказчика 2026-11-11 — «Не спрашивать».** Сочетание приватных данных, недоверенного ввода и внешней связи прерывания не вызывает: вызов идёт по режиму. Экспозиция вычисляется и записывается: `LoopState.exposure` в снимке v4, событие `exposure.changed`, запись аудита `rule_of_two` на каждый вызов, который поставил третье свойство при двух уже установленных, строка CLI один раз на run. Причины `rule_of_two` в порядке причин одобрения нет. Буква SEC-052 «третье только через человека» и требование SEC-053 этим решением отменены (ссылки: `preflight-rulings.md`, `task-13-notes.md` п. 8 R1-C1, D82, D101, D106).

**Как считается.** Свойства независимы: `untrusted` — любое происхождение метки, кроме `outside_project`; `private` — исполненный нативный вызов с путём вне проекта (в том числе по гранту); `external` — исполненный нативный сетевой вызов. Все три берутся со снимка на начало пакета: аргументы вызовов одного пакета модель выбрала до их результатов, обмен данными внутри пакета невозможен, реплей детерминирован. `bash` и правки внутри проекта в свойства не входят.

**Принятые риски.** Эксфильтрация (командой `bash` или сочетанием нативных вызовов) не предотвращается, а только записывается; граница — режимы, гранты, доверие к проекту и правила по домену. Аудит позволяет найти такие run после факта. Пересмотр — вместе с ОС-изоляцией и прокси шлюза для `bash` (R2).

**Где в коде** (R1-C2, задача 5):

- тип `za_agent::Exposure` и `Exposure::untrusted_from` — `crates/za-agent/src/tools.rs`; `decide`, `PolicyCx` (`crates/za-agent/src/policy.rs`) и `REASON_ORDER` (`tools.rs`) экспозиции не получают и не менялись;
- флаги вызова — в квитанции эффекта (`private`, `external`; `untrusted` — по происхождениям квитанции): реплей квитанции даёт те же флаги без инструмента и без диска (D92). Флаги ставит только исполненный вызов: отказ разбора, гейта, политики или пользователя и вызов, не дошедший до инструмента (смена класса пути), их не ставят;
- снимок начала пакета — `ToolEnv.exposure` (`LoopState::exposure_now`); итог пакета — `ToolsOutcome.exposure`, `ToolsOutcome.rule_of_two` (вызовы, поставившие третье свойство при двух в снимке начала пакета), `ToolsOutcome.exposure_calls` (вызовы, поставившие флаг, которого в снимке не было);
- запись аудита `audit_action::RULE_OF_TWO` (`{call_id, tool, exposure}`, объект — run) пишет слот вызова при живом исполнении, как запись гранта (SEC-090): при реплее квитанции после паузы одобрения она не повторяется, а вызов, исполненный до паузы, записан, даже если run потом отменён. Сбой записи аудита — ошибка журнала: run встаёт на паузу `store`;
- событие `exposure.changed {untrusted, private, external, calls, rule_of_two}` пишет драйвер после пакета, если флаги run изменились; после пакета, остановленного на прерывании, — нет: шаг доигрывается при resume и пишет событие один раз. Затем `st.exposure` — объединение со снимком; снимает флаги только новый run;
- строка CLI «в этом запуске сошлись недоверенное содержимое, ваши файлы вне проекта и обращение в сеть (SEC-052); вызов выполнен, запись в аудите» — `crates/zero-agent/src/run.rs`, один раз на процесс `run` по первому событию `exposure.changed` с непустым `rule_of_two`; модели не уходит;
- снимок v4 (D130): `Snapshot.exposure`, `Snapshot.skills` (оба `#[serde(default)]`, `skills` пуст до задачи 13); снимки v1–v3 читаются, фикстура v3 — `crates/za-agent/tests/golden/r1c1_v3.json`;
- тесты: `crates/za-agent/tests/policy.rs` (`rule_of_two_never_asks`, `tainted_never_asks_still_holds`, `untrusted_ignores_outside_project_origin`), `crates/za-agent/tests/tools_native.rs` (`exposure_*`, `third_property_*`), `crates/za-agent/tests/resume.rs` (`snapshot_v3_reads_with_default_exposure`; `broken_snapshot_fails_other_version_does_not` — `{"v": 5}` не читается).

## Сетевой шлюз

**Контекст.** SEC-047 требует один компонент сетевого чтения: только чтение, без учётных данных и cookie пользователя, запрет локальных адресов, лимит размера и частоты, журнал. Обход фильтра «нашли — закрыли» (литералы `0x7f.1`, `2130706433`, NAT64, 6to4, DNS rebinding, редирект на `127.0.0.1`, `localhost.`) закрывается архитектурой, а не списком исключений (D107, D108, D124).

**Решение.** Крейт `za-web` (задача 6), объект `WebGateway` — один на процесс, его держат оба веб-инструмента.

- **Разрешающий список (D108).** `check_ip` пропускает только глобально маршрутизируемые адреса: IPv4 вне всех строк реестра IANA IPv4 Special-Purpose (целиком, в том числе строки с «Globally Reachable = True», например `192.88.99.0/24`, `192.31.196.0/24`) и вне `224.0.0.0/4`; IPv6 — только `2000::/3` вне всех строк реестра IANA IPv6 Special-Purpose (целиком весь `2001::/23`, `2620:4f:8000::/48`, `3fff::/20`, `5f00::/16`). Всё прочее — отказ `local or private address`: новый блок реестра правки кода не требует. Вложенный IPv4 проверяется правилом IPv4: `::ffff:0:0/96`, `::/96`, `64:ff9b::/96`, `2002::/16`, а `64:ff9b:1::/48` — только в форме `/96` (биты 48–95 нулевые; иначе положение IPv4 зависит от длины префикса оператора по RFC 6052, и адрес — отказ). Таблицы — константы `crates/za-web/src/addr.rs`, снимок реестров от 2025-10-09 (сверено 2026-11-16); тест сверяет их со своей копией реестров и проверяет первый и последний адрес каждой строки.
- **Где проверяется.** В резолвере клиента (`FilteredResolver`, трейт `reqwest::dns::Resolve`) поверх системного: соединение идёт только по адресам, которые фильтр пропустил, поэтому проверка и подключение не разделены во времени. Хоть один запрещённый адрес в ответе — отказ всего имени (признак rebinding). IP-литерал резолвер не видит — его проверяет `parse_url` сразу. Хост нормализует только `za_core::net::normalize_host` (D124), после неё — лексический запрет `localhost` и `*.localhost`; запрос уходит на нормализованный хост.
- **Предел портов.** Только порты `[web] ports` (по умолчанию `80, 443, 8080, 8443`), иначе `blocked: port <n> is not allowed` до соединения: GET к SMTP, Redis и подобным сервисам на публичном адресе (межпротокольная атака) невозможен.
- **Клиент.** `no_proxy()` (переменные `HTTP_PROXY` и прокси системы разрешали бы имена мимо фильтра), без cookie, без `Accept-Encoding` (ответ с `Content-Encoding` не `identity` — ошибка без распаковки), `User-Agent: zero-agent/<версия>`, `connect_timeout`, TLS — rustls с webpki-roots.
- **Редиректы** исполняет сам шлюз (`Policy::none` у клиента): каждый переход — своя запись журнала, проверка URL и порта, `robots.txt` и место в лимитере. До пяти переходов на тот же нормализованный хост (`http` → `https` можно, обратно — нет); иначе вызов возвращает `redirected to <url>; …`, и следующий вызов модели снова проходит политику и правила по домену.
- **Лимиты и дедлайн.** Тело до `max_bytes` (5 МиБ), скользящее окно `requests_per_minute` (60) на процесс и не чаще запроса в 500 мс к хосту; запросы к одному хосту идут по одному (замок хоста: `robots.txt` запрашивается один раз). Дедлайн вызова соблюдается на каждом шаге: шлюз сам возвращает `Timeout` вместе с журналом обращений, включая прерванный запрос (`reason = "timeout"`).
- **`robots.txt`** — свой разбор RFC 9309: группа `zero-agent`, иначе `*`; самое длинное совпадение, при равенстве `Allow`; 4xx — всё разрешено, 5xx и сбой — всё запрещено; предел 500 КиБ, кэш на источник 24 часа. Редирект `robots.txt` на тот же хост исполняется (до пяти), на другой хост — как 4xx (RFC 9309, 2.3.1.2 «недоступен»).
- **Журнал.** На каждый HTTP-запрос вызова, отказ фильтра, отказ `robots.txt` и прерванный дедлайном запрос — запись `za_core::NetRequest` (D112); userinfo в журнал не попадает.

**Второй держатель HTTP-клиента.** `za-web` — второй после `za-llm` крейт с `reqwest` (те же функции `json`, `rustls-tls`). `za-llm` приходит в `za-web` только транзитивно через `za-core` без функций: клиент шлюза — свой. `cargo xtask policy` проверяет: `za-web` зависит только от `za-protocol` и `za-core`, от `za-web` — только `zero-agent` и `xtask`; `reqwest::Client::builder`, `ClientBuilder`, `Client::new`, `reqwest::get` и `reqwest::blocking` — только в `crates/za-web/src/gateway.rs` и `crates/za-llm`; у `reqwest` в сборке workspace вместе с тестами нет функций `gzip`, `brotli`, `deflate`, `zstd`, `cookies`, `socks`, `http2`, `http3`, корней ОС и системного TLS (D129).

**Тестовые подмены** (`with_test_resolve`, `with_inner_resolver`) существуют только с признаком сборки `test-hooks` (D128), не под `debug_assertions`: отладочная и release-сборка обхода фильтра не содержат. Тесты с ними — `crates/za-web/tests/gateway.rs` (`required-features`), в CI — отдельный шаг `cargo test -p za-web --features test-hooks`.

**Принятые риски.**

- **Hairpin NAT.** Публичный адрес, который ведёт обратно в сеть пользователя (внешний IP своего роутера с hairpin NAT, публичный адрес собственного сервера), фильтр не отличает от прочих публичных адресов. Предел портов снимает межпротокольные атаки, но HTTP-сервис на разрешённом порту такого адреса достижим.
- **Порты 8080 и 8443** открыты и на публичных адресах внутренних служб, выставленных наружу.
- **Локальный NAT64** в форме `/96` пропускает публичный IPv4 по вердикту вложенного адреса; трансляция — забота сети пользователя.
- **Прокси для `bash`** нет: команды оболочки ходят в сеть мимо шлюза (D104, R2).
