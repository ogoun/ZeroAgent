# ТЗ zero-agent. Часть 09. Арена бенчмарков

Цель: самый быстрый цикл исследований «попробовать, сравнить, оставить». Арена — не новый харнесс, а слой статистики и реестра поверх Harbor. Числа времени и бюджетов — цели проектирования: на нашей связке ничего не запускалось.

## 1. Архитектура

```text
arena try <ветка>
   │ ключ эксперимента, выбор набора
   ▼
za-arena ──► Harbor (WSL2, Docker) ──► контейнер задачи
   │              │                     └─ zero-agent (musl) пишет trajectory.json (ATIF v1.8)
   │              ├─► Inspect AI (мост) AgentDojo, Safety
   │              └─► свои адаптеры (MCPMark, WebArena-Verified…)
   ▼
Инференс-прокси с записью ─► llama-server на хосте
   ▼
Реестр прогонов (SQLite) ─► статистика ─► вердикт, CI, таблица, UI
```

**Добавлено к списку заказчика:** память (LoCoMo, LongMemEval, MemoryArena, MERIT, VibeMemBench, MemDev-Bench, SWE-ContextBench), SkillsBench, поиск (BrowseComp со свежими аналогами, WideSearch), экономические задачи (GDPval, TheAgentCompany, Vending-Bench 2), CooperBench для роя, Harbor-Index как готовая панель.

| ARN-025 | Остановка: SPRT по образцу Fishtest или anytime-valid CI; подглядывание за p-value запрещено. Вердикт: принять, отклонить, «не решено» | P1 |
| ARN-026 | Гейт регрессий: non-inferiority, нижняя граница CI разности ≥ −m. Первичная метрика одна, остальные с поправкой Холма | P1 |
| ARN-027 | `reward_valid=false` исключается, доля гейтится отдельно, не считается нулём | P1 |
| ARN-028 | Метрики цены: токены вход, выход, кэш; GPU-секунды, энергия, wall-clock, TTFT, доля времени в инструментах и выводе, шаги, компакции, стоимость на успех, цена судьи, эквивалент по прейскуранту | P1 |
| ARN-029 | Надёжность как отдельная ось: согласованность, предсказуемость, устойчивость | P2 |
| ARN-030 | Таксономия сбоев в три слоя: инфраструктура (Harbor), поведение (первая критическая ошибка), целостность (чтение оценщика, подделка, сеть). Третий слой всегда делает результат недействительным | P1 |
| ARN-031 | Лидерборд: строка — полный ключ; сравнения только с одинаковым ключом; CI, k, Парето точность–цена; единого рейтинга нет | P1 |

**Оценка мощности.** Для парного бинарного исхода с долей расхождений d: n ≈ 7,84·(d−Δ²)/Δ² задач при α=0,05 и мощности 0,8 (расчёт R06, d — допущение).

| Δ | d=0,1 | d=0,2 |
|---|---|---|
| 20 п.п. | 12 | 31 |
| 10 п.п. | 71 | 149 |
| 5 п.п. | 306 | 619 |

Вывод: smoke-набор ловит поломки, а улучшения на 3–5 п.п. видны только на токенах, шагах и плотной награде. Эффект харнесса в 5,2 раза меньше эффекта модели (Harbor-Index), хотя на слабых моделях до 18 п.п.
