# ТЗ zero-agent. Часть 05. Безопасность

**Решение заказчика (N-15).** ОС-изоляция на первых этапах не делается. Граница проекта задаётся правилом системного промпта: жёсткий механизм мешал бы обращаться к нужным данным снаружи. К вопросу возвращаемся после проверки проекта (SEC-100).

**Принятый риск.** Правило в промпте — не барьер. Исследование показывает: инъекции адаптивны (~5–6 % успеха после 100 адаптивных попыток), только 4,4 % правил безопасности в инструкциях подкреплены контролем, а на локальных моделях соблюдение правил слабее (R07). Модель, ошибившись или выполнив инъекцию со страницы, может прочитать и изменить любой файл, доступный пользователю, и запустить любую команду. Вместе с общим токеном relay это распространяется на все машины сети. Остальные меры этой части ограничивают и делают видимым ущерб, но не исключают его.

## 1. Инварианты рантайма

Обязательны независимо от модели, режима и конфигурации проекта.

| # | Инвариант |
|---|---|
| 1 | Каждое действие записано в журнал до выполнения. Обращения за пределы проекта отмечаются и видны в UI |
| 2 | Секреты не попадают в контекст модели, журнал и spill |
| 3 | До доверия к проекту не разбирается ни один проектный конфиг: MCP, хуки, скиллы, `AGENTS.md`, `.zero-agent/` |
| 4 | Жёсткие бюджеты: деньги, токены, GPU, число задач, глубина, время; kill switch всего дерева |
| 5 | Метки происхождения в контексте |
| 6 | Журнал только на дополнение, необратимые действия только с подтверждением |
| 7 | Скиллы и плагины фиксируются по хэшу содержимого, без автоисполнения инструкций установки |
| 8 | Локальный сервер: проверка `Origin` и `Host`, аутентификация на loopback, никаких панелей наружу |
| 9 | Сводки компакции, отчёты субагентов и данные пиров считаются недоверенным вводом; одобрение не передаётся |
| 10 | Перед пишущим действием автоматический чекпоинт |

## 2. Граница проекта

| ID | Требование | Приор. |
|---|---|---|
| SEC-001 | Создавать и менять файлы агент может только внутри каталога проекта. Читать и писать снаружи — только по явному разрешению пользователя. Обычная работа тулчейнов при сборке и запуске нарушением не считается. Правило стоит в системном промпте (приложение A), рантайм границу не обеспечивает | P0 |
| SEC-002 | Обращения нативных инструментов за пределы проекта и пути в командах shell (по разбору, best effort) отмечаются в журнале и показываются в UI. Они не блокируются | P0 |
| SEC-003 | Разрешения пользователя на доступ наружу записываются в журнал и передаются модели блоком `<grants>` | P0 |
| SEC-004 | Рабочие и временные файлы только в `.zero-agent/work/` (ARC-021) | P0 |
| SEC-005 | Нативные инструменты не пишут в `ZA_HOME`, журнал и политики. Shell это не ограничивает | P0 |
| SEC-006 | Запуск дочерних процессов идёт через трейт `Runner` (`za-jail`) с единственной реализацией без изоляции. Это точка расширения для SEC-100 | P0 |
| SEC-011 | Ресурсные лимиты дерева процессов: время, число процессов. Job Object, группа процессов (OPS-013) | P1 |

**SEC-100 (P3). Отложенное усиление, после проверки проекта.** Варианты из R09: Windows — MXC или отдельный пользователь с ACL и WFP; Linux — bubblewrap + seccomp + netns; прокси исходящего трафика с allowlist и подстановкой секретов; режим, где чтение открыто, а запись закрыта. Трейт `Runner` оставляет это возможным без переделки ядра.

## 3. Режимы разрешений и доверие

| ID | Требование | Приор. |
|---|---|---|
| SEC-030 | Доверие к проекту запрашивается при первом открытии. До него без разбора проектной конфигурации и без выполнения. Смена доверенных файлов показывается. Инструкции в чужом репозитории — главный вектор, а песочницы нет | P0 |
| SEC-031 | Движок политики: режимы `read-only`, `plan`, `ask`, `accept-edits`, `auto`, `bypass`. `deny` приоритетен всегда, `bypass` выключен по умолчанию | P0 |
| SEC-032 | Правила `allow`, `ask`, `deny` по инструменту, пути, команде, домену; глобальные сильнее проектных | P0 |
| SEC-033 | Классы риска действий: чтение, локальная запись, выполнение, сеть, необратимое, внешняя публикация | P0 |
| SEC-034 | Правило вместо поштучного одобрения: 93 % запросов и так одобряется (R07). UI предлагает правило после повторов | P1 |
| SEC-035 | Классификатор действий для `auto`: другая модель, fail closed, не единственная защита. Классификатор не граница | P2 |
| SEC-036 | Необратимые внешние действия (рассылка, оплата, деплой в продакшен, удаление данных) всегда требуют подтверждения с предпросмотром | P0 |
| SEC-037 | Задания cron с внешними данными работают с минимальными правами; недоверенный текст (заголовки issue, письма) не подставляется в привилегированные запуски | P0 |
| SEC-039 | Предпросмотр последствий опасных команд. Классификатор команд выделяет удаление (`rm -r/-f`, `Remove-Item -Recurse`, `del /s`), сброс изменений (`git reset --hard`, `git checkout -- .`, `git restore .`, `git clean`), перезапись истории (`git push --force` и аналоги), миграции БД. Рантайм задерживает вызов, сухим прогоном считает затронутое (файлы, число, объём; незакоммиченные изменения; вывод `git clean -n`; коммиты, которые потеряет удалённая ветка; ожидающие миграции) и показывает карточку «Продолжить» / «Отмена». Учитываются `cd`, `pushd`, `git -C`, подоболочки; пути передаются аргументами, не через shell. Фокус по умолчанию на «Отмена»; ошибка измерения означает отказ; несколько задержек идут в очередь. Модель получает отказ с причиной. В автономном режиме действие вне мандата уходит во Входящие. Вне проекта, где чекпоинта нет, предпросмотр обязателен всегда | P0 |
| SEC-038 | Автономный режим (никто не отвечает): задание или run получает мандат при создании: что разрешено без человека (инструменты, домены, запись в память, бюджет). Действие вне мандата не ждёт человека: откладывается в inbox черновиком, работа продолжается с остальным. Run останавливается, только если продолжать нечего | P0 |

## 9. Модель угроз

| Угроза | Вектор | Защита | Остаточный риск |
|---|---|---|---|
| Инъекция с веб-страницы | Контент попадает в контекст | Метка, IFC, подтверждения внешних действий | **Модель может выполнить любую команду от имени пользователя** |
| Вредоносный репозиторий | Хуки, конфиги, `AGENTS.md` | Доверие к проекту | Код из репозитория работает с правами пользователя |
| Подложенный файл вне проекта | `AGENTS.md` в Downloads | `AGENTS.md` читается только из доверенного проекта | Чтение модели не ограничено |
| Вредоносный скилл | Payload-less инструкции | Уровни, lock, ревью перед установкой | Выполнение с правами пользователя |
| Отравленный MCP | Смена описаний, ответы | Пин, повторное подтверждение, tainted | Вредные ответы; сервер работает с правами пользователя |
| Отравление памяти | Запись из недоверенного источника | MEM-075…078 | Сохранение гипотезы до ревью |
| Эксфильтрация | Команда, сеть | Журнал, подтверждения | **Не предотвращается** |
| Сайт атакует localhost | CSWSH, CSRF, rebinding, перебор | Раздел 7 | Ошибки реализации |
| Сводка компакции с инъекцией | Самогенерация | Недоверенный статус, закрепление цели | Искажение смысла |
| Спутанный заместитель | Субагент просит родителя | Отчёт — данные, авторизация по дереву | Манипуляция решением модели |
| Подделка команды | Вывод инструмента имитирует control | Экранирование, роль только у рантайма | Компрометация родителя |
| Перерасход | Циклы, рой | Бюджеты, детектор, kill switch | Расход до срабатывания |
| Разрушение данных | `rm -rf`, неверное экранирование | Чекпоинты в проекте, классификация опасных команд, подтверждение | **Потеря данных вне проекта** |
| Reward hacking | Правка тестов, чтение оценщика | Замороженный критерий, независимый проверяющий, защита файлов | Обман независимого проверяющего |
| Подделка обновления | Подмена бинарника | Подпись, откат | Компрометация ключа |

Угрозы relay — в части 06. Там же принятый риск общего токена (решение заказчика).
