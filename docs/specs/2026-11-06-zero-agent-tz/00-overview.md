## 2. Назначение

**zero-agent** — самостоятельно размещаемый универсальный агент на Rust с упором на локальные модели. Он работает от поиска в интернете и больших исследований до создания крупных проектов, управляется из веб-приложения, выполняет периодические задания, организует рои субагентов, нативно использует долговременную память ZeroAIMemory и связывается с другими агентами через **zero-agent-relay**.

**Почему это нужно.** Анализ 60+ проектов и 12 закрытых продуктов показал свободную нишу. Ни один изученный проект не сочетает Rust, веб-интерфейс, нативную долговременную память и собственный relay без облака вендора (R02, R05). При этом все закрытые продукты страдают от непредсказуемой стоимости и самоотчётов о завершении, а локальный самостоятельно размещаемый агент может закрыть обе проблемы архитектурно.

**Дифференциаторы:**

| # | Отличие | Чем обеспечено |
|---|---|---|
| 1 | Память как инфраструктура, а не как плагин | Контракт части 04, явные сессии, управляемая компакция, проверка происхождения записей |
| 2 | Экономика контекста для локальных моделей с окном 8–64k | Байт-стабильный префикс, выгрузка вывода, бюджетные уровни промпта, нормализация вызовов |
| 4 | Управляемый рой с расчётом выгоды до запуска | Детерминированный решатель, пауза/отмена/корректировка на любом уровне |
| 5 | Своя сеть агентов без облака вендора | Relay с токеном и TLS, доступ к проектам других узлов со страницы агента |
| 6 | Встроенная арена исследований | Журнал как трасса, реплей, парные сравнения, гейты |
| 3 | Доказуемое завершение | Журнал доказательств, независимый проверяющий, критерий, замороженный при старте |

## 3. Цели, не-цели, анти-цели

### 3.1. Цели

| ID | Цель | Мера успеха |
|---|---|---|
| G1 | Универсальность | Один агент проходит задачи классов: поиск, исследование с отчётом, код, операции в терминале, браузер, документы, расписание |
| G2 | Первый класс для локальных моделей | Полный цикл на Qwen3.8-27B (или аналоге) на RTX 3090 24 ГБ с контекстом 32–64k |
| G3 | Эффективность независимо от задачи | Метрики стоимости на успех не хуже контрольной связки на арене; нет фоновых LLM-вызовов без явной пользы |
| G4 | Максимальное использование ZeroAIMemory | Все девять моментов жизненного цикла закрыты нативно; измерен вклад памяти по схеме M0–M5 |
| G5 | Работа в рамках проекта | Агент работает внутри каталога проекта, наружу только по явному разрешению. Правило в промпте; выход виден в журнале; доля нарушений измерена |
| G6 | Автономность длинных задач | Работа часами с переживанием сбоя процесса и перезапуска машины |
| G7 | Сеть агентов | С любой страницы агента доступны другие агенты и их проекты в рамках настроек доступа проекта |
| G8 | Быстрый цикл исследований | Одна команда даёт вердикт по изменению с доверительным интервалом |

### 3.2. Не-цели

- Многопользовательский SaaS, биллинг, организационные роли.
- Собственная ML-модель, обучение и инференс внутри бинарника (работа с внешними рантаймами).
- Реализация поиска, индекса и хранения знаний: это обязанность ZeroAIMemory.
- Визуальный конструктор графов и DSL в ядре.
- Совместимость с API AutoGen, LangGraph и подобных фреймворков.
- Копирование браузерных сессий пользователя и обход антибот-систем (R04).
- Автоматическая мутация скиллов и ядра без проверки (R04, R07).
- macOS в первых выпусках. Архитектура этого не запрещает.

### 3.3. Анти-цели (провал, даже если формально работает)

- Агент заявляет об успехе без проверяемых доказательств.
- Рой тратит больше ресурсов, чем один поток, и никто об этом не знает.
- Ночной запуск тратит ресурс на бесконечные повторы ошибки (инциденты на $4 700 и $6 531, R07).
- Память незаметно подменяет факт записью из недоверенного источника.
- Правка в рантайме ломает кэш префикса, и каждый ход локальной модели идёт в полный перерасчёт.
- Ядро разрастается, как очереди Hermes и OpenClaw, и его нельзя сопровождать одному разработчику.

## 7. Глоссарий

| Термин | Значение |
|---|---|
| Агент (узел) | Запущенный экземпляр `zero-agent` на машине |
| Run | Один выполняемый агентный контур: верхний агент, оркестратор или воркер |
| Дерево запусков | Верхний run и все его потомки |
| Верхний агент | Run с прямым диалогом с пользователем (`role=top`) |
| Оркестратор | Run, владеющий целью, выбирает один поток или рой |
| Воркер | Run с одной ограниченной задачей |
| Журнал | Append-only таблица событий и эффектов run |
| Эффект | Любое недетерминированное действие: вызов модели, инструмент, время, сеть |
| Control plane | Канал команд рантайму: pause, resume, cancel, correct |
| Шина | Канал рабочих сообщений и элементов очереди между run |
| Work item | Единица работы в очереди с арендой |
| Blackboard | Общие факты и контракты текущего роя |
| Проект | Каталог на диске, зарегистрированный в агенте |
| Решение (solution) | Проект с точки зрения ZeroAIMemory, идентифицируется GUID |
| Грант | Явное разрешение на доступ вне проекта |
| Spill | Выгрузка большого вывода инструмента на диск со ссылкой в контексте |
| Tainted | Метка данных из недоверенного источника |
| Пак | Набор скиллов и интеграций |
| ZAM | ZeroAIMemory |
