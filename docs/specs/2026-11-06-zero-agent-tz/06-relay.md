# ТЗ zero-agent. Часть 06. zero-agent-relay

## 1. Назначение

Несколько агентов подключаются к одному relay. С любого агента доступен любой другой агент сети и его проекты. Легитимность проверяется токеном, прописанным на relay и в конфигах агентов. Работа идёт и в локальной сети, и через интернет.

**Решение заказчика (N-14).** На первом этапе защита — один общий токен. После проверки проекта подход при необходимости меняется. Поэтому транспорт спрятан за трейтом `PeerTransport`, чтобы усиление не потребовало переделки остальной системы.

**Принятый риск.** Relay расшифровывает TLS и видит трафик, а токен равен полному доступу ко всем проектам сети, включая выполнение кода. Рекомендации исследования (ключи агентов, сквозное шифрование, R09) отложены и записаны как RLY-090.

## 2. Архитектура

```text
Браузер ─ SPA ─ локальный zero-agent A                zero-agent B
                         │ WSS (TLS 1.3), токен             │ WSS (TLS 1.3), токен
                         └──────► zero-agent-relay ◄────────┘
                                  проверка токена, маршрутизация потоков
```

- Агенты подключаются наружу исходящим соединением по 443, входящие порты на агентах не нужны.
- Весь трафик идёт через relay, прямых соединений на этом этапе нет.
- Relay не хранит данные и не буферизует много.
- Транспорт: WebSocket поверх TLS, мультиплексирование `yamux`. Relay пишется на `axum` с `rustls`.

### 2.1. Логические потоки

| Поток | Приоритет | Особенности |
|---|---|---|
| `control` | Наивысший | Pause, cancel; отдельный поток, не конкурирует с данными |
| `events` | Высокий | Возобновление по `seq` |
| `rpc` | Средний | API проекта, идемпотентность по `command_id` |
| `terminal` | Средний | Терминал проекта |
| `files` | Низкий | Чанки BLAKE3, докачка, контроль потока |
| `tasks` | Средний | Задачи агент–агент, payload помечен `tainted` |
| `resources` | Низкий | Публикация моделей, слотов и ресурсов узла (RES-020) |

## 3. Требования

### 3.1. Сервис relay

| ID | Требование | Приор. |
|---|---|---|
| RLY-002 | Бинарник `zero-agent-relay`: конфигурация TOML, служба, TLS на `rustls`, порт 443. Без TLS сервис не стартует, кроме явного режима для локальной отладки | P1 |
| RLY-003 | Проверка токена при подключении. Токен высокой энтропии (не менее 256 бит), генерируется командой `zero-agent-relay token`. На relay хранится хэш, сравнение за постоянное время | P1 |
| RLY-004 | Присутствие: список подключённых агентов, пинг | P1 |
| RLY-005 | Лимиты: скорость на соединение, число соединений, размер буфера; блокировка перебора токена по IP | P1 |
| RLY-006 | Логи только метаданных: подключения, отказы, лимиты. Содержимое потоков не пишется | P1 |
| RLY-007 | Панель состояния relay, только чтение, с аутентификацией | P2 |
| RLY-009 | Минимум зависимостей; relay переживает рестарт без потери конфигурации | P1 |
| RLY-010 | Смена токена: `current` и `next` с периодом перекрытия, без простоя | P1 |
| RLY-011 | Хранение и пересылка сообщений для офлайн-агентов на этом этапе не делается | — |

### 3.2. Сторона агента

| ID | Требование | Приор. |
|---|---|---|
| RLY-020 | Подключение настраивается адресом relay, токеном и именем агента. Токен в хранилище секретов. Сертификат relay проверяется всегда; поддерживается закрепление сертификата для самоподписанного relay | P1 |
| RLY-021 | Переподключение с экспоненциальной задержкой и джиттером, возобновление с `last_seq` | P1 |
| RLY-022 | На целевом агенте для каждого проекта настраивается доступ из сети: `verbs` из набора `view`, `chat`, `files.read`, `files.write`, `run`, `terminal`, `control`. По умолчанию всё разрешено, как в задании. Настройка позволяет скрыть проект. Проверка идёт на цели, а не на relay | P1 |
| RLY-024 | Команды несут `command_id`, цель хранит обработанные id и срок | P1 |
| RLY-025 | Аудит на цели с hash-цепочкой: заявленное имя агента, время, действие. Имя заявлено самим агентом и не подтверждено: это учёт, а не доказательство | P1 |
| RLY-026 | Кнопка «отключиться от сети» и уведомление о новом подключённом агенте | P1 |
| RLY-027 | Задачи пиров выполняются в урезанном профиле инструментов; лимит переходов; запрет дальнейшего делегирования | P1 |
| RLY-028 | Правило границы проекта и журнал действуют и для удалённых команд | P1 |

### 3.3. Работа через страницу

| ID | Требование | Приор. |
|---|---|---|
| RLY-040 | Локальная SPA работает с локальным API; агент проксирует вызовы к пиру через туннель | P1 |
| RLY-041 | **HTML и JS пира никогда не загружаются в origin локального агента:** иначе XSS на одном становится полным контролем над другим. Пир отдаёт только данные, рендер с той же санитизацией | P1 |
| RLY-042 | Удалённый агент выглядит в UI так же, как локальный: тот же поток событий | P1 |
| RLY-043 | Переключатель узла виден постоянно; действия на чужом узле визуально отмечены | P1 |
| RLY-044 | Браузер не является узлом сети: страница всегда обслуживается своим агентом | P1 |
| RLY-045 | Доступ с устройства без агента: через VPN к HTTPS агента. Проброс TLS через relay — позже | P2 |

### 3.4. Межагентная работа

| ID | Требование | Приор. |

| RLY-060 | Делегирование: `peer_task(peer, project, goal, done_when, budget)` с квитанциями и прогрессом | P1 |

| RLY-066 | Память не идёт через relay: каждый агент подключается к серверу ZAM напрямую | P1 |
| RLY-067 | Машины за relay как воркеры арены | P2 |

### 3.5. Отложенное усиление

**RLY-090 (P3).** После проверки проекта вернуться к решению N-14. Подготовлено: `PeerTransport` с поточным API, проверка прав на цели, поле имени агента в протоколе. Варианты из R09: ключи агентов Ed25519 со сквозным шифрованием, подписанный список участников, ACL по агенту, прямые соединения (iroh).

## 4. Модель угроз

| Угроза | Вектор | Защита сейчас | Остаточный риск |
|---|---|---|---|
| Перехват в сети | Интернет, Wi-Fi | TLS с проверкой сертификата | — |
| Украден токен | Файл, лог, машина | Хранилище секретов, смена токена, уведомление о новом агенте, журнал | **Полный доступ ко всем проектам сети до смены токена** |
| Перебор токена | Интернет | 256 бит, блокировка по IP | Нагрузка на relay |
| Скомпрометирован relay | Взлом сервера | Хэш токена, логи без содержимого, relay на своей машине | **Чтение и подмена всего трафика** |
| Заражённый агент сети | Инъекция, вредный код | Урезанный профиль задач, лимит переходов, журнал | **Боковое перемещение на все машины сети** |
| XSS перенос | UI пира | RLY-041 | — |
| Сканирование | Открытый порт relay | Только порт 443, никаких панелей управления наружу | Отказ в обслуживании |

## 5. Приёмочные критерии

| ID | Критерий |
|---|---|
| AC-RLY-1 | Сценарий S7: страница A открывает проект на B через интернет, оба за NAT: чат, файлы, терминал |
| AC-RLY-2 | Снимок трафика между агентом и relay не содержит открытых данных и токена |
| AC-RLY-3 | Подключение без токена или с неверным сертификатом отклоняется |
| AC-RLY-4 | Разрыв на 5 минут: события дочитываются без потерь и дублей |
| AC-RLY-5 | `pause` доходит при загруженном потоке `files`; dead-man срабатывает при разрыве (SWM-071) |
| AC-RLY-6 | Смена токена без простоя активных соединений |
