# ТЗ zero-agent. Часть 10. Этапы, приёмка, риски, трассировка

## 1. Этапы

Календарных оценок нет: сроки и исполнители не заданы. Порядок определяется зависимостями. Каждый этап завершается работающим продуктом, который можно проверить сценариями.

| Этап | Содержание | Результат |
|---|---|---|
| **R0 Основание** | Тулчейн, workspace, CI, `za-protocol`, `za-store`, журнал, эффекты, conformance-тесты; зонд llama.cpp; spike контрактных тестов ZAM | Запись и реплей искусственного run на Windows и Linux |
| **R1 Локальный агент** | Цикл, контекст, коннекторы моделей (llama.cpp, vLLM, OpenRouter, Anthropic, OpenAI), нормализация, нативные инструменты, режимы, чекпоинты, память L1/L2 с жизненным циклом, outbox, минимальный UI (чат, одобрения, diff, файлы, инспектор, память, модели, настройки), простые задания cron, `doctor`, `AGENTS.md`, core pack, UI вопросов, плана, безопасности и проекта | Сценарии S1, S4, S10 на целевой связке |
| **R2 Автономия и рой** | Служба, мандат автономии, control plane полностью, top–orchestrator–worker, решатель, шина, очередь, план, stop-gate, доказательства, скиллы с lock, MCP, веб-исследования, браузер (Playwright), goal с проверяющим, события заданий, реестр утилит этап 1, бюджеты дерева | Сценарии S2, S5, S6, S8, S9 |
| **R1а Арена-минимум** | Параллельно с R1: хэш префикса, trace-проверки, золотые трассы, Harbor в WSL2, ATIF, smoke-набор | Первые замеры на целевой связке |
| **R2.5 Арена** | Прокси с записью, реестр, статистика, реплей, SPRT, nightly, базовые наборы, факторы памяти | S11; выбор модели и настроек по данным |
| **R3 Сеть** | Relay с токеном и TLS, потоки, доступ по проектам, UI пиров, делегирование, файлы, терминал, ACP-сервер, worktree и merge queue | S3, S7 |
| **R4 Широта** | Паки, документы, computer use, обновления, советник, роутер, проспективные намерения, консолидация памяти, самоулучшение, мессенджеры, OTLP | S12 |

**Зависимости от ZAM.** Этапы не блокируются CR. Выпуск M6 ZAM переводит агента на L3. Перед R2 желательно согласовать CR-4, CR-7, CR-8, CR-9, CR-20; перед реестром этапа 2 — CR-1, CR-18; перед массовым роем — CR-3, CR-6, CR-10, CR-12.

**Предпосылки R0:** установка Rust-тулчейна и WSL2-дистрибутива, Docker внутри WSL2, llama.cpp, доступный сервер памяти, загрузка целевой модели.

## 3. Правила разработки

| ID | Правило |
|---|---|
| DEV-1 | Сначала проверяемый тест или критерий, потом код. Для агентных функций — задача на арене, как только есть R1а |
| DEV-2 | С R2.5 каждое изменение промпта, инструмента, контекста сравнивается парно; до неё — по золотым трассам и smoke |
| DEV-3 | Журнал работ `docs/journal.md`, `CHANGELOG.md`, решения в `docs/adr/`, спецификации в `docs/specs/`, исследования в `docs/research/` ведутся с первого коммита |
| DEV-4 | Временные файлы только внутри проекта в `.tmp/` под `.gitignore` |
| DEV-5 | Зависимости проверяются лицензией (`cargo about`, как в ZAM), AGPL не встраивается. Заимствуются идеи, а не код: реализации из других агентов не копируются (N-13) |
| DEV-6 | Ядро защищено ratchet размера; новая функция сначала проверяется как capability или пак |
| DEV-7 | Единообразие с ZAM: логирование, конфигурация, стиль БД, стек UI |
| DEV-8 | Разработка ведётся с использованием ZeroAIMemory как настоящая проверка контракта («ешь свой корм»); заказчик это и планировал |

## 4. Риски

| Риск | Вероятность | Влияние | Мера |
|---|---|---|---|
| Объём превышает возможности: ТЗ описывает десятки функций | Высокая | Высокое | Жёсткая граница P0 в R1, маленькое ядро, паки вместо функций |
| Локальная модель на 24 ГБ не тянет сложную работу | Средняя | Высокое | Арена, смена модели, облачный советник, изоляция контекста |
| Контракт ZAM меняется до 1.0 | Высокая | Среднее | Уровни совместимости, контрактные тесты |
| Одна GPU не тянет рой и задания одновременно | Высокая | Среднее | Очередь и допуск по ресурсам (RES), другие узлы сети |
| Без ОС-изоляции модель или инъекция могут навредить файлам и другим машинам сети | Средняя | Высокое | Принятый риск: журнал, подтверждения, чекпоинты; замер AgentDojo и доли нарушений; SEC-100 |
| Rust MCP SDK в бете | Средняя | Низкое | Пин версии, свой тонкий клиент |
| Рост сложности рушит сопровождение | Средняя | Высокое | Ratchet, DEV-6 |
| Harbor на WSL2 с GPU не проверен | Средняя | Среднее | Ранняя проверка; модель на хосте, контейнеры в WSL2 |
| Выгода роя на одной GPU не подтвердится | Высокая | Низкое | Один поток по умолчанию (N-02), изоляция контекста, удалённые слоты |
| Утечка общего токена relay при работе через интернет | Средняя | Высокое | TLS, токен 256 бит, смена токена, уведомления; принятый риск, RLY-090 |
| Шаблоны моделей ломают `<control>` и схемы | Средняя | Среднее | Conformance-набор MDL-019 |
| Промпты короче проверенных вендорских снизят качество на слабых моделях | Средняя | Среднее | ARN-060; бюджет позволяет добавить |

## 6. Что покрыто дополнительно к заданию

Из исследования, что заказчик не перечислял:

- Журнал эффектов, намерение–квитанция, статус `unknown`.
- Обязательный TLS до relay, доступ по проектам на цели, запрет HTML пира в локальном origin.
- Метки недоверенного контента, Rule of Two, защита памяти от отравления.
- Доверие к проекту до разбора конфигураций.
- Цепочка поставок скиллов и MCP, пины описаний.
- Инспектор байтов и хэш префикса в CI.
- Нормализация вызовов, профиль на связку модель–рантайм, зонд возможностей.
- Журнал доказательств, замороженный критерий, независимый проверяющий.
- Управление GPU между LLM и ZAM.
- Outbox и деградация памяти.
- Единый объект заданий, догон, проспективные намерения.
- Факторный замер вклада памяти, реплей, SPRT, non-inferiority.
- Ratchet размера ядра.
