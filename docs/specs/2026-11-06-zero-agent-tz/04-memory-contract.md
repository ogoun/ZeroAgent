## 1. Принципы

| ID | Принцип |
|---|---|
| MEM-001 | ZAM — отдельный проект на постоянно работающем отдельном сервере, одна память на множество агентов, доступная откуда угодно. zero-agent только использует её по HTTP: не запускает, не обслуживает, в её код не вмешивается |
| MEM-002 | Если память недоступна, агент выдаёт предупреждение и продолжает работу: чтение возвращает явный отказ, записи копятся в outbox в своём SQLite и досылаются после восстановления (раздел 14) |
| MEM-003 | ZAM хранит и ищет, вся генерация, решение что записать и исполнение — на агенте. На сервере нет LLM |
| MEM-004 | Шина, очереди и живые статусы — в zero-agent; push в ZAM нет |
| MEM-005 | Запись всегда явная и через шлюз `za-memory`, ни один компонент не пишет в обход него |
| MEM-006 | Контент памяти — данные, а не инструкции, в том числе `axiom` и Rules. Модель угроз в документах ZAM отсутствует, эта обязанность на агенте (R10 §4). ZAM прямо называет снимок сессии «данными, а не указаниями» |
| MEM-007 | Контракт привязан к обнаруженным возможностям (флаги `features`), а не к номеру этапа |
| MEM-008 | Числовые умолчания ZAM не вписываются в zero-agent. Умолчания сервера (`digest_tokens` 1500, `recovery_tokens` 2000, `brief_tokens` 800, `search.budget_tokens` 800, `read.budget_tokens` 1500, `recall.timeout_ms` 200) — только ориентир; агент передаёт свои значения явно |
| MEM-009 | Приоритет владельца ZAM «качество важнее токенов» сохраняется: выдача не урезается ради экономии вслепую |

## 2. Подключение

| Параметр | Значение |
|---|---|
| Адрес | `[memory] url` глобальной конфигурации `ZA_HOME/config.toml`. Проект адрес не задаёт: иначе чужой репозиторий направил бы запросы с токеном на свой сервер |
| Токен | `Authorization: Bearer zam_…`, свой токен агента. Выпускается только в WebUI или администратором (токеном `/auth/tokens` → 403). Хранится вне файлов проекта; дочерние процессы его не получают. Ключи моделей лежат в Vault, поэтому токен памяти — единственный секрет агента вне Vault. Источник в R1-M — переменная `ZA_MEMORY_TOKEN` (план R1-M, D134) |
| Версия API | `/api/v1`; в нём только добавления, удаления — в `/api/v2` (`docs/api-compat.md` ZAM). Клиент пропускает неизвестные поля и флаги |
| MCP | `POST {base_path}/mcp`, streamable HTTP без сессий протокола (MCP 2026-07-28, без `Mcp-Session-Id`), ответы `application/json`. Обязателен заголовок `Accept: application/json, text/event-stream`: с `application/json`, `*/*`, `text/event-stream` или без заголовка — 406 [вып.] |

**Заголовки.** На `/mcp` сервер пробрасывает во внутренние вызовы REST только `Authorization`, `X-Zam-Solution`, `X-Zam-Session`, `X-Zam-Machine`, `X-Zam-Area`, а также `Host`, `X-Forwarded-For`, `X-Forwarded-Proto` и `Forwarded`. `If-Match` и `Idempotency-Key` туда не доходят: для MCP это аргументы.

| Назначение | REST | MCP | Ограничения |
|---|---|---|---|
| Сессия run | `X-Zam-Session`; у `/search`, `/read`, `/recall` ещё поле тела `session_id` (тело сильнее заголовка) | Заголовок или аргумент `session_id` у `memory_search`, `memory_read`, `memory_recall` [вып., `mcp_session_arg`]. Заголовок и аргумент различаются — ошибка 400 без вызова REST | Всегда, иначе нет `seen` и учёта. До 128 символов |
| Решение | `X-Zam-Solution` | Тот же | GUID; некорректный игнорируется |
| Машина | `X-Zam-Machine` | Тот же | До 128 символов |
| Область | `X-Zam-Area` | Тот же | До 128 символов. Читает сам агент (MEM-012) |
| Ревизия | `If-Match` или `base_rev` в теле | Аргументы `rev`, `base_rev` | `PATCH /nodes` берёт `base_rev` в теле, без него 400 |
| Идемпотентность | `Idempotency-Key` у `POST /spaces/{s}/entries`, `POST /entries/{id}/supersede`, `POST /nodes`, `PUT` и `PATCH /nodes/{id}` [вып., узлы — `idempotent_nodes`] | Аргумент `idempotency_key` у `memory_log` и `memory_write` | До 200 символов, ключ привязан к пользователю. У `PATCH /entries/{id}`, `answer`, `claim`, `propose`, `decide` ключа нет [M7, CR-20b] |

| ID | Требование | Приор. |
|---|---|---|
| MEM-012 | `.zeroaimemory/area.toml` (`area = "…"`) разбирает zero-agent: ни клиент `zam`, ни сервер его не читают (подтверждено ZAM, в его ТЗ — «не реализовано, замысел»). Файл читается только у доверенного проекта | P1 |

## 3. Обнаружение возможностей

При старте команды и после переподключения: `GET /api/v1/health` без аутентификации → `{status, version, git, features, token_counter, tokenizer_id, uptime_s}` [вып.]. Ответ не `application/json` — не ZAM API: корневой `GET /health` отдаёт HTML WebUI с кодом 200. Готовность — `GET /api/v1/ready` → `{"status":"ready"}`.

| Уровень | Условие | Поведение zero-agent |
|---|---|---|
| L0 Офлайн | `/api/v1/health` недоступен или ответ не JSON | Режим без памяти, очередь записи (раздел 14) |
| L1 Базовый | В ответе нет `features` (`0.0.10-m5.7`: только `status, version, git, uptime_s`) | Нет эпох, снимка, `focus`, `timeout_ms`, ключа у узлов. Скрытие в MCP — как в REST. Бюджет считается только своим токенизатором |
| L2 M6 | `features` содержит `m6` | Возможности включаются по отдельным флагам (ниже) |

Прежние уровни L2 «Экономия» и L3 «M6 полный» на выпуске `0.0.11-m6` слились: все флаги M6 есть сразу. Оговорка первой редакции «ветка называет себя `0.0.10-m5.7`» устарела. Список флагов описан в `docs/api-compat.md` ZAM; на сервере их 19.

## 4. Каналы

Решение 2026-11-16: рантайм работает через REST, MCP — только для инструментов чтения модели.

| Канал | Назначение | Почему |
|---|---|---|
| REST `/api/v1` | Всё, что делает рантайм: обнаружение, сессии, `/recall`, снимок, Vault, запись через шлюз (в том числе вызванная моделью), outbox | Код и `type` ошибки, `output_limit`, `parent_id`, `record`, `code_map`, `solution`, `area`, `Idempotency-Key` и `If-Match` есть только здесь |
| MCP `POST /mcp` | Чтение, которое инициирует модель: `memory_search`, `memory_read`, `memory_tree` | Оптимизированный для модели Markdown, карточки и строка `~N tok`. Без `initialize` и без сессий протокола |

**Ошибки MCP** [вып.]. Ошибка инструмента — HTTP 200 и `isError: true`, текст «Ошибка <код> <title>: <detail>»: в тексте есть только статус и `title`, `type` problem+json теряется (CR-25). Отказы транспорта (401, 403 Origin, 406) — обычные HTTP-коды; неизвестный инструмент — ошибка JSON-RPC.

**JSON из MCP.** При `format: "json"` текст ответа — JSON ответа REST; ZAM объявил его стабильным контрактом наравне с REST (`api-compat.md`). `structuredContent` и `outputSchema` нет (CR-16).

**Чего нет в MCP.** `memory_recall` пересылает в REST только `event`, `prompt`, `task`, `error`, `tool`, `session_id`, `budget_tokens`, `agent_block_version`, `source`, `timeout_ms`. `output_limit`, `parent_id`, `record`, `code_map`, `solution` и `area` доступны только через REST.

| ID | Требование | Приор. |
|---|---|---|
| MEM-020 | `MemoryClient` скрывает выбор канала. Прочий код не знает о транспорте | P0 |
| MEM-021 | `zam mcp`, хуки и файлы привязки по pid не используются для нативного агента | P0 |
| MEM-022 | Подпроцессы `zam` используются только для `zam code sync`, `zam refs check|verify`, `zam report` (большие файлы, ключ идемпотентности `--key`). Выставляется `ZAM_AGENT=1`, флаги `--by`, `--origin` | P1 |
| MEM-023 | Большие тела (больше `note_body_max`, ≈10 МБ) на `POST /spaces/{s}/entries` и `/mcp`: одновременно не более двух, ожидание 500 мс, иначе 503 `busy` с `Retry-After: 2`. Шлюз выстраивает их в очередь. Обычные запросы этому лимиту не подвержены | P0 |
| MEM-024 | Таймауты: connect 2 с, `/recall` — `timeout_ms` плюс 1 с, поиск 5 с, запись 30 с; отмена запроса при отмене run. Требования транспорта `/mcp` известны: `Accept` (406), без сессий протокола. HTTP-клиент памяти не использует системный прокси | P0 |

**Правило `skip_seen`.**

| Вызов | `skip_seen` | Результат |
|---|---|---|
| MCP на L2 | **Не передаётся** | Фрагмент остаётся с пометкой `(выдавалось)`; при источнике действующей выжимки того же ответа `(выдавалось, в выжимке)` без фрагмента [вып.] |
| MCP, `true` | Скрывает как REST |
| MCP, `false` | Нет ни скрытия, ни пометки |
| MCP на L1 | Скрывает как REST, пометки нет |
| REST | Передаётся явно; по умолчанию `true`: после чтения карточка приходит с `seen: true` без фрагмента |

Все варианты работают только с явной сессией. Без неё учёт выданного через MCP уходит в `unattributed`, отметок «выдавалось» нет, а счётчик `memory_writes` получает подставленную сессию хуков (последнюю незавершённую сессию верхнего уровня этого пользователя за 12 ч). Нативный клиент шлёт сессию всегда. Рантайм передаёт `true`, только когда точно знает, что нужный текст лежит в контексте этого run.

## 5. Соответствие сущностей

| zero-agent | ZAM | Как |
|---|---|---|
| Проект | Решение (solution) | GUID `agent_solution_id` в `.zeroaimemory/solution.toml`, только у доверенного проекта: иначе враждебный репозиторий направил бы агента в чужое решение пользователя. Нет файла: работа без решения; явная команда `memory init` — `POST /solutions {agent_solution_id, name}` и запись файла. 202 `pending` — работа без памяти решения до одобрения |
| Подкаталог | Область | MEM-012 |
| Узел | Машина | `X-Zam-Machine` |
| Run | Сессия | `POST /sessions {id, agent: "zero-agent", solution, area, parent_id, agent_type}`. Id всегда задаёт агент; без него сервер выдаст UUID |
| Роль run | `agent_type` | `top`, `orchestrator`, `worker:<skill>`, до 128 символов |
| Пользователь | Пользователь ZAM | Токен. Сущности «агент» в доступе нет |
| Токен | Один на агента | Все run одного узла идут с одним токеном и различаются сессией |

**Идентификатор сессии:** `za-<project>-<run_id>`, до 128 символов; значение `unattributed` зарезервировано. Сессия создаётся первым запросом с заголовком и живёт 30 дней от `last_seen_at`; для долгих проектов важные связи дублируются в записях. Снимок сессии хранится 14 дней (`snapshot.keep_days`), поле `agent` снимка — `[a-z0-9_-]{1,32}`, значение `zero-agent` подходит.

**Ограничения, которые обеспечивает харнесс.** Токен открывает всю память пользователя, кроме Human, включая Vault и другие решения.

| ID | Требование | Приор. |
|---|---|---|
| MEM-013 | Правило «строго внутри проекта» распространяется на память: шлюз разрешает только текущее решение и Knowledge. `all_solutions`, чужой `X-Zam-Solution`, `scope.spaces` вне этого набора требуют гранта. Реестр утилит живёт в Knowledge и поэтому доступен. У недоверенного проекта решения нет, память — только чтение Knowledge и Rules | P0 |
| MEM-014 | Vault ограничен рантаймом (раздел 13). Токенов с областью нет до CR-2 [M7]. Токен памяти не передаётся дочерним процессам: с ним `zam vault get` дал бы модели все секреты | P0 |

## 6. Жизненный цикл

Нативная реализация моментов, которые у чужих агентов закрывают хуки. Клиент `zam` выполняет часть шагов параллельно ради бюджета 300 мс; нативный агент может идти последовательно, у него такого бюджета нет. Жёсткий инвариант порядка один (MEM-040).

| Момент | Действия | Статус ZAM |
|---|---|---|
| **Старт run** | `GET /api/v1/health`; `POST /sessions`; догоняющий снимок оборванной сессии (свой `PUT`, `trigger: catch_up`); досылка outbox; `POST /recall {event: session_start, session_id, solution, area, budget_tokens, timeout_ms, output_limit}`. `POST /files/changed` → `GET /file-refs`, `GET /triggers` и фоновый `zam code sync` — с картой кода и локальными триггерами | [вып.] |
| **Запрос пользователя** | `POST /recall {event: prompt, prompt, session_id, timeout_ms, output_limit}`. Пусто — тишина | [вып.] |
| **Перед работой** | Поиск → карточки или `[cache]` → чтение пачкой → `memory_cache_put`. Перед исследованием поиск с `insight_kinds=[experiment,failure]` | [вып.] |
| **Взятие задачи** | `claim` (нужен `X-Zam-Session`, иначе 400), затем статус `in_progress` и `next_step` по шагам. Захват продлевается той же сессией до истечения | [вып.] |
| **Незнакомый код** | `memory_code map`, перед правкой с неясными последствиями `impact` | [вып.] |
| **Перед правкой или командой** | Локально, без сети: `file_glob`, `command_regex`, знание о файле из кэша. Одна запись показывается один раз; показанное сбрасывается при `compact` и `clear` | [вып.] в клиенте `zam`; у нас MEM-041 |
| **После инструмента, успех** | Без сети: событие, очередь изменённых файлов | [вып.] |
| **Ошибка инструмента** | Локальный `error_regex`, затем `POST /recall {event: post_tool, error, tool, session_id}`: `error_regex` действующих триггеров сопоставляет и сервер. Подсказка при каждой ошибке; третий раз тот же `err_fp` — подсказка проверить память | [вып.] |
| **После исправления** | Запись `insight` `gotcha`/`failure` с `error_regex` | [вып.] |
| **Субагент** | Родитель: `POST /sessions {id: "<run>:<child>", parent_id, agent_type, agent, solution}` — только он связывает потомка с родителем. Затем `POST /recall {event: brief, task, session_id: <id потомка>, timeout_ms}`. `parent_id` в теле `/recall` связи не создаёт: он поднимает захваченные задачи родителя только в мини-дайджесте без `task` и передаёт хукам признак `holdout` родителя (CR-23). Без `session_id` показ уйдёт в сессию заголовка. Пакет вкладывается в `<task>` | [вып.] |
| **Перед компакцией** | Обновить `next_step` захваченных задач; отправка очереди | [вып.] |
| **После компакции, resume** | Снимок `trigger: post_compact`; `POST /recall {event: recovery, session_id, budget_tokens, timeout_ms, output_limit}`. `recovery` сам начинает новую эпоху, отдельный `new_epoch` не нужен, двойной сдвиг безвреден | [вып.] |
| **Очистка контекста** | `event: session_start, source: clear`: новая эпоха без пакета восстановления | [вып.] |
| **Остановка** | Отправка очереди, снимок `trigger: stop`. Проверка итогов по журналу агента, а не по `memory_writes` (MEM-043) | [вып.] |
| **Конец сессии** | Снимок `trigger: session_end`, затем `PATCH /sessions/{id} {ended: true}`. Хуки этого не шлют, это расширение нативного агента | [вып.] |

**Особенности `/recall`** [вып.]:
- **`timeout_ms`** (флаг `recall_timeout`): от 1 до `max(recall.max_timeout_ms, recall.timeout_ms)` = 2000, иначе 400. Без поля — 200 мс, бюджет хуков; на CPU-сервере `brief` с 200 мс обрезается. Агент передаёт: старт и `recovery` — 1500, `brief` — 2000, `prompt` — 800, `post_tool` — 1000. Не успели — `warnings: ["recall timeout"]` (MEM-034).
- **Rules резервом:** у `session_start` и `recovery` Rules идут сверх `budget_tokens` — до 20 заметок по 200 токенов. На проекте резерв — 1312 токенов: `session_start` с `budget_tokens: 200` дал 1570 токенов. У `brief` правила — строки L0 внутри бюджета (`rules_tokens: 0`). Ответ несёт `tokens` и `rules_tokens`.
- **`output_limit {unit: chars|bytes, max}`** — жёсткий предел всего текста, только REST. Под ним сервер сначала сжимает правила до L0 и до пути, затем снимает разделы по стойкости. Поле описано для хуков, нативному клиенту — CR-22.
- **Ловушка предела хука:** тело REST с `source` или `code_map` и без `output_limit` сервер считает хуком и укладывает в 7500 байт: правила сжимаются до L0, разделы снимаются. Нативный клиент всегда шлёт свой `output_limit` и не шлёт `source` и `code_map` без нужды.
- **`record: false`** — вызов без отметок показа и учёта, для префетча (MEM-067) и пробных вызовов. Новую эпоху он не отменяет: `recovery` и `session_start` с `source` `compact|resume|clear` сдвигают эпоху при любом `record`. Через MCP поле недоступно.
- **`source`** действует только с `event: session_start`. `session_start` подчиняется настройкам `hooks.*` пользователя, `recovery` и `brief` — нет. `agent_block_version` нужен только агентам с блоком инструкции ZAM; без поля напоминания о блоке нет.
- **Разделы дайджеста:** «Задачи» (`in_progress`, `blocked` и захваченные `open`, до 5), «Ответы человека», «Открытые вопросы», «Идеи», «Окружение» (Vault `host` и `environment`), «Правила», «Решение», «Ловушки и сбои», «Пересмотреть (revisit)», «Последние изменения», «Последнее известное состояние» (снимок оборванной сессии), строки «Словарь», «Проверенные команды» и карты кода. У `recovery` первыми идут «Задачи», «Ответы человека» без фильтра показа и «Решения». [M6.5] — «Идеи на разбор» и строка «План из идей».
- **Детерминированность:** порядок дайджеста не зависит от `usage` и показов других сессий. Текст меняется вместе с памятью, сутками UTC, захватами задач, снимками оборванных сессий и первым показом «Идей» в сессии, поэтому одинаковый префикс между run не гарантирован: MEM-031 замораживает его на стороне агента.

## 8. Чтение

### 8.1. Протокол поиска (четыре шага)

1. `memory_search`: `[cache]` или карточки. Оценки ZAM: 100–400 токенов и 30–50 на карточку. Хвост карточки — `[балл] r<rev> · ax|th|hyp · дата UTC · Nt`.
2. Карточки → решение, что читать.
3. `memory_read` пачкой до 20 целей с явным `budget_tokens`, изменения через `since_rev`. `if_rev` и `since_rev` при той же ревизии → `unchanged: true` без текста.
4. `memory_cache_put` с честными `sources`, выжимка до 600 токенов.

**Пачка `/read`.** Неверная форма одного элемента (`focus` с `section`, `range` у вложения, `range` без ревизии) даёт 400 на весь вызов. Ошибки самой цели (`not_found`, `invalid`) приходят по элементу, код первой — в заголовке `X-Zam-Read-Error`. Шлюз проверяет форму элементов до отправки.

**Ссылки:** `n:`, `i:`, `c:`, `r:`, `t:`, `k:`, `q:`, `w:`, `e:`, `a:`, `b:`, `d:`, путь `<space>:/<path>`. Ссылка `p:` токену недоступна. `v:` — запись Vault: принимает только `memory_vault`, `/read` по `v:` отвечает `not_found`. **Префикс id тип не проверяет:** любая буква записи журнала ведёт в запись по id (`k:<id insight>` вернёт insight с `ref: i:…`), поэтому тип берётся из `kind` и `ref` ответа.

### 8.2. Формат для модели

Ответы MCP идут в контекст как есть, последняя строка — `~N tok`. На L2 дата в тексте — UTC `yyyy-MM-dd HH:mm:ss`. Результаты памяти оборачиваются и экранируются:

```text
<memory source="zam" kind="search" tainted="{bool}">
…ответ…
</memory>
```

Атрибут `tainted` ставится, когда происхождение записей ответа известно (CR-19 [M7]). До этого он не ставится: записи из tainted-контекста хранятся как `hypothesis` с тегом `tainted` (MEM-077) и видны модели как `hyp`.

## 13. Vault

**Контракт** [вып.] (`api/vault.rs` ZAM на `e391440`):
- **Область:** `knowledge` (личный Vault, общий для всех проектов) или GUID доступного решения. Vault каждого пользователя свой; Vault владельца и других участников не виден никому, кроме администратора. `rules`, `human` и id пространства → 404.
- **Типы** `data.type`: `password`, `token`, `ssh_key`, `connection_string`, `url`, `repo`, `note`, `host`, `environment`. Открытые поля `data`: `username`, `url`, `description`, `purpose`, `address`, `limits`, `notes`. Имя записи (`title`) — до 200 печатных символов, уникально в области (дубль → 409).
- **Список:** `GET /spaces/{s}/vault?q=` → `{items, locked, reason?}` — метаданные без значений и без аудита. `q` — FTS по имени и открытым полям (слова от 3 символов префиксом). Точного фильтра по имени нет: поиск по имени — точное сравнение `title` на клиенте. `?name=` молча игнорируется и отдаёт все записи (CR-24). Признака «есть значение» в метаданных нет (CR-21).
- **Раскрытие:** `GET /vault/{id}?reveal=1` → метаданные и `secret`, `Cache-Control: no-store`. Аудит `vault.reveal {item, session, machine}`, `actor` — id токена; цели раскрытия (`purpose`) в аудите нет (CR-21). У `host` и `environment` без значения — `secret: null`.
- **Блокировка:** без мастер-ключа метаданные отвечают 200 с `locked: true` и `reason`; значения, создание, правка и удаление — 503 `/problems/vault-locked`.
- **Отказы:** 403 `/problems/solution-access` (ожидание, отклонение, отзыв доступа к решению), 404 `about:blank`. Удаление и переименование — только REST.
- **Окружение (M4.5):** записи `host` и `environment` с открытыми полями видны в дайджесте `session_start` разделом `### Окружение` (до 5 записей, `<имя> — <purpose>; <address>; ограничения: … — v:<id>`); значения туда не попадают. В `recovery` и `brief` раздела нет.

**Решения 2026-11-16:**
- **Ключи агента** (ключи облачных моделей, поиска, токены инструментов) — только в Vault памяти. Поиск записи: Vault решения проекта, затем личный (Knowledge); имя записи равно `key_ref` из `config.toml`. Раскрываются только ключи, нужные команде; кэш значений живёт в процессе; раскрытие — событие журнала и запись аудита агента без значения.
- **Vault недоступен** (сервер выключен или Vault заблокирован) — агент ждёт его возвращения. Модели и поиск, которым нужен ключ, не запускаются; запасного чтения `ZA_SECRET_*` нет; локальные модели без ключей работают. `EnvStore` (`ZA_SECRET_*`) остаётся только для тестов и CI (решение владельца; ZAM `i:01M7GSTKNCEAB96HCY6RH05GBM`).
- **Записи окружения** (адреса, назначение, ограничения, без паролей) показываются всем моделям, включая облачные (решение владельца; ZAM `i:01M7GTX72QEF4TS64YSQ5EKK52`). Агент записи окружения не раскрывает и в заметки не копирует.

| ID | Требование | Приор. |
|---|---|---|
| MEM-110 | Инструмент `memory_vault` модели не выдаётся: ни одной роли. Vault доступен рантайму для подстановки (MEM-111) и пользователю через UI ZAM | P0 |
| MEM-111 | Значение из Vault в контекст модели не попадает; используется подстановкой (ключи моделей — в коннекторе, инструменты — на прокси SEC-041). Модель оперирует только именем записи. До реализации SEC-041 секреты в инструментах недоступны | P1 |
| MEM-112 | Каждое чтение значения попадает в аудит ZAM и журнал агента | P0 |

## 14. Деградация и ошибки

| Ситуация | Сигнал | Поведение |
|---|---|---|
| Сервер недоступен | Ошибка соединения | L0: предупреждение в UI и журнале, локальные триггеры по кэшу, запись в outbox. Ключи моделей не раскрываются: модели с ключом ждут Vault (раздел 13) |
| Не ZAM API | `/api/v1/health` не JSON (корневой `/health` — HTML) | L0 с причиной «не ZAM API» |
| Неверный `Accept` у `/mcp` | 406 | Ошибка клиента: заголовок обязателен |
| Старт сервера, нет модели, ORT или Qdrant | `degraded: true`, `degraded_reason` | Работа, поиск только FTS; повтор семантического запроса позже |
| Нет реранкера | `warnings: ["reranker not installed"]` | Лог, работа |
| Индекс отстаёт | `pending_count > 0`, `warnings: ["index rebuilding"]` | Чтение по id |
| `/recall` не успел | `warnings: ["recall timeout"]` | MEM-034 |
| Занято | 503 `busy`, `Retry-After` | MEM-023 |
| Медленное большое тело | 408 | Повтор с меньшим телом |
| Конфликт | 409 (`conflict`, `possible-duplicate`, `task-claimed`, `term-conflict`) | MEM-073 |
| Режим разбора идей | 409 `idea-mode` [M6.5] | Режим не меняется (определяется по флагу); идея остаётся как есть |
| Нет ревизии | 428 | Подставить, повторить |
| Повтор с другим телом | 422 `/problems/idempotency-mismatch` | Ошибка шлюза: ключ эффекта не должен менять тело |
| Неверный или отозванный токен | 401; при превышении лимита неудачных попыток 429 с `Retry-After` | Тревога в UI, L0. На обычные запросы лимита нет |
| Доступ к решению | 202 `pending`, 403 `/problems/solution-access` | Показать пользователю |
| Большое тело | 413 | Разбить, вложение |
| Vault заблокирован | Список 200 с `locked: true`; раскрытие 503 `/problems/vault-locked` | Ключи ждут разблокировки (раздел 13); показать пользователю |
| Снимок устарел или замаскирован | 200 `warnings: ["stale_ignored"]`, `["secrets_masked"]` | Успех с предупреждением в журнале |
| Несовместимость | 400 с именем поля, 422 | MEM-010 |

**`type` ошибок.** `about:blank` приходит ровно у 400, 401, 403 (кроме `solution-access` и `password-change-required`) и 404 (кроме `session-not-found`). У остальных `type` свой: `conflict`, `possible-duplicate`, `term-conflict`, `task-claimed`, `precondition-required`, `unprocessable`, `too-large`, `idempotency-mismatch`, `locator-invalid`, `session-required`, `vault-locked`, `busy`. Поэтому 400, 403 и 404 различаются только по коду и маршруту (CR-25).

**Outbox.** Офлайн-очереди CLI нет до v2 ZAM, поэтому:

| ID | Требование | Приор. |
|---|---|---|
| MEM-120 | `memory_outbox` в SQLite. Досылка после восстановления в порядке создания: записи журнала и узлы с ключом (MEM-072); запросы без ключа в очередь не встают | P0 |
| MEM-121 | Срок хранения и лимит, переполнение видно в UI; потери нет без действия пользователя | P0 |
| MEM-122 | Запрос поиска при L0 возвращает явное `memory unavailable`, а не пустой результат | P0 |

## 19. Правила развития контракта

- Изменение ZAM отражается здесь и в контрактных тестах в той же итерации.
- zero-agent поддерживает текущую и предыдущую минорную версии ZAM: сейчас `0.0.11-m6` и `0.0.10-m5.7`. Следующая — `0.0.12-m6.5`.
- Изменения разрабатываются вместе: если задача требует правки ZAM, она ведётся в его репозитории с его процессом и спецификациями. Код ZAM zero-agent только читает.
- Новые предложения к ZAM — идеями в решение ZAM (раздел 18), реестр — `docs/memory_upgrade.md`.
- Журнал несовместимостей ведётся в `docs/journal.md`.
- При конфликте кода ZAM и его документации верить коду, затем `docs/api-compat.md`, затем спецификации этапа, затем ТЗ ZAM. Расхождения первой редакции перечислены в R01 §13 и R10 §12.
